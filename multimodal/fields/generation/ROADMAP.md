# 视觉生成：阅读与问题路线

[回到入门](README.md) · [Baseline](BASELINES.md) · [论文目录](PAPERS.md)

六步。第一步用手算把"从噪声走到一张图"走一遍；第二到第四步各换基线的一组部件（采样与路径、条件与引导、表示空间与主干），读完就能看懂今天的图像配方；第五步加上时间轴，第六步接到世界模型和机器人。每步的检验题都可以只用纸笔做完，答案附在括号里。

## 第一步：一个数走完加噪、预测噪声和逐步采样

读 [VAE 讲义](../../../foundations/lessons/16-vae.md)第 4 节 → [扩散讲义](../../../foundations/lessons/17-diffusion.md)第 2–5 节 → [DDPM 精读](../../papers/ddpm/reading.md)。

为什么在这里：本方向后面的每篇论文都只改 DDPM 的一个部件（见 [Baseline 页](BASELINES.md)），没有生成式的实践经验时，先用一个像素把训练与采样完整算一遍，后面的改动才有落点。

检验题：

1. 线性日程下 t = 500 时信号系数 √ᾱₜ = 0.280、噪声系数 √(1−ᾱₜ) = 0.960。取 x₀ = 0.8、ε = −0.5，xₜ 是多少？若网络预测的噪声是 −0.4（差了 0.1），由 xₜ 反推出的 x₀ 是多少，误差被放大了几倍？（答案：xₜ = 0.224 − 0.480 = −0.256；x̂₀ = (−0.256 + 0.960×0.4)/0.280 ≈ 0.457，差 0.343，约为噪声误差的 0.960/0.280 ≈ 3.4 倍。噪声越大，单步对原图的估计越不可靠，所以要一步步走。）
2. DDPM 附录 B：TPU v3-8 上采样一批 128 张 256×256 图约 300 秒，每张图要调用网络 1000 次。平均每张图多少秒？每次（整批）网络调用多少秒？（答案：约 2.3 秒；约 0.3 秒。）
3. DDPM 的 FID 很好、似然却不占优，用精读机制第 6 节的数字解释。（答案：最后 100 步把重建误差从 12.0 降到 0.95，却用掉约 93% 的码率，似然的大部分花在看不见的细节上。）

## 第二步：少走几步——采样器与路径形状

读 [DDIM](../../papers/arxiv-2010.02502/README.md) → [Improved DDPM](../../papers/arxiv-2102.09672/README.md) → [扩散讲义](../../../foundations/lessons/17-diffusion.md)第 6.1 节 → [Flow Matching](../../papers/arxiv-2210.02747/README.md) → [Rectified Flow](../../papers/arxiv-2209.03003/README.md)。

为什么在这里：每篇扩散论文都自述"采样比 GAN 慢"，后来的视频产品全靠少步采样才可用；SD3 和开源视频报告里的"流匹配""整流流"也要先在这里弄懂。这一步只换部件 4（路径）和部件 5（采样器），网络与条件都不动。

检验题：

1. 弯路与直路：路径 A 是 x(t) = 2t²（t 从 0 到 1，从 0 走到 2），速度 4t；路径 B 是 x(t) = 2t，速度恒为 2。从 x(0) = 0 出发，各用 1 步、2 步 Euler 积分（每步按起点速度走），终点是多少？（答案：A 用 1 步得 0，用 2 步得 0 + 0.5×0 + 0.5×2 = 1，离 2 差 2 和 1；B 用 1 步就精确到 2。路径越直，步数越少，这就是流匹配与 reflow 的出发点。）
2. DDIM 表 1：CIFAR10 上 DDIM 50 步 FID 4.67，DDPM 走满 1000 步 3.17，DDPM 只走 10 步 367.43。50 步比 1000 步少调用几倍网络？代价多少 FID？（答案：20 倍；约 1.5。）
3. Rectified Flow 做一次 reflow 后，一步生成的 FID 从 378 降到 12.21，自适应求解器下的 FID 却从 2.58 升到 3.36。为什么两边朝相反方向变？（答案：reflow 把路径拉直，少步离散误差大减；但它用第一个流生成的配对再训练，速度的估计误差会累积，走满步数时反而变差。）

## 第三步：按条件作图——引导与文本编码器

读 [ADM](../../papers/arxiv-2105.05233/README.md) → [无分类器引导](../../papers/arxiv-2207.12598/README.md) → [Video Diffusion 精读](../../papers/video-diffusion/reading.md)机制第 5 节 → [DALL·E 2](../../papers/arxiv-2204.06125/README.md) → [Imagen](../../papers/arxiv-2205.11487/README.md)。

为什么在这里：类条件与文本条件的最好结果几乎都用了引导，"保真度换多样性"这个旋钮从这里开始；文本条件这一代的失败（属性绑定、计数、空间、写字）是后面三年一直在修的问题。

检验题：

1. 某像素的条件噪声预测 0.3、无条件预测 0.1，按 ε̃ = (1+w)·ε(c) − w·ε 计算 w = 0、0.3、4 时的 ε̃。（答案：0.3；0.36；1.1。w 越大，越沿"条件减无条件"的方向外推。）
2. CFG 在 ImageNet 128×128 上 256 步 FID 2.43，ADM-G 约 250 步 2.97。CFG 实际调用网络多少次？按调用次数公平比较应看哪一行？（答案：每步两次，共 512 次；应看 128 步的 3.04，略差于 ADM-G。）
3. DALL·E 2 写不出"deep learning"招牌，作者给了哪两个原因？SD3 推理时去掉 T5，哪一项人评掉得最多？（答案：CLIP 嵌入可能不编码拼写，BPE 分词遮住了单词拼写；写字一项，胜率 38%，而美学 50%、提示遵循 46%。）

## 第四步：先压缩再生成——潜空间与 Transformer 主干

读 [VQGAN](../../papers/arxiv-2012.09841/README.md) → [LDM](../../papers/arxiv-2112.10752/README.md) → [DiT](../../papers/arxiv-2212.09748/README.md) → [SD3](../../papers/arxiv-2403.03206/README.md)；结构转换的论证见[观点页：CNN 与 Transformer](../../../perspectives/cnn-vs-transformer.md)。

为什么在这里：这是 2022 年后图像和视频共用的骨架（Baseline 页的第二条基线），第五步的视频模型全部建在它上面。前三步的部件在这里汇合：SD3 = 潜空间 + 整流流 + 引导 + 大文本编码器 + Transformer。

检验题：

1. 256×256×3 的图有多少个数？DiT 用的 32×32×4 潜变量有多少个数，压缩了几倍？切块 p = 2、4、8 时各有多少个 token？（答案：196,608；4,096，48 倍；256、64、16 个。）
2. 256 个 token 的自注意力要算多少对，64 个呢？既然 p = 2 最贵，DiT 为什么还选它？（答案：65,536 对与 4,096 对；DiT 的 12 个模型里计算量与 FID 的相关系数为 −0.93，算得越多样本越好，切块越小正是增加计算量的一种方式。）
3. VQGAN 把下采样倍数从 16 再加大会怎样？LDM 与 SD3 各在哪一节写了同一个上限？（答案：重建误差变得严重，作者写明重建能力是可达质量的上界；LDM 第 5 节、SD3 第 5.2.1 节。）

## 第五步：加上时间轴——视频生成

读 [Video Diffusion 精读](../../papers/video-diffusion/reading.md) → [Imagen Video](../../papers/arxiv-2210.02303/README.md) → [Sora 技术报告](../../papers/sora-tech-report/README.md) → [HunyuanVideo](../../papers/arxiv-2412.03603/README.md)、[Wan](../../papers/arxiv-2503.20314/README.md) → [观点页：生成收敛](../../../perspectives/generative-convergence.md)"视频生成的四种基本做法"与阶段四的表。

为什么在这里：视频把每个部件的代价放大一个数量级，图像上可以忽略的问题（显存、长时一致、物理）在这里成为主要矛盾；2024 年后公司之间的竞争也集中在这里。先读两份写得最细的开源报告，再读只写方向的公司报告，才能看出公司报告"没写什么"。

检验题：

1. Wan 的视频 VAE 把 [T, H, W] 压成 [1+T/4, H/8, W/8]。81 帧、480×832 的视频，潜变量有多少个位置？是原视频像素位置的几分之一？（答案：21×60×104 = 131,040；原视频 81×480×832 = 32,348,160，约 1/247。）
2. 16 帧、每帧 1024 个位置：全时空注意力约 (16×1024)² ≈ 2.7×10⁸ 对。改成"帧内空间注意力 + 同位置跨帧时间注意力"后约多少对？（答案：16×1024² + 1024×16² ≈ 1.68×10⁷ + 2.6×10⁵ ≈ 1.7×10⁷，约 1/16。HunyuanVideo 选全注意力、Seedance 1.0 选解耦，两家的取舍不同。）
3. 从 Sora、Veo 3、Seedance 2.0 的官方自述里各找一个失败场景，分别归到"物理与状态变化""长时一致""文字与符号"哪一类。（答案示例：Sora 的玻璃破碎属物理，Sora 的长视频物体凭空出现属长时一致，Veo 3 的"文字生成仍差"属文字；Seedance 2.0 的续写中主体遗漏或重复属长时一致。）

## 第六步：从视频生成到世界模型

读 [Genie](../../papers/arxiv-2402.15391/README.md) → [GameNGen](../../papers/arxiv-2408.14837/README.md) → [Genie 3 博客](../../papers/genie-3-blog/README.md) → [Physics-IQ](../../papers/arxiv-2501.09038/README.md)、[PhyWorld](../../papers/arxiv-2411.02385/README.md) → [观点页](../../../perspectives/generative-convergence.md)"从视频生成到世界模型" → [世界模型方向](../world-models/README.md)与[机器人世界模型讲义](../../../robotics-embodied/fields/world-models.md)。

为什么在这里：规划需要的是"执行这个动作之后会发生什么"，好看的视频不等于能跟随动作、符合物理。有机器人背景的读者在这里能把生成模型和控制里的预测模型对上；Diffusion Policy 与 π0 则是同一套生成机制直接用来出动作，见 [Diffusion Policy 精读](../../../robotics-embodied/papers/diffusion-policy/README.md)。

检验题：

1. GameNGen 以过去 64 帧为条件、以 20 帧/秒运行，它能"看见"多长的历史？Genie 3 约一分钟的视觉记忆，按 24 帧/秒相当于多少帧？（答案：3.2 秒；1440 帧。前者靠屏幕上的弹药、血量数字保存状态，后者的记忆机制官方没有说明。）
2. Physics-IQ 中最好的模型只有 29.5%，视觉真实感与物理理解不显著相关。如果要用视频模型给机器人策略打分，这意味着要额外测什么？（答案：要单独测动作条件下的物理与接触结果，不能用画面逼真程度代替；PhyWorld 进一步显示分布外的速度误差不随规模下降。）
3. PhyWorld 的训练集里只有红球和蓝方块，给一个红方块作条件帧，模型生成的物体会变成什么？用作者给的属性优先级解释。（答案：变成球；模型按"最相近的训练样例"泛化，优先级是颜色 > 大小 > 速度 > 形状，颜色匹配到红球，形状被牺牲。）
