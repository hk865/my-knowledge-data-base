# Hydra-0: Action Flow for Generalist World Modeling and Control

> 状态：文献卡 · 2026 · [原文](https://arxiv.org/abs/2608.18077)

[返回多模态目录](../../README.md) · [原文与阅读记录](source.json)

- **解决什么**：动作条件世界模型通常绑定在一种本体的动作空间上，难以跨本体、任务、环境和视频生成底座共享学到的"动作后果"。
- **核心方法**：把机器人动作表示成画面上的像素运动——"动作流"（action flow，由机器人几何与相机标定把动作投影成画面运动场），作为世界模型的条件，让不同本体共享同一个视觉接口。最佳配置的机器人运动误差与物体运动误差，比动作条件的 Cosmos 2.5 基线分别低 90.4% 与 60.2%，并支持零样本组合与少数据适配；在 RoboLab 上对 5 个策略做开环回放评估，回放成功率与参考成功率的 Pearson 相关 r = 0.96。反过来用时它是"世界动作模型"：给定从人类示范迁移来的期望物体流，预测相容的机器人运动，再由训练好的动作头解出可执行动作，不需要任务专用的机器人示范。
- **为什么在这个库里**：[机器人侧世界模型基线页](../../../robotics-embodied/fields/world-models/BASELINES.md)"③ 动作接口"一行与入门页第 6 阶段"世界模型与动作模型合并"；同一个模型既做策略评估又出动作，可与 [Veo 评估器](../../../robotics-embodied/papers/arxiv-2512.10675/README.md)的 Pearson 0.92 对照读（评估方式不同：本文为开环回放）。做不好的场景：世界动作模型会出现厘米级的抓取误差（作者推测与深度感知不足有关）；生成画面里物体是否已抓牢常常看不清；策略评估只做了开环，闭环留作后续；正向部署仍要靠机器人几何与相机标定生成动作流（Sec.6）。优先级：选读。
