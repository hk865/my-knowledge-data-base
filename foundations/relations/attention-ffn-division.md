# 注意力与 FFN 的分工谱系：注意力偏向位置与结构，FFN 偏向知识

> 状态：关系页 · v1

## 一句话

Transformer 的两种子层分担不同的工作：注意力决定"从当前上下文的哪些位置读、读多少"，FFN 用训练好的固定参数做"按模式查表"。可解释性研究发现，事实性知识主要写在 MLP（即 FFN）里，再由注意力读出；MoE 和 Engram 沿着这条分工，把能够脱离上下文、按 token 查表的那部分做成稀疏的大容量模块。

## 关系链

下面每个节点按"它是什么 → 与上一节点的关系（带类型标注）→ 支撑证据"排列。类型标注的含义：`[结构]` 数学上是同一种结构，正文给出推导或手算；`[经验]` 由实验发现；`[历史]` 有作者自述或引用链；`[判断]` 是本页的综合判断。手算中的数字都是示例数值。

### 1 注意力的 A 与 V：读哪里，与读到什么

**它是什么。** 自注意力先用 Q 与 K 的点积算出权重矩阵 A = softmax(QKᵀ/√d_k)，再输出 O = AV。A 的两条轴都是位置，回答"每个位置从哪些位置读、各读多少"；V 是被读取的内容（[15-qkv-deep-dive.md](../lessons/15-qkv-deep-dive.md) 第 4 节）。

**关系。** `[结构]` 注意力把"读哪里"和"读到什么"分成两条通路。手算（15-qkv-deep-dive.md 第 4.4 节与第 5 节）：在原例中第一个位置的输出是 0.731×10 + 0.269×20 ≈ 12.689；把输入矩阵 X 中只被 V 读取的第二列整体乘 10 后，Q、K、A 全部不变，V 变成 [100, 200]ᵀ，同一位置的输出变成约 126.894。同一个 A 对应了两种完全不同的输出，差别全在 V。

**支撑证据。** [15-qkv-deep-dive.md](../lessons/15-qkv-deep-dive.md) 第 4–5 节；[14-attention-transformer.md](../lessons/14-attention-transformer.md) 第 4–6 节。

### 2 Induction Heads：位置关系由一个头建立，内容由另一个头复制

**它是什么。** [In-context Learning and Induction Heads](../../cross-domain/papers/arxiv-2209.11895/README.md)（Olsson 等 2022，Anthropic）研究上下文学习（模型不更新参数、只靠提示中的例子学会新模式的能力）的机制。Induction head 是一种注意力头，完成 [A][B] … [A] → [B] 这类续写：看到当前 token A，就去找上文中 A 后面跟着的 B，并提高输出 B 的概率。

**与上一节点的关系。**

- `[经验]` 在作者分析的小模型中，这个功能由两层中的一对头组合完成：前一层的"前一 token 头"只按相对位置读取，把上一个 token 的信息复制到当前位置；后一层的 induction head 借这份信息做"前缀匹配"，找到"前一个 token 等于当前 token"的位置，再把那个位置的 token 复制出来。前一个头建立的是纯粹的位置关系。
- `[结构]` 论文把每个头拆成两个可以分开研究的电路：QK 电路决定注意力模式（对应 A），OV 电路决定被注意到时输出什么（对应 V 再经输出投影）。prefix matching 发生在 QK 电路里，复制发生在 OV 电路里，这正是第 1 节 A 与 V 的分工。
- `[经验]` 训练早期存在一次"相变"：induction head 形成的同一时间窗口内，上下文学习能力急剧上升；只有一层的模型既不形成 induction head，也没有这次跃升，因为这种机制需要跨层组合两个头。

**支撑证据。** 原文 [arXiv:2209.11895](https://arxiv.org/abs/2209.11895) 的 Key Concepts 与 Argument 1、5。

### 3 Naturalness of Attention：只看 A 会漏掉被读出的内容

**它是什么。** [Naturalness of Attention](../../llm/papers/arxiv-2311.13508/README.md)（Saad、Sharma 2023，ICSE 2024 短文）分析代码语言模型 CodeBERT（在源代码与自然语言上预训练的 BERT 式编码器）中注意力捕获的语法结构。

**与上一节点的关系。** `[经验]` 作者沿用 Kobayashi 等的范数分析，把注意力输出拆成"注意力权重 α"和"被读取向量经变换后的大小 ‖f(x)‖"两部分，比较哪一个更符合代码的语法结构。在 Java 与 Python 上，多数层中加权变换范数 ‖α f(x)‖ 与语法关系的吻合度高于单看 α，例如第 2 层最高吻合率为 83.4% 对 54.8%（同一批头、同一种语法关系标注）；第 3、7、10 层则是 α 略高。这与第 1 节是同一件事：权重显示位置关系，被读出的内容在变换后的向量里，分析注意力时两者都要看。

**支撑证据。** 原文 [arXiv:2311.13508](https://arxiv.org/abs/2311.13508) §2、§3.2–3.3。

### 4 FFN 是一张用参数写成的键值表

**它是什么。** FFN（前馈网络）对每个位置独立做两层变换 FFN(x) = f(x W_1) W_2，f 通常是 ReLU（[14-attention-transformer.md](../lessons/14-attention-transformer.md) 第 10.1 节）。

**与上一节点的关系。**

- `[结构]` 把 W_1 的第 i 列记作 k_i，把 W_2 的第 i 行记作 v_i，就有 FFN(x) = Σ_i f(x·k_i) v_i：先拿 x 与每个 k_i 打分，再用分数加权求和 v_i。这和注意力的 o = Σ_j A_j v_j 形式相同，区别只有两处：key 和 value 是固定参数，而不是由当前上下文算出；打分经过 ReLU，而不是 softmax 归一化。
  手算（沿用 14-attention-transformer.md 第 10.1 节的数）：x = [1, −2]，三列 key 为 k_1 = [1,0]、k_2 = [0,1]、k_3 = [1,1]，打分 x·k = [1, −2, −1]，ReLU 后为 [1, 0, 0]；三行 value 为 v_1 = [1,1]、v_2 = [1,0]、v_3 = [0,1]，输出 1×v_1 = [1,1]，与讲义直接矩阵相乘的结果一致。只有第 1 个 key 被"命中"，它的 value 被原样写出。
- `[历史]` Geva 等（2021）指出这一形式与 Sukhbaatar 等 2015 的键值神经记忆几乎相同，并说明 Sukhbaatar 等 2019 已做过类似观察、把 FFN 参数改写成自注意力里的"持久记忆"。
- `[经验]` [Transformer Feed-Forward Layers Are Key-Value Memories](../../cross-domain/papers/arxiv-2012.14913/README.md)（Geva 等，EMNLP 2021）在一个 16 层、WikiText-103 上训练的语言模型里检查这些 key 和 value：每个 key 对应人能读懂的输入模式；低层（第 1–9 层）以浅层模式为主，例如以同一个词结尾的前缀，高层（第 10–16 层）以语义模式为主，例如同一话题；value 在输出词表上诱导出一个分布，并且在高层尤其集中在"紧跟该模式之后可能出现的词"上。论文同时指出 FFN 约占 Transformer 参数的三分之二。

**支撑证据。** 原文 [arXiv:2012.14913](https://arxiv.org/abs/2012.14913) §2–4。

### 5 ROME：事实回忆集中在中层 MLP、主语最后一个 token 上

**它是什么。** [Locating and Editing Factual Associations in GPT](../../cross-domain/papers/arxiv-2202.05262/README.md)（Meng 等，NeurIPS 2022）用因果追踪（先破坏输入中的主语，再把某一层某个位置的内部激活恢复成干净值，看正确答案的概率恢复多少）定位 GPT-2 XL 中负责事实回忆的部件，并据此提出 ROME（Rank-One Model Editing）。

**与上一节点的关系。**

- `[经验]` 因果效应集中在两处：一处在中间层、主语最后一个 token 上，主要由 MLP 贡献（MLP 的平均间接效应峰值 6.6%，同一位置注意力只有 1.6%）；另一处在高层、提示的最后一个 token 上，主要由注意力贡献。作者据此提出的机制是：中层 MLP 接收编码主语的输入，输出关于这个主语的记忆属性，再由高层注意力把汇总的信息复制到最后一个 token。
- `[结构]` ROME 把单个中层 MLP 当作第 4 节的键值表来改写：用主语最后一个 token 处的 MLP 中间激活作为 key k，优化出能让模型输出新答案的 value v，再对输出矩阵做一次秩一更新（只加一个外积矩阵），使这张表对 k 返回 v，同时尽量不干扰表中已有的其他键值对。编辑在主语最后一个 token、中间层效果最好，与因果追踪的定位一致。

**支撑证据。** 原文 [arXiv:2202.05262](https://arxiv.org/abs/2202.05262) §2（Figure 2）、§3.1、Figure 5。

### 6 Dissecting Recall：事实由注意力读出

**它是什么。** [Dissecting Recall of Factual Associations](../../cross-domain/papers/arxiv-2304.14767/README.md)（Geva、Bastings、Filippova、Globerson，EMNLP 2023）在 GPT-2（1.5B）和 GPT-J（6B）上用"注意力敲除"（在若干层内切断最后位置对某些位置的注意力，看预测概率下降多少）追踪事实是怎样被取出来的。

**与上一节点的关系。**

- `[经验]` 取出事实分三步：较早层的 MLP 把大量与主语相关的属性写进主语最后一个 token 的表示；关系词的信息传到预测位置；上层注意力再从富集后的主语表示中抽取出属性。切断中高层对主语位置的注意力，会使正确答案的概率最多下降约 60%。
- `[经验]` 抽取由注意力头完成，这些头的参数本身常常编码了主语到属性的映射；作者在约 70% 的预测中观察到这种抽取行为。
- 把第 5、6 节合起来，结论是：**事实主要存于 MLP，由注意力参与读出。** ROME 定位的是存储的位置，本节补上了读出的路径，并把存储的重点从中层 MLP 前移到更低层的 MLP。

**支撑证据。** 原文 [arXiv:2304.14767](https://arxiv.org/abs/2304.14767) §1、§3（Figure 2）。

### 7 MoE：把 FFN 变大，但每个 token 只读其中一小部分

**它是什么。** 混合专家（MoE）把一层拆成许多"专家"子网络，由路由器为每个 token 只选少数几个专家计算（[18-ssm-gnn-moe.md](../lessons/18-ssm-gnn-moe.md) 第 4 节）。[Switch Transformer](../../llm/papers/arxiv-2101.03961/README.md)（Fedus、Zoph、Shazeer 2021）每个 token 只选 1 个专家；[DeepSeekMoE](../../llm/papers/arxiv-2401.06066/README.md)（2024）把专家切得更细，并隔离出所有 token 共用的共享专家；[DeepSeek-V2](../../llm/papers/deepseek-v2/README.md)（2024）在整个模型中采用 DeepSeekMoE。

**与上一节点的关系。**

- `[经验]` 三篇的稀疏化对象都是 FFN。Switch 原文图 2 写明用稀疏的 Switch FFN 层替换稠密 FFN；DeepSeekMoE 把"用 MoE 层替换 Transformer 中的 FFN"称为常规做法，每个专家的结构与标准 FFN 相同，并用"知识混杂"与"知识冗余"来描述它要解决的问题；DeepSeek-V2 对注意力做的改动是 MLA（把 KV 缓存压缩成一个低维潜在向量），目的是推理省内存，对 FFN 做的改动才是稀疏化。
- `[结构]` FFN 适合按 token 路由，原因在它的计算形式：它只读本位置的向量和自己的参数，不与其他位置交互，所以每个 token 可以独立地被送到不同专家，输出形状不变。注意力里真正依赖整段上下文的是 A：它要在当前序列的所有位置之间现算。
- `[经验]` Switch 原文附录 A 也试过把注意力里生成 Q、K、V 的权重矩阵换成专家层：质量有提升，但用 bfloat16 训练时会发散，所以没有放进最终模型。被专家化的是逐 token 的投影参数，A 本身仍由上下文计算。
- `[判断]` MoE 选择 FFN，是三方面因素共同作用的结果：FFN 逐 token 计算、便于路由；FFN 占参数大头，扩容效果明显；训练更稳定（Switch 附录 A）。"FFN 存知识"的可解释性结论与这一选择方向一致，DeepSeekMoE 用"知识"描述专家分工即为一例。

**支撑证据。** Switch [arXiv:2101.03961](https://arxiv.org/abs/2101.03961) 图 2、附录 A（Table 10）；DeepSeekMoE [arXiv:2401.06066](https://arxiv.org/abs/2401.06066) §1–2；DeepSeek-V2 [arXiv:2405.04434](https://arxiv.org/abs/2405.04434) 摘要与 §2。

### 8 Engram：把静态模式从计算里拿出来，改成查表

**它是什么。** [Conditional Memory via Scalable Lookup](../../llm/papers/arxiv-2601.07372/README.md)（Cheng 等，北京大学与 DeepSeek-AI，2026）提出 Engram 模块：用当前 token 及其前几个 token 组成的 N-gram 做哈希，直接在一张很大的嵌入表里取出向量，加回主干的残差流（各层在其上逐层累加更新的主表示）。取表的计算量是常数，与表的大小无关。

**与上一节点的关系。**

- `[经验]` 作者把 MoE 称为"条件计算"、把 Engram 称为"条件记忆"，在总参数和每 token 计算量都固定的条件下，研究稀疏参数该怎样在 MoE 专家与 Engram 表之间分配。验证损失随分配比例呈 U 形，纯 MoE 位于曲线一端；把约 20%–25% 的稀疏参数预算从 MoE 挪给 Engram 时损失最低（论文 §3.1，两种计算预算下都成立）。
- `[经验]` 机制分析（logit lens：把中间层表示直接投影到词表上看它"在想什么"；CKA：比较两个模型各层表示相似度的指标）显示，Engram 让主干的早期层不必再重建静态的局部模式，相当于加深了可用于推理的网络。作者还认为，局部依赖交给查表后，注意力能把容量留给全局上下文：经过同样的长上下文扩展训练后，在检索测试 Multi-Query NIAH（在长文本中埋入多条信息、要求同时找回）上，MoE-27B 基线为 84.2，参数量相同的 Engram-27B 为 97.0（论文 §5）。
- `[经验]` 推理时把 Engram 的输出整个关掉、主干不变：事实知识类基准只保留原性能的 29%–44%，阅读理解类基准保留 81%–93%（论文 Figure 6）。作者据此认为 Engram 是参数化知识的主要存放处，而依赖上下文的任务主要靠主干的注意力。这与第 5、6 节"知识在查表式模块、读取靠注意力"的分工是同一方向。
- `[结构]` Engram 取出的向量也要经过一次注意力式的读出：以当前隐藏状态为 query，用取出的记忆向量生成 key 和 value，按 query 与 key 的匹配程度算出 0 到 1 之间的门值，再乘到 value 上。查表负责存，注意力式的门控负责按上下文决定用多少。
- `[历史]` Engram 原文的相关工作一节直接引用 Geva 等 2021 的"FFN 是键值记忆"与因果追踪一类工作，作为"知识怎样存储"的背景。

**支撑证据。** 原文 [arXiv:2601.07372](https://arxiv.org/abs/2601.07372) 摘要、§1、§2.3（式 3–4）、§3.1、§5、§6.1（Figure 4）、§6.3（Figure 6）、§7 相关工作。

### 9 记忆表成为可以移植的部件

**它是什么。** 两篇 2026 年的后续工作把 Engram 的嵌入表当作独立部件来研究。[Tokenizer-Agnostic Engram Module](../../llm/papers/arxiv-2607.29065/README.md)（Lim、Chieu）指出 Engram 按 token 级 N-gram 做哈希，表与分词器绑定，换分词器就要重训；作者改用基于字节序列的多项式哈希，使字节相同的 token 序列得到相同的哈希，在性能相近的前提下让表能跨分词器复用。[Frozen Memory Is Not Enough: Rethinking External Memory as Extraction](../../llm/papers/arxiv-2608.17050/README.md)（Li 等，2026；v1–v2 题名为 *Cross-Model Memory Transfer via Target-Side Reader Adaptation*）把在源模型上训练好的 Engram 表冻结，接到另一个目标模型上，只训练一个轻量的"读取器"。

**与上一节点的关系。** `[经验]` 跨模型迁移的消融显示，表的内容和正确的寻址都有用，但表只有通过与目标模型对齐的读取器才能发挥作用。这与第 6 节的发现形状相同：存储与读出是两个部件，读出一侧（在 Transformer 内部是注意力，在这里是读取器）决定存下的东西能否被用上。

**支撑证据。** [arXiv:2607.29065](https://arxiv.org/abs/2607.29065) 摘要与引言；[arXiv:2608.17050](https://arxiv.org/abs/2608.17050) 摘要与引言。

## 这条链解释了什么

1. `[结构]` 从 MoE 到 Engram，稀疏化和查表的对象一直是 FFN 与静态记忆，因为它们只依赖本 token（或本 token 加前几个 token）和固定参数，可以事先分块存放、按 token 取用。注意力中由整段上下文算出的权重 A 没有这样的固定内容；即使 Switch 把注意力里的 Q、K、V 投影专家化，被专家化的也只是逐 token 的投影参数。
2. `[经验]` "存储在查表式模块、读出靠注意力"这一形状在三个尺度上重复出现：Transformer 内部，事实写进 MLP、由注意力头读出（ROME 与 Geva 2023）；Engram 中，N-gram 表存储、注意力式门控按上下文决定用多少，关掉表后事实类任务大幅下降而阅读理解基本保留；跨模型迁移中，冻结的表只有配上对齐的读取器才有用。
3. `[判断]` 这条分工是训练中形成的倾向，架构设计正在把它变得更明确。Geva 2023 发现读出事实的注意力头参数里也编码了主语到属性的映射；Engram 的结果说明，早期层（包括其中的注意力）原本也在花容量重建局部的静态模式，把这部分移到查表之后，模型整体表现更好。所以"注意力偏向位置、FFN 偏向知识"更准确的说法是：MoE 和 Engram 这类设计在把训练中已经出现的分工固定成模块边界。

## 批注

**易误读**

- 在本轮查阅的段落中（Switch 图 2 与附录 A、DeepSeekMoE §1–2、DeepSeek-V2 摘要），三篇 MoE 论文都没有把"FFN 存知识"的可解释性结论列为选择 FFN 的理由；Switch 给出的放弃注意力专家的理由是 bfloat16 下训练发散（附录 A）。本页第 7 节把二者的联系标为 `[判断]`。
- "FFN 存知识"是倾向而非边界：Geva 2023 显示读出事实的注意力头参数也编码了主语—属性映射，并且主语富集主要发生在较低层 MLP，而不只是 ROME 所说的中层（Geva 2023 §1）。
- ROME 的定位结果来自 GPT-2 XL 一个模型、1000 条事实陈述的平均；Geva 2023 也只覆盖 GPT-2 与 GPT-J，结论能否推广到更大的现代模型，原文没有检验。
- Induction head 与上下文学习的因果关系，在小型纯注意力模型上证据最强，大模型上主要是相关性与间接证据，作者自己也这样评估（原文 Argument 6）。
- Naturalness of Attention 是 5 页的初步研究，只覆盖 CodeBERT 一个模型，且有若干层是注意力权重本身吻合得更好。
- Engram 的 U 形曲线与基准提升都是在"同总参数、同每 token 计算量"的对照下得到的；关掉 Engram 的实验属于训练与推理不一致的事后消融，作者因此只报告事实知识与阅读理解两端的结果。
