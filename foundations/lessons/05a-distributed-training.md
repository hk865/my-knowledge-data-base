# 05a 分布式训练：多张卡怎样仍然完成同一次学习

## 1. 从两个人合做一份作业开始

假设你有四条训练样本，一张 GPU 一次只能方便地处理两条。你找来第二张 GPU，各分两条，看起来工作量就能减半。但现在出现一个问题：两张卡各自看到了不同的错误，它们应该怎样修改模型，才能相当于用全部四条样本共同学习？

另一种情况更直接：模型本身已经装不下一张卡。即使把样本分出去，每张卡仍然放不下完整模型，这时必须考虑分模型，而不只是分数据。

**分布式训练**就是让多个计算设备协作完成训练。它首先是“谁算哪部分、什么时候交换结果、按照什么共同目标更新”的问题。理解这些，比先背一串框架名字更重要。

本篇会从一次普通更新出发，说明数据并行、张量并行、流水线并行、梯度累积和混合精度。范围止于理解计算与正确性，不把它当作通信系统实现教程，也没有实际进行多卡测速。

## 2. 一次单卡训练到底更新了什么

模型有一组可调数字，统称**参数**，用 θ 表示。给模型一批样本，它先计算预测，这叫前向计算；再把预测与目标的差异变成一个数，叫损失 L。

**梯度**记作 ∇θL，可以理解为每个参数向上微调时，损失在局部会怎样变化。反向传播是一种高效计算这些导数的方法。最简单的梯度下降更新是：

θ_new = θ_old − ηg

g 是梯度，η 是学习率，控制这一步移动多远。若只有一个参数 θ=1，梯度 g=4，学习率 η=0.1，那么新参数为 1−0.1×4=0.6。这个一维手算，是后面所有多卡更新的共同基准。

实际优化器可能还保存历史信息，例如 Adam 保存梯度的一阶和二阶统计。它们叫**优化器状态**。显存里因此不只有参数，还可能有梯度、优化器状态、前向中间结果和通信缓冲区。前向中间结果常叫激活，反向时需要利用其中的信息。

现在再问“切什么”：可以切样本，可以切同一层的计算，也可以把前后不同层分给不同设备。

![数据并行、张量并行、流水线并行及共同的正确性检查](../../assets/foundations/advanced-distributed-overview.svg)

图中三条路径不是从简单到高级的排行榜，而是在不同位置划分工作。数据并行把完整模型复制给多张卡；张量并行让多张卡共同完成一层；流水线并行让不同卡负责不同层段。最后都要回到同一个检查：是否按原先定义的目标完成了更新？

## 3. 数据并行先复制模型再合并梯度

设有两张 GPU，开始时参数完全相同。第一张处理两条样本，第二张处理另外两条。各自完成前向与反向后，得到局部平均梯度 g₁ 和 g₂。

当每张卡样本数相同、每条样本等权时，全局平均梯度就是：

g = (g₁+g₂)/2

例如 g₁=2、g₂=6，合并得到 4。两张卡都用这个 4 更新，就都会从 θ=1 走到 θ=0.6。于是它们虽然看了不同样本，下一步仍拥有相同模型。

这里交换的是梯度信息，不是投票选哪张卡的模型“更好”。也不是两张卡各更新若干步以后，随意平均参数就一定等价。若本地已经连续改变了参数，后续梯度的计算位置也变了，事情会更复杂。

**All-reduce**是一种通信操作：各设备贡献一个数组，对这些数组做求和等归约，并让所有参与设备得到结果。梯度平均可以通过求和后除以设备数实现。PyTorch 的普通 DDP，即 DistributedDataParallel，围绕模型副本与梯度同步组织数据并行；具体数据如何分给各进程仍需要用户安排。[1]

![不同数据产生局部梯度再同步执行一致更新](../../assets/foundations/advanced-distributed-step1.svg)

读图时跟踪两条数据路径，直到它们在梯度同步处汇合。同步之后各卡收到同一个更新方向，才保持参数一致。开始参数、优化器设置和更新时机也必须一致；仅仅“调用了通信”不能修复别的流程错误。

如果两张卡总读取完全相同的样本，并且计算过程相同，就只是重复了工作，没有自动获得四条不同样本的信息。数据分片、每轮打乱规则和末尾不完整批次，都是训练协议的一部分。

## 4. 样本数量不同为什么不能平均两个均值

把刚才的例子改一下：第一张卡只有 1 条样本，平均梯度为 2；第二张卡有 3 条样本，平均梯度为 6。若目标是四条样本等权，全局平均应是：

g = (1×2+3×6)/(1+3) = 5

简单平均两个局部均值会得到 4，相当于让第一张卡那唯一一条样本，拥有与第二张卡三条样本合计一样大的权重。这不一定是非法目标，但已经不是我们说好的逐样本平均目标。

同样的问题会出现在文本训练。文本补齐用的 PAD 不是真实 token；每条文本长度不同，各卡有效 token 数也不同。若目标是“所有有效 token 的平均损失”，就必须按有效 token 数加权，而不是把每个微批次的平均损失再等权平均。

![有效 token 数不同时应使用共同分母](../../assets/foundations/advanced-distributed-step2.svg)

沿图中的数字计算：一组有 1 个有效 token，平均损失为 1，总损失就是 1；另一组有 9 个，平均损失为 3，总损失就是 27。合起来是 (1+27)/(1+9)=2.8。直接算 (1+3)/2=2，则把每一组当成等权对象。

这个差异会传到梯度，而不只是日志里显示的数字。先确定要平均的是样本、序列还是 token，再让所有卡、所有微批次使用一致的权重。不要等训练完成才发现实验目标悄悄换了。

## 5. 梯度累积让小批次共同决定一次更新

**微批次 microbatch**是一小批实际送入设备计算的数据。**梯度累积**指参数暂时不动，连续计算几个微批次的梯度并累加，最后只执行一次优化器更新。

假设一张卡能放 4 条样本，使用 8 张数据并行卡，连续累积 2 次。在每卡每次都恰好有 4 条不同样本、没有补重复样本等问题时，一次更新覆盖：

有效批量 = 4×8×2 = 64 条样本

“累积两次”不是“更新两次”。前两次反向都在同一份参数上进行；如果第一批反向后立即更新，第二批梯度就在新参数处计算，已经是另一种优化过程。

当所有微批大小一致且每个局部损失已经取平均，常见实现会再除以累积次数 K，然后反向；数据并行梯度平均负责设备维度上的平均。若微批大小或有效 token 数不同，只除以 K 就不够。

可以写出一个统一目标：设本次更新覆盖的有效 token 总数为 N，把所有有效 token 的损失先求和，再除以 N。对于常规、同步且按 R 个设备平均梯度的数据并行流程，每个设备在各微批次使用“本地有效 token 损失和 × R/N”，累积后再按 R 个设备平均，就会得到全局损失和除以 N 的梯度。这里 R/N 补偿了设备平均操作；若框架采用其他归约约定，必须重新推导，不能照抄系数。

这个公式是算清分母的方法，不是通用于所有训练框架的直接代码。实际还要确认 N 是否包括所有累积微批、某卡零有效 token 怎么处理，以及末尾批次是否被补齐或丢弃。学习率日程也应说清按样本数、token 数还是优化器更新次数推进。

## 6. 张量并行怎样把同一层拆开

现在考虑模型太大，完整一层都不想由单卡独立承担。线性层常写成 y=xW，其中 x 是输入向量，W 是权重矩阵，y 是输出。

用一个很小的例子理解。设 x=[1,2]，W 的两行分别为 [1,3] 和 [2,4]。则输出两个分量为：

- 第一个分量：1×1+2×2=5
- 第二个分量：1×3+2×4=11

可以按输出列切分：第一张卡保存第一列并算出 5，第二张卡保存第二列并算出 11。需要完整输出时，再把两部分组织到一起。如果下一层也采用兼容的分片，未必每一步都要立刻还原完整向量。

也可以按输入行切分：第一张卡算出 [1,3]，第二张算出 [4,8]，最后相加得到 [5,11]。这次通信需要合并的是对同一个输出的不同部分贡献。

这就是**张量并行**的基本直觉：张量是多维数值数组，多卡协作计算同一层的不同切片。Megatron-LM 研究了适合大型 Transformer 的层内分割和通信安排。[2] 但小例子只是说明切分维度为什么重要，不代表任意神经网络都能以相同成本随意切开。

代价是通信。层切得越细，局部工作可能越少，但交换数据也可能更频繁；设备之间传输速度不足时，更多卡未必更快。

## 7. 流水线并行为什么需要多个微批次

**流水线并行**把前半部分层放在设备 A，后半部分层放在设备 B。一个输入必须先经过 A，再把中间表示传给 B。

如果只有一个微批次，A 工作时 B 等待，随后 B 工作时 A 可能等待。模型确实被分开存储了，但设备没有一直同时工作。

引入多个微批次后，可以让 A 处理第二个微批时，B 同时处理第一个。用只有前向、两阶段各耗时一单位的教学模型说明：

1. 第一个时间单位：A 处理微批 1，B 等待
2. 第二个时间单位：A 处理微批 2，B 处理微批 1
3. 第三个时间单位：A 处理微批 3，B 处理微批 2
4. 第四个时间单位：A 等待，B 处理微批 3

三个微批通过两阶段，理想串行需要六个时间单位，流水重叠后是四个。开始和结束的等待区域叫**气泡 bubble**。这只是前向调度例子；训练还要安排反向传播、激活保存和更新时机，不能把四比六直接当作完整训练加速比。

GPipe 的思路包括把一个批次拆成微批次，并组织流水计算与梯度累积。[3] 各阶段负载不均、通信耗时或内存限制，都会影响实际效果；把层平均分成两半，不保证计算时间也刚好一半。

## 8. 状态分片和混合精度在节省什么

数据并行的朴素实现会在各卡保存完整训练状态。**状态分片**则让不同设备分别保存参数、梯度或优化器状态的部分，再在需要时交换信息。ZeRO 研究了不同程度的训练状态分片。[4] 它回答的是存储冗余如何减少，不能把所有这类方案都直接叫张量并行。

做一个纯存储估算：若 P 个参数都以 4 字节浮点数保存，参数约 4P 字节；同精度梯度再需约 4P；两个同精度 Adam 状态再需约 8P，合计约 16P。这个数还没包含激活、临时缓冲和可能的主权重副本，所以不能直接当成训练显存预算。实际精度与优化器实现也会改变数字。

**混合精度**是在部分计算中使用更低精度表示，并在需要的位置保持较高精度。它改变数值计算方式，不改变我们原本想优化的数学目标。FP16 可表示的范围有限，过小的数可能下溢，过大的数可能溢出。

**loss scaling 损失缩放**先把损失乘以 S，梯度也随之乘以 S，降低小梯度在计算中消失的风险；更新前再把梯度除以 S，恢复原本尺度。[5] 如果要做梯度裁剪，应先还原尺度，否则裁剪阈值作用在被放大的梯度上。累积期间缩放因子应保持一致，并在完整有效批次结束后处理更新；框架示例对此有明确说明。[6]

缩放不是让网络走更大步，因为最后还原了梯度。它也不能让所有运算自动稳定；出现非有限梯度时需要相应检测与处理。BF16、FP16 等格式的范围和精度不同，不应假定所有低精度训练都使用完全相同规则。

## 9. 先验证一次更新再追求速度

最有价值的入门实验不是立刻训练大模型，而是固定一个小模型和一批样本，分别执行单设备与多设备的一次更新。比较全局损失、归一化方式、梯度和更新后的参数。

为了减少干扰，先关闭随机 dropout 等因素，避免使用会依赖本地批次统计而改变行为的部件。例如普通 BatchNorm 使用批次统计，拆小批后不一定与大批完全相同。即使数学目标一致，浮点加法顺序改变也可能产生微小差异，不要求所有数逐位完全一致。

若差异很大，依次检查：是否使用相同初始参数和样本；有无重复采样；有效位置分母是否一致；梯度是求和还是平均；累积中途是否误更新；优化器与学习率计数是否一致。确认这些以后，再测吞吐量、通信占比和显存。

最后记住三个问题：模型本身装得下吗？时间主要花在计算还是通信？多卡更新是否仍在优化同一个目标？回答清楚以后，才有理由选择和组合并行方案。
