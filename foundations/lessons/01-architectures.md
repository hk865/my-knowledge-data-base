# 架构与生成模型 学习地图

## 先理解架构是在选择什么

给一个模型输入，它要经过哪些计算，才能产生输出？这些计算怎样连接、哪些地方使用相同的参数，就是架构要决定的事。

想象你要从照片中找到一只猫。一种办法是先检查附近的小块图像，再把局部线索组合起来。换成读一段传感器记录，问题就不同了：当前读数可能不够，你还需要保留此前发生过什么。CNN 和 RNN 分别提供了处理这两类结构的办法。下面的讲义会从像素和连续读数开始讲，不要求你先认识这些名字。

![建模问题与结构选择](../../assets/foundations/architecture-map.svg)

这张图先用来找问题，不必一口气记住全部术语。局部结构指附近的输入往往有关；时间状态指处理现在时还要带上过去的信息；内容交互指根据输入本身决定应参考哪些其他位置。正文会把每一种计算拆开。

## 为什么 VAE 和扩散模型也放在这里

还有一类问题是生成：我们想让模型产生一个合理的图像或动作，而不是只判断一个已知输入属于哪类。对同一个条件，合理答案可能有很多个，因此不能总是把所有答案平均成唯一结果。

VAE 和扩散模型提供不同的生成建模办法。“怎样生成”与“内部用什么网络计算”是两层独立的选择。比如，扩散模型中的去噪网络可以采用 CNN，也可以采用 Transformer。先区分这两层问题，后面就不容易被模型名称绕晕。

## 每篇要走完什么过程

每篇先说明旧办法在哪个具体例子里不够用，再逐步引入结构。遇到公式时，先解释输入、输出与符号，再手算一次。图中的每条主要路径也会在正文中解释。

这些模块与传统滤波、状态方程、核回归等经典方法之间的联系，按三种性质分别写出：`[结构]` 表示两者在数学上是同一种结构或一个是另一个的特例，正文给出推导或手算；`[经验]` 表示论文实验发现两者表现出相同的行为；`[历史]` 表示有作者自述或原文引用链。教学类比会直接标明。每篇讲义末尾都有“与其他概念的关系”一节。

## 关系索引

跨越三个以上模块的关系链单独成页：

- [递推状态谱系](../relations/recurrent-state.md)：状态方程 → [RNN](12-rnn.md) → [LSTM](13-lstm.md) → 线性递推与 SSM → Mamba（[SSM GNN与MoE](18-ssm-gnn-moe.md)）→ 线性注意力（[QKV](15-qkv-deep-dive.md)）。核心问题是状态转移怎样同时做到稳定、按内容选择、可并行。
- [注意力与 FFN 的分工谱系](../relations/attention-ffn-division.md)：注意力的 A 与 V（[QKV](15-qkv-deep-dive.md)、[Attention与Transformer](14-attention-transformer.md)）→ FFN 键值记忆 → MoE 与 Engram（[SSM GNN与MoE](18-ssm-gnn-moe.md)）。核心问题是读取位置与存放知识怎样在模块之间分工。
