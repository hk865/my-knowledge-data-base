# ASPIRE：失败诊断怎样变成验证过的技能

论文卡（本地来源，未发布） · [官方原文](https://arxiv.org/abs/2607.00272v2) · [官方 PDF](https://arxiv.org/pdf/2607.00272v2)

## 失败要能定位到具体原语

ASPIRE 认为“这一回合失败了”不足以指导程序改进。失败可能来自对象定位、抓取候选、运动规划或接触执行；如果不保留各调用的输入输出与视觉证据，Agent 容易反复改错模块。方法因此把逐原语多模态 trace、程序调试和经过验证的技能库连接起来。（§2）

## 如何修复一次机械臂失败

教学例子中，机械臂认对了杯子，却连续无法到达抓取前位姿。Agent 先读对应规划调用的状态、候选位姿和图像，发现是目标落在障碍缓冲区，而不是识别错误。它修改接近方向，在开发种子上重执行，再把有效修复概括为“何种规划失败下尝试其他接近角度”。这段经验比“再试一次”更可复用，也比整条固定坐标轨迹更易迁移。

实际系统记录原语前后的关键帧、叠加图、返回值及规划结果，并不把完整视频每帧都送入模型。技能包含失败特征、适用条件、修复策略，必要时附代码草图。新的 verifier actor 独立重做源任务，协调器检查 API 规则后才收录可复用条目。（§2.1–2.2）

## 搜索与评估不是同一阶段

进化搜索并行提出多个候选程序，用开发种子执行结果选择并继续修复；最终程序再在留出种子上评估一次。课程与库增长还允许对早期失败任务进行另一次回访。引用成绩时需要写清模型、库版本、搜索预算、是否有回访，不能称所有结果都是第一次零样例执行。（算法 1、§2.3–2.4）

模型权重不更新，改变的是代码与上下文技能。感知、抓取和运动规划 API 仍提供大量先验。论文的 v2 已扩展到多基准与模型，还展示模拟经验对真机编程的帮助；这不能消除真机调试、人类指导、复位和安全监督的成本。（§3）

## 本地能立即借鉴的研究问题

与 RoboSkill 的完整技能包相比，ASPIRE 更强调从细粒度失败中提取已验证的修复模式。对 RPent，可先保留每次 VLA/解析原语的目标、起始观测、返回原因和关键帧，再对照“同信息文字总结”与“结构化诊断”。这是一项可控的研究设计，不需要先引入完整进化搜索平台。
