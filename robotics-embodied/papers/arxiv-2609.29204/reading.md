# AdaHVLA：把一次失败变成可检验的协调规则修改

> 状态：技术精读 · v1 · 未复现

## 一句话

AdaHVLA 固定 VLA 的动作能力，用彼此分开的分析、改码和评估过程，把机器人执行证据转成协调代码的修改，再用新轨迹检验修改是否产生了预期行为。

## 它要解决的问题

机器人已经走到卧室门前，任务却要求它穿过门、进入卧室再停下。局部动作正确，整段任务仍会失败：如果系统过早把“通过门口”记为完成，接下来的规划与纠错都会围绕错误的阶段展开。这是协调问题，涉及何时推进目标、保留哪些历史、纠正指令要持续多久，以及何时结束整项任务。[原文 §I](https://arxiv.org/html/2609.29204v1#S1)

[Code as Policies](../arxiv-2209.07753/reading.md) 已经让语言模型生成调用感知与控制接口的程序；[Hi Robot](../arxiv-2502.19417/README.md) 把复杂指令分解为低层 VLA 可以执行的语言子目标。VLA（视觉—语言—动作模型：根据观测和语言要求产生机器人动作）提供局部执行能力，高层推理负责组织任务。AdaHVLA 沿用这个分工，进一步研究连接两层的规则怎样从经验中改变。

这里的 harness 指围绕模型运行的可执行协调程序。即使高层每次都会重新规划，如果“看到门口就推进阶段”“转向后保留全部旧图像”等规则始终固定，系统仍可能稳定地重复同类错误。本文把这些规则变成可修改对象，要求每次修改回答：具体怀疑哪个机制，下一次运行应该观察到什么？

## 核心想法

增量位于 **高层推理与已有执行器之间的协调代码，以及修改代码的流程**。一个版本控制目标推进、传给 VLA 的局部指令与视觉上下文、纠偏和完成检查。机器人每跑完一次，再决定要不要产生新版本；同一回合内依靠现有代码和动态状态闭环行动。[§III-B–D](https://arxiv.org/html/2609.29204v1#S3)

适配过程将三种工作放在不同 Agent 上下文中：分析者先从轨迹提出可检验假设，修改者检查源码并实现补丁，评估者在新的上下文中比较父版本和新版本的行为。它们交换结构化记录，避免一整段共享对话把“为什么改”直接变成“已经改对”的依据。源码及接口审查另行判断候选能否运行。

revision graph（修订图：将代码版本、假设、运行证据与评估结果关联起来的记录结构）保留分支。修复提前停止却暴露后续绕路问题的版本，仍可能值得继续研究。系统因此同时保存可执行代码和解释代码为何改变的证据，让后续任务能沿着已有发现继续适配。

## 机制

**一次执行的输入与输出。** 令源码版本为 c，运行状态为 mₜ，交互历史包含整项指令、截至当前的观测及此前动作。harness Hc 读取这些内容，输出局部指令 qₜ、观测上下文 κₜ、更新后的状态 mₜ₊₁，以及终止标记 zₜ。zₜ=0 时，固定的 VLA 根据 qₜ、κₜ 产生动作；zₜ=1 时结束回合。c 在一次 rollout（从初始化到终止的一次运行）中固定，mₜ 则随反馈变化。[§III-B，式 1](https://arxiv.org/html/2609.29204v1#S3.SS2)

协调代码控制三组决策。第一组是目标与进度：当前子目标是什么，达到哪些可观察条件才提交下一阶段。第二组是记忆与视觉更新：旧图像可能仍有助于理解路线，但转身后对局部动作已经过时，两者需要不同的保留规则。第三组是纠偏与完成：从“转向正确门口”到“向前穿过门口”，纠正指导应连续生效；局部停止还要与剩余目标核对。[§III-C、图 2](https://arxiv.org/html/2609.29204v1#S3.SS3)

**从证据到补丁。** 每次 harness–VLA 请求带有编号，用来对齐图像、日志、轨迹片段与运行的源码版本。分析记录区分观察和解释，例如“报告偏离路线时仍把子目标从 0 推到 2”属于观察，“进度提交缺少一致性检查”属于解释。假设还必须写明支持证据、期望变化和可观察指标。修改者检查源码后可以修正解释，但应在下一次运行前记录实际采用的假设与预测。

**示例数值：进度提交如何被修正。** 图 2 的补丁在偏离路线、又请求推进时保留当前阶段，并撤回超前的完成记录。用自拟数字演算：当前阶段 current_step=2，原提议 next_step=4、completed_until=3、done=True。若 off_route=True 且 wants_progress=True，补丁令 next_step=2、done=False、completed_until=min(3, 2−1)=1。随后提交的是“阶段 2 尚待处理、仅到阶段 1 完成”，纠偏指令因而仍能围绕未完成的通道生成。这些数值用于说明图中代码，并非一次论文实验的日志。

**从新轨迹到假设支持。** 评估者比较同一任务实例上的父版本和新版本，分别判断目标机制的效果、总体行为与最终成功。设 û 表示修改的机制是否被触发，v̂ 表示两条轨迹是否在触发前已经分歧；两者都有真、假、不确定三种取值。论文采用归因门 χ=1{û=1 且 v̂=0}。只有 χ=1 的比较才可以改变假设支持度。[§III-D，式 3](https://arxiv.org/html/2609.29204v1#S3.SS4)

**示例数值：修复有效不等于任务成功。** 若 û=1、v̂=0，则 χ=1：新版本确实触发进度保护并成功穿门，即使随后在终点处失败、整项任务奖励 R=0，也能支持“进度保护改善穿门”这一局部假设。若 û=1、v̂=1，则 χ=0：此前路线已经不同，假设支持度保持原状，记录仍留给下一轮分析。未触发或无法判定时也不更新支持度。这里没有一个“成功加几分”的连续奖励公式；对未改善或退化的效果，论文规定在弃用该候选时削弱支持。

**怎样继续搜索。** 修订图将版本与相关假设、证据、行为评估相连，并保留不活跃分支。候选优先级先看任务成功，再看目标行为与总体行为；存在局部改善或新暴露的问题、且预算允许时，可以继续扩展。W 限制当前活跃候选叶子的数量，D 限制当前任务焦点下的修订深度。系统还会重复运行，并检查此前已成功的适配任务。

跨任务保留的是选定代码以及压缩的适配记忆：协调问题、检验过的假设、尝试的修改、观察到的效果、评估条件和证据链接。每回合运行状态及局部探索深度重新初始化，无关修改任务重建上下文，每次行为评估使用新上下文。最终版本只依适配证据选择，测试任务上源码固定，但在线推理和运行状态仍继续更新。[§III-E](https://arxiv.org/html/2609.29204v1#S3.SS5)

## 证据：哪个实验支撑哪个主张

**先看比较是否隔离了适配收益。** NaVILA-LH 从 NaVILA-Bench 选取 50 个导航实例，随机分成 10 个适配、40 个测试；Go2 在 Matterport3D 场景和 Isaac 仿真中执行。操作使用 VLA-Arena Long Horizon：L1 组合独立原子技能，L2 同时增加流程长度及阶段依赖，每层同样为 10/40 划分，平台为 MuJoCo/RoboSuite 中的 Panda。[§IV-A–B](https://arxiv.org/html/2609.29204v1#S4)

所有 harness 运行时推理均使用 Qwen3.7-Flash；导航执行器固定为 NaVILA。导航比较六种适配模型，操作适配固定用 GPT-5.6-sol Max，分别配 SmolVLA、OpenVLA-OFT 和 π0.5。Initial Harness 已有在线推理与状态更新，只是不改代码。每个配置从同一初始 harness 独立重启适配三次、使用相同任务划分；每次最多评估 16 个候选，含初始版本。VLA 参数与控制器保持不变。

下表集中保留主要测试结果。导航 Adapted 对应六种适配模型中最终均值最高的配置；操作三种执行器均使用同一适配模型。（各行都是相同 40 个测试实例上三轮评估的均值，分母为 120 次测试，并非 120 个不同任务。）

| 测试设置 | Single VLA | Initial Harness | Adapted |
|---|---:|---:|---:|
| NaVILA-LH，sol Max 适配 | 2.5% | 22.5% | 57.5% |
| 操作 L1，SmolVLA | 7.5% | 11.7% | 25.8% |
| 操作 L1，OpenVLA-OFT | 15.0% | 20.8% | 40.8% |
| 操作 L1，π0.5 | 20.0% | 25.0% | 55.8% |
| 操作 L2，SmolVLA | 1.7% | 2.5% | 10.8% |
| 操作 L2，OpenVLA-OFT | 4.2% | 7.5% | 23.3% |
| 操作 L2，π0.5 | 6.7% | 10.0% | 38.3% |

**主张一：在已有协调程序上改码，仍能提升未参与适配的实例表现。** 表 I 的导航结果把两步收益分开：引入初始 harness 先增加 20 个百分点，适配再增加 35 个百分点。sol Max 三轮测试为 62.5%、52.5%、57.5%，均值为 57.5%；它不是从某一轮挑出的最好成绩。六种适配模型最终均值范围为 31.7%–57.5%，说明效果依赖适配模型。表 II 中六个操作组合全部改善；摘要的“最多增加 30.8 个百分点”特指 π0.5 的 L1，从 25.0% 到 55.8%，L2 对应增加 28.3 个百分点。

**主张二：组织证据比只存版本更有用。** 图 4b 在相同候选预算下重新适配。W/O Graph 仍保留版本和回退，只用平铺历史替代修订图；导航从 57.5% 降至 42.5%，操作 L2 从 38.3% 降至 26.7%。这支持将修改、假设和行为证据关联起来。SR Select 仅凭最终成功选择下一候选，修改者仍能看轨迹、失败候选仍有资格被选；导航降至 38.3%。所以关键区别是候选选择能否使用局部行为改善，而非简单地“允许或禁止重试”。[§V-B](https://arxiv.org/html/2609.29204v1#S5.SS2)

**主张三：上下文隔离有帮助，收益随任务变化。** Shared Context 把各 Agent 的上下文共享并跨任务延续，导航降至 49.2%，L2 降至 30.0%，L1 几乎不变。把分析、修改、选择交给一个 Agent，或把观察与假设合并，也降低导航表现。L1 上去掉观察/假设分离却略高于完整系统，原文明确指出三次运行的接近均值不足以确定可靠排序。证据支持特定困难任务中的隔离收益，机制的贡献仍需按任务判断。

**主张四：终止、记忆与纠偏是不同任务的不同瓶颈。** 图 4a 在适配后直接禁用功能，不重新适配。导航去掉完成检查后降至 29.2%；操作 L1 去掉视觉刷新降至 37.5%；操作 L2 去掉恢复指引降至 23.3%。这些结果定位最终程序依赖哪些部件。[判断] 对工程排查，先找“阶段何时被错误提交”和“纠偏何时过早结束”，往往比立即更换执行器更有针对性。

图 3 展示连续候选的总体改善，也有后期回退；其测试曲线仅作报告，论文说明测试结果不参与修订或选择。图 5 的 Go2 真机轨迹则展示完成第一个目标后偏航、持续纠正、达到第二个目标再继续，提供运行机制的定性例证。

## 局限与后续

**适配成本仍是重要缺口。** 实验给出了候选数量上限，但一个候选可以有多次运行和旧任务回查。表中的适配成功率平均 30 次评估，属于最终候选在 10 个适配实例上的三轮统计；它不表示整个搜索只用 30 次交互。更完整的比较需要报告总 rollout、模型调用与 token、墙钟时间、失败终止成本，并与等成本的单 Agent 改码比较。

**归因质量依赖感知与判断质量。** 论文承认视觉和空间推理错误可同时影响修改与评估；分开上下文仍可能共享基础模型的偏差。归因门增加了克制，但触发和早期分歧本身仍由 Agent 判断。下一步可用可测的状态事件、人工抽检或独立判定器校验这些标签，并检验错误假设是否长期污染记忆。[§V-D](https://arxiv.org/html/2609.29204v1#S5.SS4)

**当前改善位于协调层。** 对已有执行器根本不会完成的局部动作，修改任务组织方式的空间有限。作者提出让适配记忆筛选反复出现的问题和经过验证的观测—动作序列，再用于 VLA 微调或强化后训练；可对照其引用的 [ConRFT](https://www.roboticsproceedings.org/rss21/p019.html) 理解参数学习这条路线。这是未来组合方向，而非本文已经训练过的第二阶段。

[判断] 对可复用系统，最值得借鉴的是让“证据、预测、补丁、行为判定”形成可审计链条。进一步验证应保留实例隔离，在多个任务划分上重跑，并把探索预算与最终部署成功率共同呈现。L2 同时改变长度和依赖关系，拆开这两个因素也能更准确定位记忆和恢复模块的用途。

## 批注

**易误读**

- “适配”是回合之间修改协调代码；测试时仍进行在线推理和状态更新，但不改源码或 VLA 权重。固定源码不等于固定动作序列。（§III-B–E、§IV-B）
- 22.5%→57.5% 是导航测试均值增加 35 个百分点；操作的 +30.8 是一个 backbone–level 条件的最大增益，不能说三种 VLA 平均都涨了 30.8。（表 I–II）
- Overall SR 混合适配与测试两部分；它不等于 held-out Test SR。三次运行使用同一任务划分，不能当成三套独立任务集。（§IV-B）
- runtime 消融测的是已适配程序对模块的依赖，adaptation 消融才是在相同候选预算下重新搜索；二者不能混读为统一训练条件。（§V-B、图 4）
- χ=1 只允许更新假设支持，不提供因果证明；局部效果、最终成功、是否继续扩展候选是三个不同判断。（§III-D–E）
- 真机部分是恢复与跨阶段执行案例，未报告足以量化真机总体成功率的对照试验；“跨环境”也不能直接改写成训练与测试场景严格不重叠。（§IV-A、§V-C）

**与其他论文的关联**

- [Hi Robot](../arxiv-2502.19417/README.md) 用高层 VLM 把开放指令变成低层语言命令，本文继承这种高低层接口，把阶段推进、记忆、纠偏等协调规则纳入经验驱动的代码修改。这里的增量是适配接口周围的程序，不是首次提出分层 VLA。[Hi Robot §4](https://arxiv.org/html/2502.19417v1#S4)
- [RoboSkill](../roboskill/reading.md) 将实际执行代码、文字指导及证据整理为可检索技能包；AdaHVLA 保存的是协调代码版本、修改假设与行为检验关系。两者都让经验进入后续任务，但复用对象不同，前者着重“这件事怎样做”，后者着重“协调规则为什么这样改”。这是方法对照，不声称同月稍晚的 RoboSkill 已继承本文。[RoboSkill §3.4](https://arxiv.org/html/2609.37810v1#S3.SS4)
- [Code as Policies](../arxiv-2209.07753/reading.md) 提供可组合感知与控制接口的程序表达；本文进一步对程序版本做执行证据驱动的分支探索，并把“程序可运行”与“物理行为按预测改善”分开检查。（本文 §II、§III-D）
