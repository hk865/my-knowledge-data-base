# Graph-of-Mark：把对象关系画回图像，让冻结的视觉语言模型读到空间结构

> 状态：技术精读 · AAAI 2026作者稿及arXiv v2 · 未复现

## 一句话

Graph-of-Mark（GoM）先用现成感知模型估计对象及其空间关系，再按问题筛选，把对象编号、关系箭头和关系文字画回原图，让视觉语言模型直接消费带结构的视觉证据；其最值得借鉴的部分，是同一份对象图如何编译成可指代、可裁剪、可反向定位的输入接口。

## 它要解决的问题

给模型一张厨房照片，问“盆栽在烤箱下面吗”，模型可能认出盆栽和烤箱，却把两者位置说反。视觉语言模型（VLM，联合处理图像与文字并生成回答的模型）能够识别物体，并不意味着它会稳定使用物体间的相对位置。

[Set-of-Mark（SoM）](https://arxiv.org/abs/2310.11441) 的办法是在分割区域上添加编号。模型可以说“对象3”，程序也可以把这个编号还原为图像区域。这建立了语言与像素之间的指代接口，但区域仍是独立的标记；“谁在谁上面”主要留给模型自己判断。

[ConceptGraphs](../arxiv-2309.16650/reading.md) 进一步将多视角观测组织成三维对象与关系，用结构化文字支持查询和规划。GoM 选择的是另一处切口：保持任务模型冻结，直接改变它看到的图像，让关系与被描述的对象同时出现在像素空间中。论文研究的是单张图像上的问答和对象定位，任务收益来自前置感知、关系估计与提示设计的组合。[原文§1–3](https://arxiv.org/html/2603.06663v2#S3)

## 核心想法

GoM 的增量在输入接口，而非重新训练视觉编码器或语言模型。它把输入加工拆成三个相互衔接的职责。

第一，**前端显式计算关系**。检测与分割提供对象区域，二维框中心提供左右、上下，单目深度模型提供前后顺序。场景图（scene graph，以对象为节点、以对象间关系为边的结构）把这些结果统一保存。

第二，**按问题编译局部图**。先保留问题涉及的对象，再按关系相关性与距离选择少量边。图的大小由当前查询决定，而非把整张图像的所有关系都交给模型。

第三，**保留双向指代**。对象在图像中有唯一标记，文字关系可以引用同样的标记，模型返回的标记又能映射回区域。图像、文字与输出解析因而共享对象身份。论文测试数字编号与“类别_编号”两种显示方式，以及有无关系文字两种箭头形式。[原文§3、附录A–B](https://arxiv.org/html/2603.06663v2#A1)

[判断] 对“场景编译器”来说，这更像一个可替换的渲染后端：上游产生对象与关系，中间层选择任务需要的证据，下游输出图像或文字。其研究价值在于证明输入格式会影响冻结模型如何利用已有信息，同时提示必须进一步分离“多给了什么”与“怎样呈现”。

## 机制

**1. 从图像建立对象候选。**

系统并用 OWL-V2、YOLOv8-X 与 Mask R-CNN：前者支持文本指定的开放词汇类别，后两者补充常见对象检测。经过置信度筛选，WBF（按置信度加权融合同类重叠检测框的方法）合并重复框；SAM-HQ（细化实例边界的通用分割模型）再给出掩码，分割失败时保留框区域。

这里的掩码、类别、框与编号组成一个对象记录。掩码负责视觉范围，类别帮助语义匹配，框支持快速几何计算，编号负责跨表示引用。它们在接口中承担不同角色。

**示例数值：融合一次重复检测。** 假设两个检测器对同一物体给出置信度0.8与0.6，框分别为 `(10,20,50,60)`、`(11,21,51,61)`，坐标依次为左、上、右、下。两框交集面积为39×39=1521，并集为1600+1600−1521=1679，IoU（交并比）约0.906，超过论文的合并阈值0.9。按归一化置信度加权，左边界变为 `(0.8×10+0.6×11)/1.4≈10.43`；同理得到融合框约 `(10.43,20.43,50.43,60.43)`。这是讲解用算例，展示后续关系计算依赖怎样的对象输入。

**2. 用几何与深度生成关系。**

方向关系比较两个框中心的位移，选择较占主导的轴，再用阈值排除过小位移。深度关系由 MiDaS DPT-Large 产生的相对深度估计：框中心处的值归一化到 `[0,1]`，较大表示更靠近相机，差值超过阈值时产生前后关系。系统还定义近邻关系，以及依据框重叠、框边缘间隙和中心距离产生的接触、很近、较近修饰词。

这种设计把一部分空间判断移到了可检查的规则层。例如归一化深度为0.8和0.5时，差值0.3超过0.1的深度阈值，前端便可给出相对前后顺序。模型随后读取的是已经表达出来的关系，而不仅是原始像素。（此处是相对深度顺序，不能把0.3解释成米制距离。）[原文§3–4](https://arxiv.org/html/2603.06663v2#S3)

**3. 按问题缩小对象集合与边集合。**

对象匹配先查标签、别名与同义词，再比较 FastText 词向量的余弦相似度。FastText 在这里提供词语语义接近程度；WordNet 提供同义词集合。若找到多个有关对象，就保留它们及彼此关系；只找到一个时，保留该对象、以它为头节点的边及对应尾节点；一个也找不到时，回退到完整集合。

对每个头节点，边按“是否与问题相关、空间距离”依次排序，再取前k条。相关性的排序值是0，无关是1，因此它不是把两种数值随意相加。以讲解用候选分数 `(0,90)`、`(1,10)`、`(0,30)` 为例，取两条时会先保留距离30和90的相关边；距离只有10的无关边仍排在后面。原文默认k为3，最后还去掉正反方向的冗余连接。[原文§3、算法3](https://arxiv.org/html/2603.06663v2#A1)

这一步决定了图中哪些事实能被看见。它同时是检索策略与视觉密度控制，会改变模型可用证据的范围。

**4. 将同一对象图输出为视觉与文字提示。**

图像后端用同类同色的半透明掩码表示对象，添加数字ID或“类别_ID”，再画有向弧线。关系文字放在箭头附近；发生重叠时，标记沿坐标轴逐步移动，用虚线把移开的关系标记连接回原位置。布局策略的目的，是让增加的结构仍能对应原图中的对象。

文字后端采用“头对象—关系—尾对象”的三元组形式，并附解释性提示。附录区分只给视觉场景图，以及同时给视觉场景图和文字场景图两种模式。对于 REC（根据描述定位特定物体的任务），模型输出对象ID，程序据此返回对应区域。

[工程推论] 可迁移的接口约束是：同一次请求内，图像标记、文字节点和返回ID必须查同一张对象表；显示名可以换，内部对象键应保持不变。跨时刻的持久ID则需要另有跟踪与关联层。GoM 的静态图像流程为前一种绑定提供了范例。

## 证据：哪个实验支撑哪个主张

论文在 GQA、VQAv1、VQAv2 和 RefCOCOg 各随机取1000张图像，保留这些图像关联的全部问题。GQA主要检验组合式视觉问答，VQAv1/v2涵盖一般视觉问答，RefCOCOg检验描述指向哪个对象。算法配置先在 Qwen2.5-VL 的 GQA 预实验上选择；每种“模型×提示×数据集”再使用27种种子、温度、top-p组合运行。表中的误差范围来自这些解码设置，而非独立重抽数据集的置信区间。

下表保留决定解释的比较。前四行采用 Table 2 的仅视觉场景图设置，数值为准确率百分数；“文本ID”指画在图像里的类别加编号。

| 主张 | 支撑实验 | 怎么读 |
|---|---|---|
| 整体管线能显著改善小模型问答 | Gemma-3 4B / VQAv2：原图59.9，SoM 59.0，文本ID加关系标签71.9 | 相对原图提高12.0个百分点，相对SoM提高12.9个百分点；这是整套输入加工的收益 |
| 仅加对象标记可能损害某些模型 | Qwen2.5-VL 7B / VQAv1：原图77.7，SoM 65.4，文本ID加关系标签82.5 | GoM既补回SoM的损失，又超过原图；不能把“视觉标记”统一视为有益 |
| 关系文字比只有箭头更有说服力 | Gemma / VQAv2：数字ID无关系文字70.2，文本ID无关系文字62.8，文本ID加关系文字71.9 | 对象ID语义和关系标签存在交互；同为文本ID，加关系文字提高9.1个百分点 |
| 定位增益比部分问答增益小 | RefCOCOg：Gemma的SoM 54.8→最佳GoM 56.4；Qwen 55.5→57.5；LlamaV-o1 55.3→57.6 | 增幅分别为1.6、2.0、2.3个百分点；该任务采用预测区域与真值框IoU≥0.9的严格标准 |
| 更多边并非持续获益 | Figure 3：三模型VQAv2曲线在约8条边附近最高，超过16条后总体下降 | 支持控制提示密度；不等于已分离出纯拓扑的因果作用 |
| 额外处理有可见成本 | §5：GoM平均1.13秒/图，SoM 0.92秒/图，分割提示0.77秒/图 | 比SoM多0.21秒；这些是文中报告的图像增强延迟，不是完整机器人闭环频率 |

[AAAI作者稿Table 1–2、Figure 3–4与§5](https://github.com/disi-unibo-nlp/graph-of-marks/blob/main/paper/graph_of_marks_AAAI26.pdf)

最关键的消融是“只有箭头”与“带关系文字”的比较：Table 2的九个VQA模型—数据集组合，最佳项都带关系标签；但哪种对象ID最好仍随模型和任务变化。这支持把关系明示为输入的一部分，并按任务选择显示格式。

Figure 4对 Gemma 比较原图、原图加文字图、视觉图、视觉图加文字图，整体上视觉图强于只加文字图；图文联合在三个数据集上继续提升，在GQA上反而下降。它支持视觉落地的价值，但提示模板也随输入模式改变，尚不能完全把收益归给“画图”这一项。

[判断] 论文比“纯格式优化”提供了更宽的干预：对象类别、深度估计、关系词、问题相关筛选与像素布局都进入输入。Figure 7的SoM还标出了更多区域，GoM则明显聚焦少量候选。因此，最稳妥的实验证据是“这一组关系增强的输入管线有效”；若要声称“同等信息下，图像形式更好”，仍需固定对象、边、标签和输出约束，再只切换序列化方式。

## 局限与后续

**关系质量受前端与规则语义限制。** 框中心深度在遮挡、细长物体和背景穿透时可能失真；二维框接触与真实三维接触之间需要额外几何证据。面向操作系统时，可以为关系附上生成方法、坐标系、置信度与观测时间，并允许任务侧回查原始图像。[工程推论]

**查询裁剪需要保留推理所需的中间对象。** 直接提到的两个物体之间，可能还需要第三个物体才能消歧。按词语匹配保留对象、按头节点选边能控制成本，但多跳问题需要检验相关证据是否被裁掉。论文提出的后续方向包括更复杂的超图、双目深度与视频时序建模，尚未给出这些方向的结果。[原文§6](https://arxiv.org/html/2603.06663v2#S6)

**场景编译器可继承接口，另补持久状态。** [ConceptGraphs](../arxiv-2309.16650/reading.md) 提供跨视角对象关联，[3D-Mem](../arxiv-2411.17735/reading.md) 提供保留共视图像并按任务检索的路线。把它们与GoM连接起来的合理分工是：对象层维护身份，证据层维护原图和时间，查询层选子图，渲染层输出视觉图或文字图。这是跨论文的工程组合建议。

最有价值的下一步实验，是固定一份带稳定ID的场景记录，分别输出纯文字、原图加ID、关系覆盖图与图文联合；统一信息量、图像尺寸、解码设置和答案格式，再测任务正确率、引用ID有效率、关系事实准确率及延迟。如此才能判断改进来自额外感知、查询筛选，还是模型更容易读懂某种格式。[工程推论]

## 批注

**易误读**

- “Visual SG only”只是不在文字提示中另附场景图，图像本身仍可含类别ID与关系文字；不能解释为完全没有语言标签的视觉推理（§3、Table 2）。
- 摘要称最多提高11个百分点，而Table 2的Gemma/VQAv2原图59.9到71.9实际相差12.0个百分点；引用具体增益应给明对照项。
- §5称“文本ID、不带关系标签”一般最好，与Table 2图例和最佳项不符；图文联合“总有增益”的表述也与Figure 4的GQA柱图不符，本文依据图表描述。
- RefCOCOg要求输出ID并达到IoU≥0.9；原图与只有分割的输入在Table 2中没有该成绩。Figure 4却绘出相应原图柱，具体如何使两种设置可比，正文与附录没有交代（§4、Figure 4）。
- 正文先称恢复metric depth，实际实现用MiDaS相对深度；框中心前后关系不能直接作为可执行的米制距离或碰撞证据（§3–4）。
- 唯一标记保证单次图像中的指代；论文未展示跨帧身份保持、对象移动后重识别或持久ID评测（算法4–5、§6）。

**与其他论文的关联**

- [SoM](https://arxiv.org/abs/2310.11441) 建立“可说出的标记→视觉区域”的反向映射；GoM继承这条接口，新增关系估计、筛选与绘制。评价增量时应保持候选对象与ID分配一致。
- [ConceptGraphs](../arxiv-2309.16650/reading.md) 关注多视角对象地图及其关系；GoM关注任务模型怎样读取关系。两者分别位于地图维护与输入呈现环节，可组合，但不能用GoM的静态问答提升替代地图一致性实验。
- [3D-Mem](../arxiv-2411.17735/reading.md) 以共视图像保留背景和布局，GoM把估计出的关系再画回图像。前者重在选哪些视觉证据，后者重在怎样标注证据；组合后需要检查重复标记与遮挡是否反而增加干扰。

**未核实 / 待验证**

- 未见将检测器、深度来源、查询筛选、标记布局和关系信息量全部固定的成套消融，也未见机器人真实执行实验。
- 附录算法3在“没有匹配对象”分支保留全部对象，但没有显式恢复全部关系；正文则说明两者均保留。方向关系符号与三元组头尾的实现约定也需用最小测试确认。
- 开源仓库现有README列出的深度模型、默认检测器和WBF默认阈值与论文实验配置有差别；复现应锁定实验配置与提交，而非直接采用当前默认值。[作者代码](https://github.com/disi-unibo-nlp/graph-of-marks)
