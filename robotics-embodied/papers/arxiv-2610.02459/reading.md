# OpenRUA：通用 Agent 怎样使用原生机器人接口

论文卡（本地来源，未发布） · [官方原文](https://arxiv.org/abs/2610.02459v1) · [官方 PDF](https://arxiv.org/pdf/2610.02459v1)

## 是否一定需要为 Agent 再造一层机器人接口

OpenRUA 让通用 coding agent 通过终端使用原生 ROS 2，把机器人当成一个可探索的软件工作区。起点是机器人文档、配置与基本工具；Agent 自己决定读哪些资料、怎样获得观测、写什么程序和何时验证，不预设完整任务流程。（§3）

## 把方块放进碗里的实际链条

Agent 先了解话题、服务、坐标系、关节和限制，保存 RGB-D 等观测为文件；它可以写点云、裁图或几何计算代码，从现场确定目标，再通过 `rclpy` 或 CLI 请求轨迹与夹爪动作。执行后重新查看观测和状态，按结果修改程序。工作目录里逐渐形成感知和控制客户端。

“zero-abstraction”指不再添加特制 Agent 任务抽象，不是机器人没有抽象、控制器或先验。ROS 2 原生接口、标定、运动服务和启动文档仍承载工程能力；底层执行也不会因为 Agent 会写代码而自动变得可靠。

## 零样例与分数的精确含义

论文每个 episode 使用新的工作区，不继承其他回合的任务记忆，不使用任务专门训练；Agent 看不到 simulator 特权状态或基准成功 predicate。主要量化评测是 CaP-Bench、LIBERO-Pro 和 RoboCasa365 仿真，不能仅凭接口支持真机就把这些数值称为真实机器人结果。（§4.1）

Claude Opus 5 条件下作者报告 CaP-Bench 99.0%、LIBERO-Pro 87.0%。其总表也列出其他论文的报告数字，不是所有方法在这里重新配对跑出的统一排名；模型版本、探索经验、工具和预算差异仍需核对。（§4.2、附录 C）

## 与当前工程的关系

它提供一个有价值的反方向检验：如果通用 Agent 可以从原生工具自己建立程序，那么人为编写很多专用宏的收益究竟来自便利、稳健性还是缩小问题？答案不应由口号决定，而应测同预算下的成功、耗时与失败可诊断性。

当前 RPent 已有成熟固定接口，没必要为了“最薄 harness”立即拆掉它。可以先借鉴清楚的机器人文档、坐标/观测文件与日志结构；原生接口路线可作为以后独立对照，本次没有接入 ROS 2 或修改运行环境。
