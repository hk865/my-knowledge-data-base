# RoboSkill：把代码、触觉与迁移的收益拆开检验

> 状态：技术精读 · arXiv v1 · 未复现

## 一句话

RoboSkill 的价值要分别用“保留了什么经验、迁移到谁、节约哪一种成本”检验；同任务复用、异任务迁移、跨 Agent 迁移和反复更新，对应的是不同能力。

## 它要解决的问题

[Voyager](../../../llm/papers/arxiv-2305.16291/README.md)把交互经历变成代码技能库，证明外部程序可以积累经验。真实机器人进一步遇到两种不确定性：程序执行成功不等于物体真的被拿起；一次成功程序也未必适合下一张桌子的坐标、物体状态和接触条件。RoboSkill 让通用多模态 Agent 经由 SDK 编程控制与感知，把会话中的探索、执行及复盘接起来。

SDK 是供程序调用的机器人控制和观测接口。它允许 Agent 把感知处理、动作与检查点写成可重用程序。技能包保存文字策略、实际执行代码、失败记录、轨迹、元数据和关键帧；新任务读取相关包并按当前场景重新适配。模型权重与动作接口在各组比较中保持固定，变化的是经验输入。见 §3–4。

这种系统不能只用“有记忆比无记忆好”描述。一个 Agent 拿到同任务成功经验，和只拿到另一个任务经验，难度不同；更少重试、更短用时和更高首回合成功，也可能发生取舍。本文最有用的实验贡献，是提供了能分开追问这些机制的几组对照。

## 核心想法

把技能复用拆成三层证据：

1. **程序保留。** 代码是否减少重新推理与编程的工作？比较同任务文字技能与文字加代码技能。
2. **物理信息。** 接触反馈是否帮助获取当前状态？比较探索时保留或移除触觉相关观测。
3. **经验适用范围。** 同任务技能、异任务技能、不同 Agent 产生的技能，能否在固定测试条件下帮助执行？分别改变技能来源，而不是把所有提高归成一种“泛化”。

论文的循环在执行退出后调用同一 Agent 作 reviewer，整理已执行记录，更新已有技能或新建技能。执行中暂存知识，避免每完成一个小动作都进行昂贵复盘。新任务按元数据选择最多三个技能。因此可复用的信息、现场反馈和选择过程是三个不同干预点。见 §3.2–3.4。

## 机制

### 先固定评估单位，再判断变好的是什么

仿真的基本单位是 task–seed cell，即一个任务和一个环境初始随机种子的组合。每 cell 可在四小时内 reset 多次；第一次尝试为 Episode 1。Final SR 表示终止前成功的 cell 比例，1st SR 表示第一次 episode 就成功的比例，SR@30m 则要求三十分钟内成功。平均 episode 数和平均时间都覆盖成功及失败 cell，终止可由成功、Agent 主动退出或超时触发。见 §4.1、§6.1–6.2。

主实验在十个 LIBERO-10 任务上用 seeds 1–4，共四十个 cell；构建技能的 seed 0 被排除。跨任务和跨 Agent 则用 seeds 0–4，共五十个 cell。技能迭代另用 seeds 100–104，并把所有比较条件重新运行。它们回答的测试问题不同，具体分母随实验改变。

**示例数值：主标题的提高，不能替代正确的对照。** Sol 在同一四十 cell 协议下，无技能的首回合成功率为 27.5%，即 11/40；单个同任务技能为 67.5%，即 27/40；允许再选其他任务技能的 Top-K 方案为 52.5%，即 21/40。相对无技能，Top-K 多完成十个首回合；相对已有同任务技能，它反而少六个。前者支持技能输入有用，后者不支持额外异任务信息必然提高可靠性。见 Tables 1、3。

这也解释为何必须区分 Baseline、RoboSkill⁻ 和 RoboSkill：前者没有保存技能，中者只给一个同任务技能，后者可选至多三个。在真实机器人主实验中，只提供一个同任务技能，RoboSkill 与 RoboSkill⁻ 等价。

### 代码提供的是怎样的额外信息

Table 9 保留文字说明，只移除技能中的代码。代码保存循环、坐标转换、感知处理和异常处理等过程，让 Agent 少做一轮“从策略到程序”的翻译。它仍需重新获取现场状态并修改参数，实际执行也由当前 Agent 决定。

这组干预衡量“提供整个代码部分”的收益。它没有把上下文长度、伪代码、程序结构和真正执行代码的作用分别拆开。配合 §8 的说明，提供某个包也不等于包里每段程序都被调用过。若研究下一步系统，应该同时记录被选技能、被读取内容、真正执行的代码版本和所依赖现场变量，再判断节约发生在检索、推理、编码还是物理动作阶段。

### 触觉消融同时改变了哪些观测

真实装置使用 Piper 右臂、两指触觉传感器、腕部相机及外部俯视相机；照片中的左臂未用于实验。真实任务每次只有一个 episode，最多一小时，由现场志愿者判断成功。见 §5、§6.4。

触觉在此泛指压力和力/力矩反馈，给接触、碰撞及夹持增加图像之外的信息。可视化“夹爪贴到物体”与确实产生有效抓持，是不同观测问题。但 Table 10 的仿真 w/o tactile 条件同时移除了全部力相关信息和夹爪状态；真机条件则移除触觉传感器观测。两者是不同的观测删减，不能把仿真效果单独归因于一种压力传感器。

**示例数值：小样本变化对应多少次。** Remove Test Tube 真机消融每组十次，80% 与 90% 分别是八次与九次成功，只差一次。它提供支持触觉的具体案例，同时提示复验应增加任务与重复次数，而不是只报告百分比。仿真中首回合成功反而略降、三十分钟内成功提高，说明反馈可能主要改善后续判断与执行效率。见 Table 10。

### “会选技能”与“会迁移技能”怎样区分

Table 15 的所有 Agent 对每个目标任务，都把同任务技能放在所选列表第一位；选择主要是在已有同任务方案上添加或删减补充技能。它支持相关信息筛选，不是未知任务上只靠异任务库的检索测试。

更直接的异任务测试是 Table 4：固定五对源–目标任务，并双向评估，共十种方向，只给源任务技能。跨 Agent 测试则换技能作者、保持同任务：Kimi K3 接收 Astra、Sol、Fable 或 Opus 产生的技能。真实跨 Agent 测试也只在六个 easy 任务中，把 Astra 技能交给 Sol。任务变化和执行者变化被分开，是这组实验更清楚的地方。见 §6.3。

## 证据：哪个实验支撑哪个主张

| 主张 | 支撑实验 | 怎么读 |
|---|---|---|
| 代码可显著补足部分 Agent 的技能利用能力 | Table 9：Sol 首回合 15.0→67.5%，时间 67.1→39.9 分钟；Opus 首回合 70.0→67.5% | 时间在四个 Agent 均下降，可靠性不是全部提高 |
| 触觉相关观测有助及时完成 | Table 10 仿真：SR@30m 74→94%，平均时间 25.35→15.93 分钟；首回合 82→78% | 支持时间与后续执行收益；仿真同时删掉夹爪状态 |
| 增加技能可能引入干扰 | Table 3：Sol 单同任务首回合 67.5%，Top-K 为 52.5% | 技能数量、成员与选择一起变化，归因需要进一步控制 |
| 异任务信息不保证首回合提高 | Table 4：Sol 30→44%，Opus 60→56%；两者平均时间下降 | 部分经验可复用，但可靠性与成本有取舍 |
| 程序经验可跨 Agent 重用 | Table 5：Kimi K3 首回合 12→42–66%，依来源而不同 | 是同任务、跨作者迁移，且该五-seed协议包含构建seed |
| 更新成功经验不等于单调改善 | Table 7：Opus 第一次更新后 SR@30m 86%，第二次降到 74%；Table 8 真机更新提高成功但成功用时变长 | 经验累积需要独立验证与版本回退，而非只检查构建回合成功 |

真实分任务结果还暴露平均值隐藏的失败：Table 13 中“从针眼移除线”由 7/10 降至 5/10，而整体成功率提高。技能可能固化不适合该任务的过程，完整分任务结果比整体“提高8.3点”更适合诊断技能库。

## 局限与后续

**先把建立技能的成本纳入账本。** 表中的收益主要描述复用阶段。若创建技能耗时 C_build，每次之后由 t_base 降至 t_reuse，摊销总成本可写成 C_build+N·t_reuse，对照 N·t_base；当 N>C_build/(t_base−t_reuse) 时才在时间上回本。这是基于成本定义的工程推导，不是论文给出的回本实验。例取构建120分钟、每次省10分钟，超过12次后才回本；真实节约还要同时满足成功率、风险和人工监控要求。

**建立更能归因的对照。** 下一步可以固定技能数量和上下文预算，再比较等信息量文字、伪代码、可执行程序；固定测试 seeds，分别测同任务、异任务与跨 Agent；保留测试阶段技能快照，单独核算库更新。论文已有多种对照，但没有证明长期库增长、广泛未见任务和不同硬件上的稳定迁移。

[BATON](../arxiv-2608.16889/reading.md)把经验的单位进一步放在子任务及衔接条件上；[AdaHVLA](../arxiv-2609.29204/reading.md)把可改写对象放在协调策略与候选修订图上。[判断] 它们提示下一步评估可分别控制“改技能内容”和“改调用/衔接策略”，避免同一成功回合同时改变多处，最后无法知道哪一处有效。

## 批注

**易误读**
- 这里的 evolution 是外部技能更新，不是每次交互重新训练模型权重；比较中的模型参数与接口保持固定（§4.1）。
- 主结果40-cell协议排除技能构建seed，跨 Agent50-cell协议包含seed 0；后者不完全等价于前者的未见初始状态测试（§6.1）。
- 仿真 Avg.Time 含失败终止，真机 Avg.Time 只含成功试验；两种均值不能直接合并，较早放弃也可能降低仿真均值（§6.2/6.4）。
- Top-K 选择名单证明哪些技能可用，不证明哪些组件实际被执行；技能数与成员同时变化，也未隔离纯数量收益（§8）。
- 全文有一处 skill reuse 的“??”交叉引用占位；相关协议以已实际列出的 §3.4、§6–8 为依据，不补造缺失章节。

**与其他论文的关联**
- [Voyager](../../../llm/papers/arxiv-2305.16291/README.md)提供交互经验沉淀为代码技能库的前作；本文增加真实接触反馈和物理任务复用，其评估还要计入感知、动作与监控成本。
- [BATON](../arxiv-2608.16889/reading.md)关心单个子任务成功后，下一段是否继承到可用状态；本文主要测技能内容复用，二者可对应“记住怎样做”与“检查能否接着做”的不同层次。
- [AdaHVLA](../arxiv-2609.29204/reading.md)以执行证据改写 harness 协调程序；本文保存并选择程序技能。对二者应分别记录策略修订成本和技能构建成本，不能只比较最终执行成功率。

**未核实 / 待验证**
- 全文结果均为作者报告，未独立运行程序、测量时间、核验日志或控制真实机器人。
- 未将代码收益进一步拆成更长上下文、结构提示和实际复用执行三种因果来源，也未验证 Agent 自我复盘是否总能保留正确失败条件。
- 摊销模型是显式假设下的计算工具；构建120分钟等示例数值是自拟例子，不是论文实测。
