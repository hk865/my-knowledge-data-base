# Foundation4D：共享时空表征，分阶段接入感知与高斯重建

技术精读 · v1 · 未复现

## 一句话

Foundation4D 把多相机驾驶视频的几何、检测、占据和高斯外观接到共享表征上，但其训练配方的价值应与配方为何取这些数值的证据分开看：论文给出了阶段与权重，未证明冻结时点和权重组合最优。[原文](https://arxiv.org/html/2610.30340v1)

## 它要解决的问题

驾驶场景不仅需要知道物体在哪里，还要把环境重新渲染出来。若深度、检测、占据和重建分别使用完整网络，相同图像会被重复处理，不同系统的坐标、对象身份和时间也需要再对齐。这里的“占据”指空间体素是否被物体占用及其类别，不是仅对可见像素做分割；“rig”是固定在同一车体上的相机组合；“ego motion”是车辆自身运动。

模型窗口只能覆盖有限时间，整段视频又要求轨迹一致。因此需要区分：窗口内前馈预测、跨窗口轨迹拼接、对象跟踪以及下游逐场景高斯优化。把其中任一部分的速度当作整个系统速度，会误读论文。

前作 [VGGT](../arxiv-2503.11651/README.md)建立多图像几何恢复的表征基础；[Instant NuRec](https://arxiv.org/abs/2607.14203)侧重从驾驶日志预测可渲染高斯。本工作要连接这些能力，而不是只替换一个渲染器。

## 核心想法

网络共享图像编码器与分解式时空注意力，分支输出几何、检测、占据和高斯；视频层再做轨迹优化与离线跟踪。官方项目还发布了带密集深度和占据标注的共同评测基准。[架构与项目](https://research.nvidia.com/labs/sil/projects/foundation4d/)

核心增量有两层：一是让任务共用输入理解，而非四条独立流水线；二是明确处理静态相机布局与动态车辆/对象轨迹的区别。它没有证明“增加任务总是改善一切”，实际更像一套有正迁移也有冲突的统一系统。共享并不等于所有模块从训练第一步到最后一步都一起更新。

## 机制

### 从输入到输出：先理解信息怎样流动

输入是带拍摄时间的多相机图像。编码器逐图提取特征，聚合器交替沿相机维和时间维交流信息；细空间特征保留给检测与占据。几何头把固定相机布局与时变轨迹分开，深度转点云；高斯头解码深度、外观和形状，对象轨迹负责把动态高斯搬到目标时刻。长视频处理不更新网络参数。[原文 §3、§5](https://arxiv.org/html/2610.30340v1#S3)

相机位姿写作 T(t,c)=T_ego(τ_t,c)T_rig(c)。这是一种结构化参数化：同一相机的车体相对变换跨时刻共享，而轨迹随时间变。它利用的是相机固定安装这一结构假设，不是把每帧相机自由当作互不相关变量。

对单位相机射线 r 与 camera z-depth d，点/高斯中心为：

μ = R·[d/r_z]·r+t。

**示例手算，非论文实验值：**若 r=(0.6,0,0.8)、d=10m、R=I、t=0，则沿射线的距离是 10/0.8=12.5m，μ=(7.5,0,10)m。若误把 z-depth 当射线长度，结果会变成 (6,0,8)m。这个例子说明“网络预测深度后沿已知射线定位”确实给高斯中心加入了参数化结构，但不等于所有位置都由现成三维真值固定；深度仍需学习，位姿误差仍会传入中心。

### 三阶段训练：冻结的是谁，为什么不能泛化为“冻主干”

第一阶段联合更新图像编码器、聚合器和三个感知头；第二阶段延长时间窗口、冻结图像编码器，继续更新聚合器和感知头；第三阶段先固定现有模型、暖启动高斯头，再保持编码器冻结、联合更新聚合器与四任务头。[§4.2](https://arxiv.org/html/2610.30340v1#S4.SS2)

image encoder 与 spatiotemporal aggregator 都在共享路径上，然而后者在第二、三阶段仍可学习。因此“冻结 backbone”过于含糊，容易错冻全部时空聚合器。第一阶段是适应多任务，第二阶段是增加时序范围，第三阶段才承担重建解码和可微渲染成本。

感知阶段约 170K 与 45K 更新；高斯暖启动后再做 10K 联合更新，编码器先前的学习率也低于其余模块。原文没有给出高斯暖启动的明确更新步数；最终联合权重为：

L=1·L_geo+0.1·L_det+0.2·L_occ+4·L_gs。

仅对激活任务、存在有效标注的数据计算对应损失。[§4.2–4.3](https://arxiv.org/html/2610.30340v1#S4)

延后接高斯任务的明确动机是计算成本，而“为了避免重建梯度破坏几何所以冻结”只是合理猜测，不能替换作者未做的因果实验。冻结不意味着不用前向计算，也不意味着吞吐量按可训练参数比例提高。注意力、激活保存、任务头和渲染仍然可能占据主要成本。

### loss 权重：原文的设定，不是自动选参算法

几何、检测、占据、高斯的任务级系数之外，每个任务内部还有残差尺度、归一化、有效区域、多个辅助损失。原文把深度/位置/平移按固定长度缩放，并给高斯重建加入图像、感知、逆距离、不透明度、法线等监督。语义掩码部分使用 stop-gradient，即阻断该路径反向影响语义预测。[§3.4、§3.7](https://arxiv.org/html/2610.30340v1#S3)

最关键的问题不是“4 比 0.1 大四十倍”，而是共享参数实际收到什么梯度。设共享参数为 θ，则 g=Σ_k λ_k∇θL_k。即便高斯系数为 4，如果其梯度范数为 0.1，而几何梯度范数为 2，加权范数也只是 0.4 对 2；若方向相反还会抵消。**这些范数是示例，不是论文测量。**只看 loss 标量或系数，不足以判断谁主导训练。

数据采样也构成隐含权重。若任务 k 的标注仅在部分批次可用，长期平均贡献更接近 E[m_k λ_k∇L_k]，而不是固定 λ_k 本身；m_k 表示该批次该任务是否有效。因此改数据比例、标注覆盖或 mask 规则以后，原权重的意义也会改变。不能脱离论文数据配方照搬一组系数。

### 对“选参前置证据”的直接回答

在已核对的正文训练部分、任务组合实验及局限中，未见权重网格搜索、梯度范数/余弦分析、自动任务加权、冻结与不冻结的等预算对照，或逐阶段加入高斯的时机消融。论文说明了“采用何种方案”，不能据此断言这组方案通过上述程序确定。

以下设计理由可以借鉴，但并未被本文实验单独证明：先适应图像编码器，再固定它以限制后续训练成本；用较短窗口建立能力，再增加时序；让新任务头先适配现有特征，再联合微调。它们可作为实验假设，而非适用于一切多任务训练的定律。

若要把该思路用到新项目，建议先做以下低成本诊断，而不是先展开全组合搜索：

1. 固定每个任务的单位、求和/平均方式和 mask，记录有效样本数；否则不同 loss 量级不可比。
2. 在共享聚合器抽样记录各任务梯度范数与成对方向余弦，找出长期压倒或冲突的任务；这是诊断，不是保证最优的权重公式。
3. 用同样数据、更新次数和总算力预算比较冻结编码器、低学习率更新编码器两种方案，防止把更多训练步的收益误归因于冻结。
4. 把新头冷启动、暖启动及从头联合三种方案分开；若只能做少量实验，先关注旧任务是否退化、新任务是否收敛及峰值显存。
5. 最终以验证任务指标与预算约束选配方，并记录测试集未参与选参。不得将这些建议写成 Foundation4D 已执行的流程。

以下只保留一张证据表，数字来自对应表内条件，不跨实验直接排榜。[原文实验与局限](https://arxiv.org/html/2610.30340v1#S7)

| 主张 | 支撑实验 | 怎么读 |
|---|---|---|
| 多任务有正迁移 | Table 16：检测 top-mAP，单任务 40.94%→三任务 42.14% | 支持当前配方下检测获益；四相机、80K 单阶段实验，不是最终六相机三阶段配方的消融 |
| 多任务也有冲突 | 同表：GEO+OCC 的 mIoU 11.82%，三任务 11.53% | 增加检测未让占据更好，不能声称任务越多越好 |

| 高斯任务有明显计算成本 | Table 17：T=24 时高斯头约 3.255s，完整前向 9.673s，不含渲染 | 支持关注解码成本；不是冻结策略优于不冻结的直接对照，也不是实时在线速度 |
| 最终高斯输出可用 | §7.4 与 Instant NuRec 比较 | 不同输入相机数、位姿来源与窗口方案，不能把全部增益归给高斯头 |

## 局限与后续

训练数据和标注流水线是重要前提，而不只是网络结构。该模型利用内部驾驶集合；“推理不输入 LiDAR”不代表训练从未用 LiDAR 生成深度。动态物体、异步曝光、细结构和远距离区域仍有挑战。高斯训练用真实位姿与对象轨迹，推理改用预测量，必须考虑该条件变化。[数据与局限](https://arxiv.org/html/2610.30340v1#S9)

这篇最值得借鉴的是把变量依赖关系拆清楚，再决定哪里共享、哪里固定。最不值得照搬的是把阶段数、更新数、权重当作没有上下文的常数。若目标是在线机器人，必须另测因果窗口、延迟、峰值显存与轨迹漂移；离线未来帧信息和后向平滑不应悄悄进入在线评估。

下游 NuRec 的流程加速还混合了软件、硬件与相机配置变化，原文明示不是隔离单个算法变化的实验。因此只能说该版本流水线更快，不能直接解释成 Foundation4D 某个冻结策略带来同等倍数收益。

## 批注

### 易误读

- “冻结图像编码器”不等于冻结全部共享网络；“stop-gradient 掩码”也不是整模型冻结。
- λ_gs=4 不是对高斯真值可信度的概率估计，更不是某个物理单位换算。
- 三阶段主配方、四相机任务组合实验、公开基准专项微调是不同设置，不能拼成同一个实验叙述。
- 几何分支预测 rig 标定，不等于所有分支都无标定输入；检测/占据/高斯的投影仍有已知标定条件。

### 与其他论文的关联

- 与 [VGGT](../arxiv-2503.11651/README.md)：沿用几何表征思路，但把全局交流拆为相机/时间组；值得比较表征效率与准确度代价，不能仅说“更高效所以更好”。
- 与 [Instant NuRec](https://arxiv.org/abs/2607.14203)：同样分离静态、动态与天空外观；Foundation4D 更强调感知提供轨迹，但两者比较有输入条件差异。
- 与 [3DGS-LM](https://arxiv.org/html/2409.12892v2)：后者加速单场景参数拟合，本文把大量代价转移到跨场景训练；“前馈快”与“优化器快”不在同一计算账本。

### 未核实

- 未核到这组任务级 loss 权重的搜索日志、候选范围、选择指标与随机种子稳定性；不据此推测作者未做过任何内部调参。
- 未核到高斯头暖启动准确步数；10K 是后续联合更新数。
- 未核验公开训练配置是否完整重现论文全部内部数据与阶段；本笔记不提供伪装成官方的训练命令。
