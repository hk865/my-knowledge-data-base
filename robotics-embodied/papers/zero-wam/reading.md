# Zero WAM 如何把人类示范视频变成机器人动作

> 状态：机制教学 · 原文 arXiv:2608.26103v2 · 未复现

本文回答一个很具体的问题：机器人看过一段人类操作视频后，能否在不为这个新任务重新训练参数的情况下照着做？Zero-WAM研究的是这条路线。它是具身Agent可以使用的动作生成底座。[1]

## 先想象一个人也会遇到的说明问题

假设桌上放着两个小盒子、一只杯子和三根不同颜色的短杆。你说“把东西装好”，即使听者认得每个物体，也不知道该用哪根杆、插哪个孔、先放杯子还是先盖盒子。你可以写很长的说明，也可以拍一段示范。

视频额外提供了两类信息：目标状态是什么，以及中间变化按什么顺序发生。但视频中的手不是机械夹爪，拍摄视角也不等于机器人的摄像头视角。把人手的像素轨迹直接变成机械臂轨迹，通常没有意义。更合理的学习目标是：先理解这段示范要求世界发生什么变化，再用机器人自己的动作去实现。

这个例子是本文的教学例子。它帮助我们把“模仿视频”拆成两个问题：理解任务和生成可执行动作。

## 架构的关键是一个中间桥梁

Zero-WAM把人类视频作为上下文，把机器人已经看到和做过的内容作为历史，先预测机器人接下来会看到的视频片段，再据此解码相应动作。视频分支与动作分支通过Mixture-of-Transformers结构交互：两种模态各有自己的网络参数，通过注意力交换信息。重要细节是，动作分支不直接读取人类视频；人类示范的任务信息先进入预测出的机器人视频，再影响动作。[2]

这里必须区分训练与部署：训练动作分支时，条件中的下一段机器人视频采用数据里的真实片段，这叫teacher forcing，也就是先给出正确的中间条件来学习动作；部署时拿不到真实未来，才改用视频分支生成的片段。[2] 因而视频预测误差会在部署时传到动作侧。

可以把它理解为一个会画草图的操作员。操作员看到人把红杆插进右侧孔，先画出“我这台机器人把红杆移到右侧孔附近”会是什么样子，然后决定夹爪如何移动。草图不是机器人最终完成任务的证据，只是动作计算的中间表示。如果草图画错了，后面的动作即使忠实执行，也会把事情做错。

```mermaid
flowchart LR
    H[人类示范视频] --> V[视频预测分支]
    O[机器人观测与动作历史] --> V
    V --> F[下一段机器人视频预测]
    F --> A[动作解码分支]
    O --> A
    A --> R[机器人执行动作片段]
    R --> N[新的真实观测]
    N --> O
```

上图是部署时的简化数据流。图中最值得记住的是“新的真实观测”这条回路。生成的未来图像不等于真实传感器读数。一个实际执行系统仍要面对模型想象与物理世界的差异。本文将数据流画成教学简图，省略了潜变量编码、噪声采样和位置编码等实现细节。

“上下文学习”的前提是模型事先已经经过大量训练。新示范在部署时进入输入上下文，改变本次行为；它不需要为这个留出的任务再更新模型参数。正如一个已经学会阅读的人看一份新说明书，不等于从零学习语言。

## 为什么仅把视频塞进输入还不够

现在假设训练集中大多数片段都是“夹爪靠近杯子，然后抓杯子”。模型只看最近几帧就能猜中下一步。即使旁边还有完整示范，它也可能懒得用。训练损失看起来不错，却没有学会在陌生任务中认真读示范。

Zero-WAM使用IFP，即训练时的跨步未来片段预测，让当前表示承担更远期的预测任务。辅助分支必须通过主视频分支的当前表示获取示范信息，不能直接绕过去看人类视频；部署时这些辅助分支被移除。[2]

一个教学类比是：如果考试只问故事下一句话，学生可能靠语法猜；若还要求预测几个阶段后的情节，就更需要理解故事目标。因此作者做了消融实验。

正文的IFP消融中，七任务平均成功率从无IFP的28.55%升到46.95%。这是支持该训练设计有用的证据（它没有单独证明所有收益都来自人类式的任务理解）。[2]

## 数据从哪里来

示范视频能够说明任务，机器人轨迹能够提供真实动作标签。理想训练样本需要这两种信息成对出现，人工逐个采集会很贵。

HumanGen采用反向构造：从已有机器人轨迹出发，分析物体状态变化，生成语义相符的人类操作视频，再做语义与物理合理性筛选。机器人原始动作标签保留下来，人类视频则成为输入提示。作者报告约7.42万对样本、8600个任务。另一部分Task-diverse VA数据按任务采样，避免少数任务的重复轨迹淹没其他任务。[3]

这里有一个很有价值的机器学习思想：训练数据的作用由输入与监督目标的分工决定。人类视频不必提供机器人关节角，它负责说明“要做什么”；与之配对的机器人记录负责告诉模型“这种机体怎样做到”。

## 47%到底说明了什么

最常被转述的数字是约47%。其精确值为46.95%，来自RoboTwin 2.0中七个留出任务的宏平均；模型在其余43个任务上进行后训练。每个种子、每项任务运行100次闭环试验，共三个种子。LingBot-VA对应平均为17.45%，差距是29.50个百分点。两项任务的成功判据作了调整，对所有比较方法一致使用。[2][4]

宏平均把每项任务的成功率等权平均（它不是“面对任意新任务有47%的成功概率”）。比如该评测里放空杯成功率为84.87%，叠三个方块仅9%；任务难度和失败结构被一个平均数压缩了。[4]

真机实验也必须单独看：论文在双臂Franka上测试物体入容器、三物体顺序操作、两条桌腿插接。它先用已见配置的机器人示范适配机体，再测试留出的配置。[2]

对于初学者，更稳妥的结论是：视频作为任务说明，配合专门的数据和训练目标，可以改善这组未见任务上的迁移；它还没有让长程桌面操作变成高可靠能力。

## 它和具身Agent的关系

如果把一个具身Agent拆成“理解目标、选择子目标、生成动作、检查结果、保存经验”，Zero-WAM主要强化动作生成时的任务说明接口。它让“给一段示范”成为可计算的输入形式。

但是一个完整Agent还要回答：示范与当前场景冲突时听谁的？夹爪滑落后是否重试？什么时候重新拍摄？连续失败后是否停机？谁来判断任务已经完成？这些问题需要上层执行与验证机制。

学习时可以做一个纸面练习：画出“示范中是红杆，但当前场景只有蓝杆”的流程。视频提示负责哪种信息？机器人观测负责哪种信息？谁有权决定替代物？如果图里没有一个模块回答最后的问题，就说明系统还缺少任务级决策，而不是动作模型的名称不够先进。

这篇论文最值得带走的观念是：新任务泛化不只取决于模型有多大，还取决于新任务被怎样说明，以及训练时是否真的迫使模型利用这份说明。

## 局限与后续

**作者自述。** 实验主要是静止的桌面操作，作者把更复杂、动态、非结构化的环境留给未来工作；最难的留出长程任务是叠三个方块，Zero-WAM 只有9%，其他方法为0%。[2] 官方README说明，公开训练数据只覆盖原训练混合的一部分，用发布数据重新后训练会与发布checkpoint（保存的模型参数）不同。[4]

**合成数据的风险。** [判断] 合成视频是否真的保留了任务语义，是这条路线最需要追问的地方。例如，生成器可能让杆穿过盒子表面，或者让物体在遮挡后突然出现在目标处。质量筛选可以减少问题，但不能自动保证每一对训练数据都准确。依据是 HumanGen 的数据管线描述。

**它在修补谁的不足。** 论文相关工作指出，已有的“视频作提示”系统要么覆盖的任务有限，要么随任务增多需要额外人工采集人类视频，并把 Vid2Robot、BC-Z 和 [Behavior Prompting Policy](../arxiv-2606.30457/README.md) 归入这一类。[2] HumanGen 的反向构造正是针对“人工采集”这一瓶颈。[判断] Behavior Prompting Policy 自己的结论是任务多样性是提示能力的主要驱动因素，这与本文单独构造 Task-diverse VA 数据的做法相互印证；两篇相隔约两个月，说明“示范作提示”的瓶颈已从架构转到数据覆盖。

**动作侧的代价。** [判断] 与只生成动作的 [Diffusion Policy](../diffusion-policy/reading.md) 和 VLA 相比，本文多了一步视频预测，部署时视频预测的误差会传给动作分支；这一误差的大小与多出来的推理延迟，是部署前要先测的量。

## 批注

**易误读**

- Zero-WAM 是动作生成底座，不是一个已经包含长期记忆、任务调度、权限管理和失败恢复的完整 Agent 框架；理解这个位置，比先记住模型缩写更重要。也不要把一个 WAM 自动升级成通用 Agent，更不要把具身 Agent 与 AGI 混为一谈。
- 版本：v1 发布于2026年8月26日，v2 于8月27日，是同一论文的修订关系，不是两代独立模型。本页按 v2 引用。[1]
- 训练数据流和执行数据流不能画成完全相同：训练时动作分支以真实未来视频为条件（teacher forcing），部署时用的是预测视频（§2）。
- “上下文学习”不意味着机器人一开始什么都不会。
- IFP 带来的“更需要理解任务”是训练压力，不是逻辑保证，模型仍可能学到别的相关性；不能把训练意图直接当成已经证明的心理机制。
- 真机实验先用已见配置的机器人示范适配机体，所以“测试新配置时不更新参数”不能写成“从未为这台机器人训练”。
- 论文标题中的 open-ended 描述研究方向，不能替代测试范围。
- v2 正文列出的四个 IFP 损失权重最后一项为0.15，官方 README 的 MCP 配置最后一项为0.1。两处文档有差异，本页不猜测哪项是笔误。[2][4]

**与其他论文的关联**

- `[历史]` 论文把 Vid2Robot、BC-Z 与 [Behavior Prompting Policy](../arxiv-2606.30457/README.md) 列为“以人类视频作任务提示”的前作，主要对照是视频-动作模型 LingBot-VA。
- `[结构]` [In-Context Imitation Learning via Next-Token Prediction（ICRT）](../arxiv-2408.15980/README.md) 也是“提示一段示范、不更新参数执行新任务”，但它的提示是遥操作采集的机器人轨迹（图像、动作、状态），本文换成人类视频，因此需要中间的机器人视频预测来跨越机体差异。核验时未在本文相关工作中找到对 ICRT 的引用，两者的联系是结构上的。
- `[结构]` [Diffusion Policy](../diffusion-policy/reading.md) 只生成动作、刻意不生成未来画面；本文先生成未来视频再解码动作，属于世界-动作模型一支，背景见 [世界模型讲义](../../fields/world-models.md)。
- 在具身 Agent 闭环里，本文只覆盖“生成动作”一段；检查与恢复见 [EmbodiedSkills](../embodiedskills/reading.md)。

**未核实 / 待验证**

- 本页核读了 v2 的第2至4节（数据构造、因果视频动作建模、IFP、推理设置、仿真与真机实验及消融）、讨论、官方项目页、仓库 README 和安装说明。没有运行训练、推理或机器人试验，没有独立验证成功率；没有逐行比较 v1 与 v2。
- 合成数据的语义错误率是读者据数据管线提出的风险，不是独立测得的数字。
