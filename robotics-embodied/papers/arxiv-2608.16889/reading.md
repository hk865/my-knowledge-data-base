# BATON：技能记忆还要记住怎样把状态交给下一步

> 状态：技术精读 · arXiv v3 · 未复现

## 一句话

BATON 把冻结的 VLA（视觉—语言—动作模型：根据图像和指令产生机器人动作）交给通用大模型编排，分段探索长任务，并把“何时可以调用、下一步怎样接手、这一步应以哪种方式结束”保存为可检查的转换条件。[1，§3]

## 它要解决的问题

机器人打开抽屉、拿起罐子、把罐子放进微波炉，每一步单独练习都可能成功；串起来时，打开抽屉留下的手腕姿态可能妨碍下一次抓取，罐子的抓法也可能让夹爪过高、进不了微波炉。局部目标达成后留下什么状态，决定了剩余任务是否可行。

[具身 Agent 基线](../../fields/embodied-agents/BASELINES.md)把技能接口、反馈恢复与记忆分成可替换部件。[Harness VLA](../arxiv-2607.08448/reading.md)已经把接触操作包装成可重试的 VLA 工具：通用模型负责定位、接近和自由空间运动，冻结策略处理抓取等接触密集动作，执行经验写入外部记忆。BATON 沿用这个底座，把问题推进到**多个技能怎样经济地学会组合**。[1，§1–3；2]

原来的探索方式以整项任务首次成功为记忆写入点。长任务即使前几步已经解决，后面失败仍可能让这些成果无法成为独立可复用单元。另一个问题是，工具有停止条件，却缺少明确的入口检查和下游兼容约束：知道“已经抓住”并不等于知道“以这种抓法，接下来放得进去”。BATON 因而同时改探索单位和技能间接口。[1，§3.1]

## 核心想法

**把子任务和边界分别当作需要解决的对象。** 先探索短子任务，成功后保存抽象解法；再将相邻已验证单元接成更长的单元。组合失败时，优先调查新接缝，而保留已完成的局部成果。一个边界通过验证的标准是：后继确实从前驱留下的状态出发成功。[1，§3.2]

**把记忆从“过去怎么成功”扩展为“下一步需要我怎样成功”。** 转换记忆有三种：invocation 是子任务内部从解析控制切换到 VLA 的准备条件；handoff 是相邻子任务之间的入口条件；lookahead 是后续计划反过来约束当前执行方式的条件。前两者由 verifier（根据实时观察检查条件的验证角色）把关，第三种由 scheduler（结合剩余计划选择执行策略的调度角色）处理。[1，§3.3、图1]

增量集中在编排和外部记忆。模型权重保持固定，经验改变的是下次执行时读到的内容。尤其值得保留的是同一技能的多个成功策略：侧抓和顶抓都可能有效，调度器根据后续用途选择，而非把其中一个当作冲突记录删除。[1，§2–3]

## 机制

**从指令到动作。** 高层把任务写成子任务序列，再插入相邻子任务的边界。每个子任务内部先执行解析原语，如移动末端、转动手腕和操作夹爪，再调用 VLA_ACT(ℓ, φ)：ℓ 是局部指令，φ 是令该调用停止的条件。BATON 在两者之间加入 readiness condition（准备条件：当前场景是否适合让接触策略接手），用腕部相机检查，不满足就重新摆位。[1，式1–3]

入口与出口应分开理解。φ 回答“这次接触执行何时返回”；handoff 的 entry condition 回答“下一子任务可以从什么状态开始”；lookahead 的 execution constraint 回答“当前子任务应留下怎样的结果”。前一技能停止后，还需要观察世界并判断后两个条件。边界条件依赖前驱留下的状态和后继的需求，因此论文把它存于两者之间，而非只挂在某个技能名称上。[1，§3.3]

**一条交接链的手算，以下均为示例数值。** 任务是“开抽屉、取罐子、放入低矮空间”，数值仅解释机制，不是论文控制阈值或实验记录。

1. 开抽屉后，手腕相对下一次抓取所需姿态偏转 70°。边界要求偏差不超过 10°，则当前超差 60°。handoff 检查触发解析转腕；假设修正后剩余 5°，入口条件通过。这里修复的是上一步遗留的状态。
2. 调度器读到后面要放入净高 12 cm 的空间。两种抓法都能抬起罐子，但假设顶抓时物体与夹爪所需总高度为 15 cm，侧抓为 10 cm。顶抓余量为 12−15＝−3 cm，侧抓为 12−10＝2 cm，因此选择侧抓。lookahead 必须在抓取前发生，避免抓稳以后才发现无法放入。
3. 按侧抓策略接近后，假设腕部图像显示罐子中心距两指中心线 18 个像素，教学条件要求不超过 10 像素。invocation 暂缓 VLA 调用；重新摆位后偏差为 6 像素，才交给 VLA 抓取。像素阈值只是方便手算，原文用语言条件和视觉验证。
4. 达到抬起停止条件后，系统检查抓取结果和下一边界，再执行搬运与放置。若局部抓取成功、下游放置失败，新增经验应指出哪种抓法造成几何不兼容，让下次选择另一策略。

这三个检查解决不同时间位置的问题：handoff 修复已经继承的状态，invocation 检查即将发生的控制权切换，lookahead 提前改变尚未执行的策略。

**记忆何时读写。** 图2给出比“使用记忆”更具体的节奏：技能记忆在子任务前读、首次成功后写；invocation 条件随技能首次成功写入，每次 VLA 调用前读；handoff 在发现前驱干扰后继时写入，边界处读取；lookahead 在局部成功形式造成下游失败时写入，执行当前子任务前结合剩余计划读取；失败记忆每次失败后写、重试前读。正常直接拼接成功的边界无需额外记一份新技能。[1，图2、§3.2–3.3]

**为什么作者写 T^K 与 KT。** T 表示一个短子任务找到首次成功所需的平均尝试数，K 是阶段数。理解指数项的一组简化假设是：各阶段每次成功概率稳定且相互独立，均为 p＝1/T；整项尝试必须同时成功，而且失败后不复用已经解决的前缀。整链成功概率才是 p^K，首次完整成功的期望尝试数为 1/p^K＝T^K。[判断：这是把原文论证展开所需的概率模型。]

例如 T＝5、K＝4 时，整链概率为 (1/5)^4＝1/625，期望625次完整尝试；独立探索四个技能需4×5＝20次局部尝试。如果三个新边界也各需5次探索，总计是20＋3×5＝35次。更一般地，应分别记子任务代价 T_k 和边界代价 B_j，总探索量为 ΣT_k＋ΣB_j；当这些代价有统一上界且既有单元可直接复用时，才随 K 线性增长。[1，§3.1–3.2]

这里比较的是简化的探索尝试数。执行较长已验证单元、恢复起始状态、视觉验证和模型推理都继续产生费用，部署账本还应累计控制步、重置和 token 开销。（KT 不是论文证明过的端到端时间或资金复杂度。）

## 证据：哪个实验支撑哪个主张

**先固定协议。** RoboMemArena 是部分可观察厨房中的长程操作基准，26项任务按搬运、遮挡、计数、顺序分成4、11、7、4项，每项有3–9个验证阶段，平均轨迹超过千步。BATON 在一个参考场景种子上探索，在另外十个种子上评估；种子改变物体摆放。主要受控对照 Harness VLA 与 BATON 使用同一个冻结 π_RLinf 策略、SAM-3 分割器和 GPT-5.6-sol 编排模型，两者都继承在 LIBERO 获取的技能记忆，并各有每任务20个探索 episode 的预算。前者探索整项任务，后者把预算用于子任务转换。[1，§4.1]

TSR 是完成全部验证阶段的回合比例；CSR 先计算每个回合通过的阶段占比，再在回合间平均。比如两个示例回合分别通过3/3和3/6个阶段，则 TSR＝1/2＝50%，CSR＝(1＋0.5)/2＝75%，而非把阶段合并后得到6/9。论文的阶段验证数也应与 Agent 自己选择的子任务划分区分。[3，§3.4，式4–5]

| 主张 | 支撑实验 | 怎么读 |
|---|---|---|
| 新的组合与记忆机制优于直接扩展原运行时 | 表1：Harness VLA 的 TSR/CSR 为23.1/37.9，BATON 为63.5/82.9，单位均为% | 相同主要组件与参考探索预算下，完整系统提升40.4/45.0个百分点；这里同时改变探索组织和转换记忆 |
| 主表总体结果超过已有方法 | 表1：FrameSamp+Modul 为46.1/63.9，BATON 为63.5/82.9 | 提升17.4/19.0个百分点；其他方法并非统一组件重新训练的受控消融 |
| VLA 调用前的准备检查有贡献 | 表3：保留分层探索，去 invocation 后降至47.3/68.9 | TSR 下降16.2个百分点，支持调用入口的作用 |
| 继承状态的修复是关键环节 | 表3：去 handoff 后降至30.4/64.6 | TSR 下降33.1个百分点，是三个单项移除中最大降幅 |
| 为下游保留合适策略有贡献 | 表3：去 lookahead 后降至37.7/68.0 | TSR 下降25.8个百分点；该操作同时关闭调度器并只保存每技能的首个成功策略 |

摘要的37.7%与29.7%可由主表手算：17.4/46.1≈37.7%，19.0/63.9≈29.7%，属于相对提升。四个任务类别的大小不同，总体按任务数量加权，例如 BATON 的 TSR 约为 (4×75＋11×50＋7×64.3＋4×87.5)/26＝63.5%。（不能把摘要增幅写成百分点，也不能将四个类别简单平均。）[1，表1]

消融的任务分布也符合机制预期。遮挡类包含开关抽屉、微波炉等异质操作，去掉 handoff 时跌幅突出；顺序类本已较强，改进较小。图3的抽屉案例展示了三个介入点：抓把手前确认两指包围，下一次接近前恢复手腕，最初抓法为后续关抽屉留空间。[判断] 它们共同支持“接口失配是该设置的重要瓶颈”，其中消融比一条成功视频更能支持组件贡献。[1，§4.2–4.4]

真机使用 PiPER-X 六自由度机械臂，两个任务各20次：依次把两罐放盘子，及把一罐一瓶放盘子。BATON 平均 TSR 为47.5%，Harness VLA 为27.5%，即40次中分别成功19次与11次；CSR 为68.3%与52.5%。这支持方法可以落到物理执行，适用范围仍是这两个任务。[1，表2]

## 局限与后续

**成本论证还需要实际账本。** 论文主要实验证明的是已有相关技能条件下，固定探索 episode 预算内的成功率改善。下一步应在不同 K、不同边界难度上同时统计首次成功、控制步、重置次数、模型调用和总时间，并加入能保存成功前缀的整链基线。[判断] 这样才能区分收益来自更好的进度保存、入口验证，还是更多可用局部尝试。[1，§4.1–4.3]

**视觉条件的正确性成为新瓶颈。** 准备条件依赖腕部观察，局部成功还可能是偶然。后续需要测量验证器的误放行与误拒绝，并检验在物体遮挡、接触状态不可见和状态分布变化时，已验证单元是否需要重新验证。可与 [EmbodiedSkills](../embodiedskills/reading.md) 的前提、依赖与证据新鲜度检查对照：前者着重学到接缝条件，后者着重运行时管理调用所依赖的证据。[判断]

**多策略记忆需要覆盖与维护。** lookahead 能选择的策略来自已有探索；若后续约束需要未探索过的抓法，还需补充搜索。随着技能、对象和剩余计划增加，策略适用条件的维护与检索成本会增长。可把 [RoboSkill](../roboskill/reading.md) 保存实际代码与执行证据的办法作为对照，研究每条转换规则应附哪些证据、何时废弃，以及跨任务复用何时产生负迁移。[判断]

最值得迁移的设计是把失败日志落到明确边界：是接触策略本身不会做、调用时机不合适、前驱留下错误状态，还是选错了下游需要的成功形式。这样的诊断能让下一轮实验只改变有关部件。[判断]

## 批注

**易误读**

- 冻结指 BATON 使用时不更新权重，π_RLinf 本身已经训练；实验还继承 LIBERO 技能记忆并在目标任务参考种子上探索，不是零交互冷启动（§4.1）。
- 单阶段平均首次成功次数 T 本身不足以推出 T^K；概率稳定、独立或相应条件成功率、是否保留部分进度都会改变计算。边界探索成本也应计入 KT 的解释（§3.1–3.2）。
- 在一个状态上通过组合检验是经验性证据，不能证明所有后继状态都满足技能适用条件；语言契约也不等于形式化安全保证（§3.2–3.3）。
- 去 lookahead 同时改变策略库与调度器，因此表3不能分别给出“多存几个策略”和“读取剩余计划”的独立贡献（§4.3）。
- PrediMem＋GT memory 是特定系统使用真实历史信息的参考项，不能当成所有机器人系统的理论上界；BATON 超过它，不能推出“预测比任何完美记忆更强”（表1）。
- CSR 衡量部分进度；TSR低于CSR本身也会由多阶段相乘产生，不能只靠两者差距证明所有失败都在转换处。组件消融提供了更直接证据（§4.3）。

**与其他论文的关联**

- `[结构]` [Harness VLA](../arxiv-2607.08448/reading.md)提供固定解析原语、冻结接触策略和参考探索记忆；BATON在这个底座上增加分层组合与三类转换条件。两者最直接的增量关系是技能接口和探索组织，而非新的动作网络。[1–2]
- `[结构]` [RoboSkill](../roboskill/reading.md)保存文字、真实执行代码和证据，重点是减少下一次重复探索；BATON突出同一技能保留多种策略，并由剩余计划约束选择。两者可组合成“保存可检查经验、按下游条件使用”的设计，但没有联合实验支持其叠加收益。[判断]
- `[结构]` [EmbodiedSkills](../embodiedskills/reading.md)将前提和验证放进执行运行时；BATON将失败中发现的入口与兼容约束存进转换记忆。二者可对照“检查规则怎样执行”与“规则如何随探索积累”，不能因为都使用契约就视为同一方法。[判断]

**未核实 / 待验证**

- 未复现实验。v3没有附录，公开正文也未提供完整提示词、可运行记忆模式、逐任务探索轨迹和预算计账细节；已验证单元的复跑与重置怎样计入20个episode，需要实现材料进一步确认。
- 没有找到在 v3 原文明确链接的 BATON 官方代码或项目页，未凭相似名称认定仓库。验证器校准、分解策略、多策略候选上限及长期记忆维护仍缺可审核细节。
- 三张实验表未报告置信区间或多次独立探索构建记忆的方差；真机两任务不足以推断普遍部署可靠性。模型调用成本和延迟也没有独立消融。
