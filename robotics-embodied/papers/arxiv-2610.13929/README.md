# Chronos Policy: Learning Robot Policies on Physical Time

> 状态：文献卡 · 2026 · [原文](https://arxiv.org/abs/2610.13929v1)

- **解决什么**：传感器采样、观测送达与推理延迟变化时，同一个序列位置可能对应不同的新旧程度，策略需要知道观察发生于何时、动作准备在何时执行。
- **核心方法**：相对 [Diffusion Policy](../diffusion-policy/README.md) 的序列位置表示，把观测采集时间与动作查询时间用于 time-aware RoPE（旋转注意力的查询与键，让两者的物理时间差直接影响匹配），并随机化训练中的采样、送达与动作起点。
- **为什么在这个库里**：[VLA Baseline](../../fields/vla/BASELINES.md)“观测表示—推理调度”接口的时间信息问题。[判断] 最值得借鉴的是先判断旧数据能否被策略正确解释，再决定是否丢弃或重采样；可用同频率、同延迟设置下的消融检查。优先级：选读。

## 批注

**易误读**
- 仿真各策略都预测 20 Hz 的 16 步动作；DP 与 Chronos 同骨干，但完整方法同时改变时间表示和训练随机化，归因应看拆分消融。Conveyor 的 0–200 ms 延迟条件下，DP 与完整方法成功率为 1.8% 与 76.4%；联合扰动下完整方法仍仅 32.7%。出处：[附录 A、B，表 1–3](https://arxiv.org/html/2610.13929v1)。
- 平均鲁棒性提升不保证每个任务受益：Threading 联合扰动下，Chronos 为 63.3%，DP 为 77.3%。真机分数另含部分成功的半分，不能与仿真成功率混用。出处：[表 4 与附录 C](https://arxiv.org/html/2610.13929v1)。
- 动作时间是请求的执行时间；真机推理延迟由过去请求估计，过期动作丢弃。可变控制频率仍列为后续工作。出处：[§3.4、§5](https://arxiv.org/html/2610.13929v1)。

**与其他论文的关联**
- [Diffusion Policy](../diffusion-policy/README.md) 提供动作块生成基线；这里的增量集中在时间坐标与训练样本的时序分布。
- [RTC](../arxiv-2506.07339/README.md) 处理新旧动作块接续；本文真机对照将它移植到 DP 的 DDIM 采样器。[判断] 同样异步执行仍有收益，支持继续检验“队列连续”之外的观测时序问题；不能据此认定 Chronos 在所有平台替代 RTC。
