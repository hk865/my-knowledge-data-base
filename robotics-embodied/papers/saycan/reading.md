# SayCan 从语言建议到机器人能够执行的技能

> 状态：机制教学 · 原文 arXiv:2204.01691v2 · 未复现

如果对机器人说“帮我把桌子收拾好”，语言模型可以给出一串听起来合理的步骤。但房间里有没有垃圾桶？夹爪能不能拿起那只盘子？机器人是不是站得太远？这些问题无法仅靠句子的流畅程度回答。SayCan适合作为具身Agents的入门baseline，因为它把“这一步有没有用”和“这一步现在做不做得到”放到同一个选择过程中。[1][2]

例子中的数值全部是教学设定。你可以先理解技能选择，再读更复杂的记忆、规划与执行框架。

## 1 先定义机器人已经会什么

设想一个教学机器人只有三种技能：走近桌子、抓起杯子、放下物体。“技能”不是一句漂亮的话，而是一段能够调用的行为。每个技能有一个文字名字，也有真正控制机器人执行的程序或策略。

为什么要先有技能库？因为高层语言推理并不天然知道电机该如何转动。把问题拆开后，高层只需选择已有行为，低层负责把该行为完成。技能库也限制了高层的能力：如果机器人没有开门技能，语言模型再确信“先开门”很合理，也不能凭空让机器人拥有这种能力。

## 2 两个分数分别回答什么

第一个分数来自语言侧。给定目标和已经选择过的步骤，某个技能名称接在后面有多合适？本篇把这个分数写成L。它反映语言模型对下一步的排序信号（不是机器人现场成功概率的直接测量）。

第二个分数来自执行侧。给定当前状态，机器人执行某个技能可能成功到什么程度？本篇写成C。这里的状态可以包含技能模型需要的观察。机器人尚未接近桌子时，抓杯子的可行性应很低；已经站到杯子旁边时，这个值可能更高。

将两个分数相乘得到S，即S = L × C，然后选分数更高的技能，是论文核心选择机制的直观写法。[1] 它组合的是两个不同来源的判断。

## 3 亲手算一次选择

以下数字不是实验结果。假设机器人还在离桌子较远的位置。

| 候选技能 | 语言分数L | 可行性分数C | 组合分数S |
|---|---:|---:|---:|
| 走近桌子 | 0.4 | 0.9 | 0.36 |
| 抓起杯子 | 0.6 | 0.1 | 0.06 |

只看语言分数，会选“抓起杯子”；加入现场可行性以后，“走近桌子”得到更高分：当前更适合先走过去。

走近桌子之后，必须根据新状态重新评分。假设此时抓杯子的L为0.8、C为0.8，组合分数变成0.64。与之前相比，任务仍然是收拾桌子，但当前可行的步骤发生了变化。由此可以看到，计划随现场状态逐步重算。

为什么不用简单相加？如果某技能几乎不可执行，乘法能使它的组合分数明显降低。相加则可能让很高的语言分数抵消极低的可行性。

把S当作选择信号，和把S当作经过校准的整个任务成功概率，是不同的主张（语言分数0.8并不意味着现实中80%的此类任务会成功）。

## 4 可行性估计怎样和强化学习联系起来

先不用复杂符号。设一个短技能成功时奖励为1，失败为0。如果在相同条件下多次尝试，平均奖励就是成功比例。在不折扣、终止奖励符合这个定义等条件下，预期回报可以对应成功概率。

这解释了为什么价值函数可以用来提供技能可行性信息。[1] 价值函数利用任务经验估计执行结果。

## 5 训练和部署各在做什么

理解系统时，可以把时间分成准备和执行两个阶段。准备阶段，需要能执行的低层技能，以及用于评价技能是否可行的模型；语言模型提供已有语言知识。执行阶段，根据当前指令、历史步骤和环境状态反复给候选技能评分、执行选择，再继续下一步。

执行阶段语言模型的权重保持不变：系统先利用已有模型和已有技能，再在运行时组合它们。

## 6 实验要怎样读

官方项目报告的PaLM-SayCan规划成功率为84%、执行成功率为74%，测试包含101条任务指令。[2] 两个指标的差距说明，语义上合理的步骤序列，仍要经过低层技能逐个执行这一关。

可以用一个独立的教学计算理解长任务：假设每个技能成功概率都为0.9，并且错误彼此独立，连续五个技能全成功的概率是0.9的五次方，约0.59049。它说明，单技能看上去很可靠，也可能在长序列里累积明显失败风险。

## 7 局限与后续

第一，技能库没有覆盖的新任务怎么办？第二，执行以后怎样验证结果，而不是只相信原先的成功预测？第三，失败经历能不能转成以后可复用的知识？第四，环境改变以后，过去的事实何时失效？这些问题把阅读自然引向执行契约、闭环恢复、空间记忆和技能复用。

**论文自己写明的局限。** 结论部分列出三点：方法继承语言模型的局限与偏见，包括对训练数据的依赖；系统的主要瓶颈在底层技能的范围和能力；某个技能报告了高价值却执行失败时，系统不容易作出反应。[1] 结果部分的错误归因给出了比例：在101条指令的厨房评估中，PaLM-SayCan的错误有65%来自语言模型，35%来自可行性判断。[1] 也就是说，即便有了可行性评分，多数错误仍出在“选哪一步”上。

**闭环反馈由后续工作补上。** v2的§5.2写明，SayCan只在当前决策步通过价值函数获得环境反馈，技能失败或环境变化后，所需的反馈可能拿不到；同节指出 Huang 等的 Inner Monologue 在 SayCan 之上，用成功检测器、场景描述乃至人的反馈形成闭环规划。[1] 2026年的 [EmbodiedSkills](../embodiedskills/reading.md) 把这一步做成显式结构：高层选择只作为提案，运行时检查前提和依赖新鲜度，执行后再用新观测验证子目标；它的相关工作把 SayCan、Inner Monologue、Code as Policies 列为前作。

**技能范围瓶颈。** [判断] 自述的“技能范围”瓶颈，后来有两种修法。一种是让技能库自己生长：[RoboSkill](../roboskill/reading.md) 把执行过的代码、反馈记录整理成可复用技能，它在相关工作中把 [Voyager](../../../llm/papers/arxiv-2305.16291/README.md) 的技能库与 Code as Policies 列为前作。另一种是取消显式技能边界：[π0.5](../arxiv-2504.16054/README.md) 在同一个模型里训练语义子任务预测和低层动作，端到端地完成新家庭中的长程清理任务。依据是两篇原文的方法描述；代价是后者的可行性不再有一个单独可查的分数。

## 批注

**易误读**

- 版本：arXiv v1 发表于2022年4月4日，v2 发表于8月16日；官方记录说明 v2 加入 PaLM 结果及更多能力研究。两者是同一论文的修订，84%/74% 与 65%/35% 都按 v2 引用。[1][2]
- 84%/74% 来自101条厨房指令的测试，不能外推成任意家庭任务的成功率。
- S = L × C 是选择信号。乘法并不是普遍最优的证明：两个评分的校准、候选技能覆盖以及当前观察是否正确，都会影响选择；论文的概率分解有建模假设，不能仅凭乘法形式就认定它是现实真值（§3）。
- “期望回报 = 成功概率”只在成功为1、失败为0、无折扣时成立。奖励包含速度、能耗和姿态惩罚，或者使用折扣时，回报就不再是简单的0到1成功比例（§4）。
- 价值函数不是只检查句子语法的验证器；但它是用近似模型和有限数据训练的，一个新杯子的材质、一个未见过的障碍物，都可能让估计失准（§4）。
- 0.9 的五次方是假设错误彼此独立的教学计算；真实错误一般并不独立，它不是对 SayCan 实验的解释（§6）。
- 把语言模型接到机器人上，不意味着每次做任务都重新训练语言模型；后续研究增加微调或在线学习，是另外需要实验证明的机制（§5）。
- SayCan 不是机器人系统第一次分层，它的价值在于一种具体的衔接办法，而不是“分层控制从此诞生”；讨论历史时，应把传统任务分解这个更宽的思想，与论文实际实现的语言和可行性组合区分开（§1）。
- §3 表中的情形并不是说抓杯子不是最终要做的事，只是当前更适合先走过去。乘法组合也没有把两个大模型拼成一个新网络；示意图各框是教学分解，不对应论文的网络层数。

**与其他论文的关联**

- `[历史]` Inner Monologue 直接建立在 SayCan 之上，引入执行后的环境反馈；SayCan v2 §5.2 自己写明了这层继承。[EmbodiedSkills](../embodiedskills/reading.md) 把“选择 → 执行前检查 → 执行 → 验证 → 恢复”做成带契约的循环，相关工作同样以 SayCan 为起点。
- [RoboSkill](../roboskill/reading.md) 与 [Voyager](../../../llm/papers/arxiv-2305.16291/README.md) 让技能库随执行经验增长，对应 SayCan 自述的“技能范围”瓶颈。
- [MEMORA](../memora/reading.md) 的相关工作把 SayCan 作为“用语言模型、代码或技能库连接感知、推理与行动”的代表；MEMORA 补的是 SayCan 没有的跨经历记忆。
- [π0.5](../arxiv-2504.16054/README.md) 把“高层选子任务、低层出动作”放进同一个 VLA；与之对照，SayCan 的两层由不同模型承担，可行性评分可以单独检查。
- 本库路线图中的连接表示“解决相邻问题”；除非有明确引文，否则不表示作者师承或直接技术继承。后来的具身 Agent 系统不必都沿着 SayCan 的一条直接继承线发展。

**未核实 / 待验证**

- 本页核对了 v2 的方法部分、结论与局限、§5.2、错误归因、官方项目说明和版本记录；没有完整审计所有附录，也没有运行实验。
- 官方开放桌面仿真实现只核对了公开入口，没有安装运行。
