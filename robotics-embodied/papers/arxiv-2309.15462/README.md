# DTC: Deep Tracking Control

> 状态：文献卡 · 2024 · [原文](https://arxiv.org/abs/2309.15462)

[返回机器人与具身目录](../../README.md) · [原文与阅读记录](source.json)

- **解决什么**：模型方法（轨迹优化、MPC）能找出稀疏地形上的落脚点，但依赖完美状态估计、无遮挡、无打滑等假设，模型失配时会出错；纯强化学习在落脚点稀少的地形（缝隙、踏石、窄梁）上奖励稀疏，学不会，泛化也差（Introduction、Methods "Motivation"）。
- **核心方法**：训练时在 CPU 上并行运行轨迹优化器 TAMOLS，每次脚触地时重新求解，给出落脚点和触地时的关节角；强化学习策略只看这些落脚目标、相位、脚到目标连线上的高度扫描和本体感知，学习去"跟踪"它们（不看机身位姿参考，以降低对建图误差的敏感）；critic 拿特权信息。部署时优化器约 400 Hz、策略 50 Hz（Methods）。相对 [Miki 2022](../arxiv-2201.08117/README.md) 的纯 RL 策略，0.1 m 缝隙上后腿不再掉进去（10 次全成功）；相对纯模型控制器，在打滑、软地、塌陷和感知看不见的缝隙上不摔（图 4–5）。作者自述：训练环境并不比统一的 RL 方法更省样本（ANYmal 4096 台并行训练 14 天），步态固定为对角小跑，建图漂移超过 0.1 m 后崎岖地形成功率线性下降（Discussion、图 7C）。
- **为什么在这个库里**：[运动控制方向](../../fields/control-locomotion/README.md)中模型控制与学习控制两条路线合流的节点；Baseline 表"规划与执行的分工"一格的代表，回答了"MPC 和 RL 各自坏在哪里、怎样各取所长"。优先级：必读。
