# VoxPoser：语言怎样转成可优化的三维目标

论文卡（本地来源，未发布） · [官方原文](https://arxiv.org/abs/2307.05973v2) · [官方 PDF](https://arxiv.org/pdf/2307.05973v2)

## 从语言到可以优化的空间目标

VoxPoser 面对的难点是：语言说“靠近把手，同时避开花瓶”，怎样变成运动规划器能计算的目标？模型生成程序，调用视觉模块定位对象，将目标和避让要求写成三维体素价值图。随后由规划器找轨迹，而非由 LLM 逐步猜关节角。（§3.1–3.2）

## 以打开抽屉为例

输入含指令与 RGB-D。高层分解出抓住把手和拉开等阶段；视觉链用开放词汇检测、分割和跟踪得到对象/部件点云。代码在把手附近赋较高吸引值，在需避让对象附近编码约束，并为末端朝向、夹爪与速度生成相应图。运动规划器结合机器人模型生成末端轨迹，控制器执行第一段，然后重新读取视觉状态。

论文实现中，一类价值图为 `100×100×100` 的体素数组，位置吸引/避让参与轨迹代价，其他图参数化姿态、速度和夹爪。这里的 value map 是空间场，不是 SayCan 对整项技能成功率的价值函数。把两者都称为“价值”容易掩盖接口差异。

## 闭环在哪里，学习在哪里

同一子任务内缓存生成的代码，利用新视觉重新计算地图并进行 MPC，论文给出的重规划频率约为 5 Hz；并不是每个控制周期都重新请求 LLM。主要零样例路线无需额外训练大模型。另一个接触任务支线利用在线交互学习动力学，不能把这个支线也写成完全没有学习成本。（§3.3–3.4、§4）

实验包括真实 Franka 操作和 RLBench 仿真。其结果支持用视觉对齐的空间表示组织动作，但依赖目标/部件正确识别、深度与标定、可用规划器和动力学假设。细小部件、遮挡、复杂接触与全臂约束仍是瓶颈。这里没有引用不同平台混合后的总成功率。

## 与当前方向如何相接

VoxPoser 和 ReKep 都把语言理解与几何执行分开：前者生成稠密空间图，后者生成稀疏关键点关系。对 RPent，最直接的启发是将“目标坐标来自哪一帧、哪个像素、哪个坐标系”记录清楚，再研究准备动作是否改善后续 VLA 输入。单独加入分割器并不能保证空间推理或闭环恢复变好。

可先借鉴坐标和观测新鲜度的审计方式；全面接入三维价值图需要额外感知与规划栈，不是当前文献整理自动授权的实现事项。
