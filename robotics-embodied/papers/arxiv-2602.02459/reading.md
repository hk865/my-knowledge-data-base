# TIC-VLA：让控制器知道语义推理已经过时多久

> 状态：技术精读 · v1 · 未复现

## 一句话

TIC-VLA 把慢速视觉语言推理的时间戳、延迟和期间的机器人运动一起交给快速控制器，并在训练时制造同样的延迟，使机器人能够一边使用旧语义，一边根据当前画面继续导航。

## 它要解决的问题

一台机器人收到“沿走廊前进，在拐角左转”的指令。视觉语言模型开始看图和推理时，前方行人还在道路左侧；等推理完成，机器人已经前进，行人也可能进入通道。推理内容即使在生成时正确，直接把它当作当前场景的描述，也会让动作建立在错误的时间关系上。

[NaVILA](../arxiv-2412.04453/README.md) 把语言导航和底层运动执行分开，[DualVLN](../arxiv-2512.08186/README.md) 进一步采用慢速语义、快速动作的双系统。TIC-VLA 针对的是这条路线上的一个具体问题：分开执行解决了“控制必须等推理”的阻塞，却仍然需要告诉控制器，正在使用的语义对应哪一时刻、机器人此后移动了多少。

这里的 VLA（视觉语言动作模型，即结合图像、语言指令产生机器人动作的模型）同时面对两种变化：机器人自身的坐标系在移动，场景里的人也在移动。机器人可以用运动估计解释前一种变化，用当前视觉感知应对后一种变化。论文把这两种信息同时保留在控制输入中，而把慢速模型主要用于理解指令、辨认关键对象和判断任务进度。[1，§1–3]

## 核心想法

核心增量是“带时间信息的语义接口＋匹配部署时序的训练”。

慢速模块保留最近一次完成的推理表示；快速模块每次读入当前图像、当前速度、旧语义、语义年龄和累计位姿变化，预测短期运动。这样，旧语义提供“现在要去哪里、哪一步已完成”的上下文，当前图像提供“眼前能不能走”的反馈。训练时也要让动作模块看到过时的语义，才能学会两者如何配合。

论文使用 InternVL3-1B（把视觉编码器与小型语言模型组合起来的视觉语言底座）和一个交叉注意力动作头。交叉注意力在这里让动作查询从当前视觉、旧语义和状态信息中读取所需内容。语义接口和延迟训练是主要消融直接检验的设计，动作头层数则用于检查容量选择。[1，§3.2、表2、表13]

## 机制

### 1. 语义缓存保存内容，也保存生成锚点

慢速模型读取语言指令、历史运动上下文，以及相隔数秒的图像序列，生成场景推理和远期航点。快速模块使用其最后一层的 KV cache（Transformer 推理时保存的注意力键值表示，可作为语言和视觉上下文的连续特征），从而获得比几个航点坐标更丰富的语义输入。

设当前时刻为 t，所用语义对应 t−Δt，论文的动作接口写成：

aₜ = πθ(Sₜ₋Δt, xₜ, sₜ, Δt, Δpₜ)。

S 是延迟语义，x 是当前图像，s 是平面线速度和偏航角速度，Δp=(Δx,Δy,Δθ) 是从旧语义锚点到当前的运动。有效延迟 Δt 包括一次推理耗时，以及这份结果完成后继续被复用的时间。因此，一次推理用了三秒，结果随后又使用两秒，控制器拿到的是五秒前的语义。

接口的时间锚点是输入图像对应的时刻，位姿锚点也是那一时刻的机器人状态；两个锚点共同说明这份语义在哪里、何时产生。每次后台推理完成，系统更新缓存和对应的时间、位姿锚点；下一次推理运行期间，动作模块继续使用上一次结果。首次语义尚未准备好时，论文的闭环算法让机器人保持零速度，之后进入连续异步控制。[1，式1–2、附录算法3–4]

### 2. 运动补偿让“旧的前方”有当前含义

**示例数值：**旧坐标系里，一个航点在机器人前方4米。推理期间机器人向前走了1.5米，并左转90°。把旧航点换到当前坐标系，先减去平移，再反向旋转：

p当前 = R(−90°) · ((4,0)−(1.5,0)) = (0,−2.5) 米。

这个航点现在在机器人右侧2.5米。运动偏移把延迟的时间长度，补充成当前坐标系里的方向和距离。

航点接口可以直接进行这类坐标变换；使用语义缓存时，动作网络读取运动偏移，学习结合当前画面重新解释旧语义。语义缓存携带连续上下文，动作网络通过这些条件输入实现补偿。当前视觉则提供推理期间新出现行人的观测。[1，§3.2、附录B]

[判断] 这些信息在接口中承担不同作用：指令决定任务目标，语义缓存保留路线与场景解释，当前图像支持局部避障，运动状态连接前后坐标系，时间年龄提示语义陈旧程度。把它们分别记录，也便于诊断失败来自错误理解、定位偏差还是推理延迟，并与最终成功率相互补充。

### 3. 快速动作通过滚动规划持续更新

按论文描述，动作头以共享视觉编码器的当前特征为输入，将视觉、旧语义与低维状态投影到共同空间，通过动作查询输出未来三秒的相对运动增量，再累积为短轨迹。控制器从轨迹选取近处目标，转换为线速度和转向速度。

默认三秒轨迹离散成30步；仿真中动作策略每0.1秒重新规划，仿真每秒推进30帧。因此，“预测三秒”表示规划视野，机器人仍在不断根据新画面改动作。作者选择三秒，是因为更短的预测视野牺牲了任务进展，更长的预测视野影响近端动作质量；这项比较在未进行强化学习的模型上完成。[1，表5、附录A、D]

### 4. 三阶段训练把异步部署搬到训练里

第一阶段微调语言模型。数据来自 SCAND、GND 的真实导航记录和 DynaNav 的遥操作轨迹。作者把连续记录切成短片段，用 GPT-5 结合图像、轨迹和未来信息生成指令、推理说明及航点监督，再训练模型从可用上下文预测这些目标。未来信息用于构造训练标签；部署时输入的是机器人已经获得的观测。[1，附录B、图7–8]

第二阶段训练动作头，冻结语言与视觉底座，在零到十秒之间抽样语义延迟。当前视觉和专家未来轨迹保持对齐，语义则来自过去时刻，并附上相应的延迟、位移。损失比较预测轨迹和专家轨迹。这里一个隐藏的关键是：离线动作训练使用标注推理提供语义上下文，闭环部署则使用模型自己生成的语义，两者存在分布差异。[1，算法1]

第三阶段在动态行人的仿真环境中进行强化学习（RL），用 PPO（通过在线试错提高预期回报的策略优化算法）微调动作模块。奖励包括到达目标、取得进展、碰撞惩罚与速度约束；随机延迟继续保留，平均约五秒。附录说明实际只更新动作头最后一个交叉注意力层和解码器。价值网络训练时可以看到目标位置，部署的动作策略仍使用语言、图像和机器人状态。[1，式5、算法2、附录D]

### 5. DynaNav 提供动态物理闭环的测试条件

DynaNav 是这篇论文同时提出的仿真套件：用 Isaac Sim 渲染医院、办公室、仓库和室外场景，加入动态行人，执行机器人速度控制；另用 Isaac Lab 支持在线强化学习。基准包含85个回合，改变人群密度、语言任务、起终点和超时条件。

平台层面支持轮式 Nova Carter 和四足 Spot；论文真机实验使用四足 Unitree Go2。当前公开完整基准配置的85个回合全部选择 Nova Carter，Spot 另有行为实现。复用资产时，机体支持范围与这组具体配置应分别记录。[1，§3.4、附录C；2，完整配置及机器人分支]

## 证据：哪个实验支撑哪个主张

仿真主结果在相同85个回合上比较。语言导航基线包括视频动作模型 Uni-NaVid、分层执行的 NaVILA、双系统 DualVLN、多模态指令模型 OmniVLA 和推理增强的 MobileVLA-R1，均经过相同训练数据微调；BC、普通RL、NavDP 则直接获得点目标，是任务难度参照。成功率 SR 衡量是否进入目标容差，SPL 进一步惩罚绕路，碰撞率 CR 单独统计发生过碰撞的回合比例。（SR 不是“无碰撞成功率”，目标阈值还要按逐回合配置读取。）

| 主张 | 支撑实验 | 怎么读 |
|---|---|---|
| 允许持续反应优于阻塞推理 | 表1：同步变体 SR 32.94%，完整模型55.29% | 同步变体会停下推理、再执行一小段动作，比较的是完整闭环调度方式 |
| 延迟条件化是关键部件 | 表2：未RL的 KV 接口无延迟建模 SR 30.59%，加入后47.06%；延迟航点接口22.35% | 连续语义和延迟训练结合最有效；这里没有把延迟输入与延迟训练分别隔离 |
| 在线适应改善部署分布 | 表1：无RL SR 47.06%、CR 34.12%；完整模型55.29%、28.24% | 任务完成与碰撞指标一起改善，支持在线闭环学习的价值 |
| 结果优于主要语言基线 | 表1：MobileVLA SR 32.94%、CR 45.88%，完整模型55.29%、28.24% | 点目标 NavDP 的 SPL 52.62%仍高于本方法50.29%，不同指标有取舍 |
| 能承受真实推理开销 | 表3：4060上的 Go2 成功17/20，动作/推理延迟85.73/3430.73毫秒；Orin NX 成功15/20 | 支持小规模机载部署；Orin动作耗时120.27毫秒，与仿真10Hz为不同口径 |

运动偏移本身也有贡献：未RL模型去掉它，SR 从47.06%下降到41.18%（表6）。这项消融最直接对应“机器人动了，旧语义怎样理解”。图5显示RL在所测延迟下总体更稳，但最低延迟条件会暂停仿真等待推理，读图时应区分模拟时间和真实墙钟时间。

作者还比较了测试时生成推理与只提取视觉语言特征的版本。后者语义模块更新更快，却更难完成任务，说明“降低语义延迟”和“保留有效任务推理”需要共同权衡。更低CR同时伴随更低任务活动和成功率，也说明安全指标应与进展一起解读。[1，§4.4、表4]

## 局限与后续

证据最强的结论是：在这组连续物理导航任务中，显式建模语义时间关系，比把旧语义当新语义更有效。DynaNav 的训练采集与测试共享四类环境，在线强化学习使用其中三类的新任务；它主要支持同环境任务变化和小规模真实迁移的结论。真机每项任务只有五次试验，后续需要更大规模、不同人群行为与不同里程计误差的验证。

延迟建模和延迟训练在主要消融里一起变化，还需要进一步分开验证“输入时间信息”和“接触延迟数据”各自的作用。旧语义已经误解任务、行人突然改变意图、运动估计出现结构性错误时，也需要独立统计失败模式。

[NavVerse](../arxiv-2607.19695/README.md) 对物理属性和机体执行提出更系统的评估，可以补充这里以动态行人为重点的测试。[判断] 对实际系统更值得迁移的是语义结果携带采样时间、参考位姿和状态年龄的接口，以及按真实延迟训练动作模块的方法；更换机体或导航任务后，仍需重新标定控制与评分条件。

## 批注

**易误读**

- DynaNav 是本篇的仿真套件，TIC-VLA 是模型；它们不提供 ORB-SLAM3 式建图、回环和重定位系统。真机硬件图出现深度相机、LiDAR，也不能推成动作网络使用了这些观测。[1，§3、图6]
- 仿真默认动作10Hz、推理约0.5Hz；真机表3报告的是分模块耗时，不能把它们称作所有硬件上的闭环固定频率。动作视野与执行周期也是两个量。[1，§4.2、表3]
- 主文把成功阈值概括为1.5米，附录C说明户外放宽；当前85回合配置中75条为1.5米，户外其余条目有1、2、4米。论文附录D的人距碰撞阈值为0.5米，当前评分源码为0.2米，物理接触另要求至少10N持续100帧。比较CR前应先固定评分器。[1，附录C–D；2，配置；3，L125–132、L649–702、L1250–1295]
- 原文描述三维增量动作、位移含Δθ、六层动作头；当前公开模型直接输出二维相对航点，状态用速度、偏航角速度、Δx、Δy和延迟，默认训练配置为三层；缓存读取也具体取最后一层的 value 表示。论文机制与当前实现应分别引用。[1，附录A；4，L90–209、L472–484；5]
- 官方代码和训练/RL入口、USD资产、HF数据包及模型权重已公开，但公开不等于已复现。数据卡声称权重用于论文，尚未逐张量核对它与每项论文实验配置的对应关系。[2、6]
- GitHub 代码采用限制学术/非营利用途、禁止再转发的 Academic Software License；HF 数据卡标 CC-BY-4.0。第三方场景与数据还应分别遵守原许可，不能统称商业可自由使用。[7、6]

**与其他论文的关联**

- [NaVILA 文献卡](../arxiv-2412.04453/README.md)：同样把高层语言导航与机体执行分开。TIC-VLA 的增量集中在旧语义与当前控制的时序关系；可对照[官方论文](../arxiv-2412.04453/README.md)理解两层接口。
- [DualVLN 文献卡](../arxiv-2512.08186/README.md)：慢速理解、快速运动已经是既有路线。TIC-VLA 用语义年龄和延迟训练进一步约束该接口；可对照[官方论文](../arxiv-2512.08186/README.md)区分异步架构与延迟条件化。
- [NavVerse](../arxiv-2607.19695/README.md)：前者突出动态人群中的语义延迟，后者突出物理执行条件；两个基准测量的能力不同，成功率不适合横向直接排名。

**未核实 / 待验证**

- 尚未运行 Isaac Sim、下载全量数百GB训练包或加载权重；发布状态依据官方文件清单、数据卡与源码，运行正确性及依赖完整性仍待独立验证。
- 当前公开代码与论文动作维度、层数、评分阈值有明确差异；需要论文实验快照或作者说明才能逐项对齐。离线数据加载器还用 t+0.1秒轨迹差分估计“当前速度”，部署则需要测量速度，需检查这种输入差异的影响。[8，L204–247]
- 固定随机种子的85回合与20次真机试验未给出跨种子置信区间；不据此推定高密度人群中的安全保证。图5的数值点未从图片估读。
