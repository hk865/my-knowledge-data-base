# 3D-Mem：把共视图像保存为可检索、可继续探索的三维场景记忆

> 状态：技术精读 · CVPR 2025 正式版及补充材料 · 未复现

## 一句话

3D-Mem 用少量覆盖已见对象的整帧图像保存空间证据，再把朝向未探索区域的图像放进同一个决策接口，让视觉语言模型选择“利用记忆回答”还是“继续走过去看”。

## 它要解决的问题

机器人走过客厅后，被问到“扶手椅前是否还有地方放茶几”，需要的证据同时包括椅子的朝向、前方空地和周围布局。对象名称与包围盒容易定位椅子；一张保留背景的图像则把这些细节一起交给视觉语言模型。视觉语言模型（VLM）是在同一输入中理解图像与语言的模型，本文主要使用 GPT-4o。

[ConceptGraphs](../arxiv-2309.16650/README.md) 已能把多视角观测合并成三维对象，再生成对象描述和关系。3D-Mem 关注的缺口是：任务出现之后，怎样让模型直接重新查看对象所在区域的视觉证据，而不是主要依赖预先提炼的文字或单个对象裁剪？另一个缺口是主动探索：已有地图可以回答“看见过什么”，机器人还需要判断“哪个方向值得继续看”。[1，§1–3]

直接保存并输入全部历史帧又会产生冗余。沿走廊连续拍摄的图像大多重复，相机刚好转向桌面的一帧却可能决定答案。3D-Mem 因此把问题拆成三步：按对象覆盖组织图像，用问题筛选有关记忆，再把记忆与探索候选一起交给 VLM。

## 核心想法

相对对象中心表示，增量集中在**任务模型消费的证据单位**：Memory Snapshot（记忆快照）把一组同时可见的对象和整帧图像绑定，物体之间的布局及背景仍保留在图像中；Frontier Snapshot（前沿快照）把尚待探索的区域、可导航位置和朝向该区域的图像绑定。二者共同成为 VLM 可以选择的候选项。

这里的“三维”来自带相机位姿的 RGB-D 输入、跨视角对象关联以及对象与导航目标的三维位置。RGB-D 指彩色图像附带逐像素深度，位姿指相机在地图中的位置与朝向。送入 VLM 的主要证据仍是二维图像，几何结构负责把这些证据接回同一个空间。[1，§3]

关键设计还有两项：只重新聚类本次观测影响到的快照，降低在线更新成本；先用对象类别筛选相关快照，减少每次决策要读取的图像数量。它们共同把“保存历史”变成了可以重复用于后续目标的查询接口。

## 机制

### 1. 从 RGB-D 观测得到对象与候选帧

系统沿用 ConceptGraphs 的对象处理思路：检测、分割图像中的物体，用深度和位姿转到地图坐标，依据几何与视觉相似度匹配、合并跨帧观测。每个对象保存类别、置信度与三维位置；候选帧保存原始观测和这一帧检测到的对象集合。[1，§3.1.1]

默认每个探索步骤采集三个相隔 60° 的视角。图像先以较高分辨率做检测，再缩小到 360×360 供 VLM 使用。检测模型为 YOLOv8x-World，实际实验采用 ScanNet 的 200 类词表，并只纳入距离机器人 3.5 米内的对象，使一张快照主要代表局部区域。[2，§10、§13.1]

记候选帧为 \(I_i=\langle I_i^{obs},O_{I_i}\rangle\)，其中 \(O_{I_i}\) 是该帧可见的已关联对象。一个记忆快照为

\[
S_k=\langle O_{S_k},I_{S_k}\rangle,\qquad O_{S_k}\subseteq O_{I_{S_k}}.
\]

快照负责的对象集合需要满足

\[
\bigcup_k O_{S_k}=O,\qquad O_{S_i}\cap O_{S_j}=\varnothing\;(i\ne j).
\]

这让每个对象都有唯一的快照归属，同时允许它出现在其他快照的画面里。对象集合决定索引与检索；图像保留的内容可以比索引更丰富。

### 2. 共视聚类：让每一组对象都有一张真实图像作证

Co-Visibility Clustering（共视聚类）寻找能够被同一候选帧完整覆盖的对象组。算法从全体对象开始：取最大的待处理组，寻找包含该组全部对象的帧；找到后，优先选检测到对象最多的帧，数量相同时按检测置信度和排序；找不到就根据对象水平面位置，用二分 K-Means 将该组拆成两组。K-Means 是按点到簇中心的距离组织相近点的聚类方法。最后，使用同一图像的组再合并。[1，Algorithm 1]

**示例数值。** 五个对象的水平坐标分别为 A=(0,0)、B=(1,0)、C=(0.5,1)、D=(7,0)、E=(8,0)。四张候选帧看到的对象为：第一张 ABC，第二张 BC，第三张 CDE，第四张 ABC；第一、第四张对 ABC 的检测置信度和分别为 2.7 与 2.4。

没有任何一帧覆盖 ABCDE。二分聚类把它们分为 ABC 与 DE：两个簇中心分别为 (0.5,1/3) 和 (7.5,0)，各点离本簇中心明显更近。ABC 可由第一或第四张覆盖，两者对象数相同，因此选置信度和较高的第一张；DE 由第三张覆盖。最终四张候选帧压成两张快照，每个对象都有归属，C 仍同时出现在两张画面中。这个例子展示的是算法操作，并非论文实验数据。

这一步保留了“对象和背景在同一视角下是什么关系”。例如，C 即使被索引到客厅快照，也可能出现在卧室方向的快照边缘，帮助 VLM 判断房间连接和相对位置。

### 3. 增量更新：修改受新观测影响的对象组

设本次观测的对象集合为 \(O^{new}\)，先找出旧记忆中与它相交的快照：

\[
S_{prev}=\{S\in S_{t-1}:O_S\cap O^{new}\ne\varnothing\},
\quad O_{input}=O^{new}\cup\bigcup_{S\in S_{prev}}O_S.
\]

随后使用累计候选帧 \(I_t\) 重新聚类这些对象：

\[
S_t=(S_{t-1}\setminus S_{prev})\cup Cluster(O_{input},I_t).
\]

例如旧快照分别负责 ABC 与 DE，本次重新看见 B 并发现 F，则重新处理 ABCF，DE 所属快照保持不变。这样，新视角可以替换旧代表图，新对象可以加入合适的局部组，又保留未受影响的记忆。[1，§3.2.2]

官方代码 `Scene.update_snapshots` 对应这一过程：扩大待更新对象集合、移除相交的旧快照、重新聚类，并检查对象覆盖和唯一归属。帧候选和对象地图则继续积累。[3]

### 4. 检索：先选类别，再把整张图交给模型

Prefiltering（预筛选）先把问题和已经观察到的对象类别列表交给模型，让它按可能有用的程度排序，保留前 K 个类别。随后保留至少包含其中一个类别的快照：

\[
S(q)=\{S\in S_t: categories(O_S)\cap C_K(q)\ne\varnothing\}.
\]

K 限制的是类别数；最终图像数由类别分布决定。筛选后的快照图像、相关类别标签、前沿图像和当前视图共同进入下一次决策。[1，§3.2.3；2，§15]

假设问题是“电视右边是什么”，检索选中电视类别，一张含电视的快照便会被送入 VLM。即便右边的时钟没有被检测器识别，它仍可能留在整帧中，模型可以直接看见。论文失败分析展示了这种偶然保留证据带来的补救，也展示了关键对象完全没有进入可检索快照时的失败。[2，§8，Fig.9–10]

因此，视觉证据与类别索引承担不同职责：类别负责把相关区域召回，图像负责提供尚未写进标签的细节。检索在早期丢掉整个区域之后，后续视觉推理就失去了这部分证据。

### 5. 探索前沿：把“去哪里看”变成可读图的选择

系统维护占据地图，即记录空间是否被障碍占据、能否行走的网格；再在可行走区域中区分沿途已经探索的部分和有待探索的部分。Frontier Snapshot 记为

\[
F=\langle r,p,I^{obs}\rangle,
\]

其中 \(r\) 是待探索区域，\(p\) 是通向它的可导航位置，\(I^{obs}\) 是机器人朝该区域拍摄的图像。图像提供走廊、门口等可见线索，帮助判断哪里可能通往目标。区域变化时更新前沿及其图像，完全探索后移除。[1，§3.2.1–2；2，§9]

在问答任务中，VLM 返回某个快照及答案，或者某个前沿及继续探索的理由。导航任务在快照后额外附上对象裁剪，要求模型选择具体对象，再把该对象的位置交给路径规划器。默认向目标移动一段后就重新观察和决策；这让机器人能在途中纠正方向，也可能造成前沿之间来回切换。[1，§3.3；2，§7.2、§11]

## 证据：哪个实验支撑哪个主张

OpenEQA 包含主动问答 A-EQA，以及给定历史观测、无需探索的 EM-EQA。LLM-Match 是由 GPT-4 对答案与参考答案的匹配程度评分，再映射到百分制；LLM-Match SPL 进一步按探索路径长度加权。GOAT-Bench 则要求在同一场景中依次完成类别、语言或图像描述的对象导航，报告成功率与 SPL，即按路径效率加权的成功率。

| 主张 | 支撑实验 | 怎么读 |
|---|---|---|
| 共视整帧比同管线的对象裁剪更适合主动问答 | 正式版 Table 1，184 题子集：3D-Mem 的 LLM-Match/SPL 为 52.6/42.0；CG + Frontier Snapshots 为 47.2/33.3 | 这是共享探索框架、预筛选与 VLM 的较直接对照，支持记忆输入格式的价值 |
| 保留图像背景尤其帮助空间问题 | 补充 Table 4，同子集空间理解：3D-Mem 为 43.4/33.3，CG 对照为 32.9/18.7 | 空间类别有增益；属性识别等类别未全面领先 |
| 选择信息帧优于均匀抽帧 | 正式版 Table 2，EM-EQA：平均 3.1 帧的 3D-Mem 得 57.2；平均 3.0 帧的 Multi-Frame 得 48.1 | 两个图像方法都使用 GPT-4o，这更接近相同图像预算下的信息组织比较 |
| 跨目标保留记忆有收益 | 正式版 Table 3，GOAT 的 278 个子任务：保留记忆为 69.1%/48.9；每个子任务后清空为 58.6%/38.5 | 支持同场景连续任务中的经验复用，尤其是行走效率 |
| 看前沿图像有助于探索选择 | 补充 Table 7，A-EQA：改为总选最近前沿后，52.6/42.0 降至 49.3/31.0 | 对照同时改变了前沿选择策略，收益来自视觉引导的探索决策整体 |
| 输入压缩确实减少每次要看的图像 | §4.1、§4.3：A-EQA 平均 39.76 个候选帧形成 10.94 张快照，筛后 3.26 张；GOAT 为 91.37→16.58→4.66 | 衡量快照与查询输入的紧凑性，完整运行内存还包括对象、候选帧和占据地图 |
| 子集分数需要和全集分开引用 | 补充 §6：GOAT 全集为 62.9%/44.7，子集为 69.1%/48.9；A-EQA 全集为 53.3/38.0，子集为 52.6/42.0 | 全集结果只有本方法，无法据此重建所有基线的全集排名 |

最值得保留的证据链是“共享框架下更换记忆输入”“相近帧数下比较抽帧”“每个目标后清空记忆”。它们分别检验视觉证据格式、信息选择与跨目标复用，解释力度比把所有排行榜数字并排更强。

评测还有一个关键工程条件：实验采用 Habitat-sim 路径规划器，补充材料明确它利用全局导航网格的先验计算最短路径。导航网格是仿真环境提供的可行走区域几何。3D-Mem 主要决定去哪个目标，底层寻路与行走由这套能力支撑。（因此，与采用学习型低层控制器的 GOAT 原始基线比较时，差距包含导航栈差异。）[1，§3.3；2，§11]

## 局限与后续

**时间变化仍需要单独建模。** 作者在补充 §7.3 明确把方法定位于静态环境，对移动对象缺乏鲁棒性。当前更新累积观测、重组快照，适合逐渐看全一个场景；持续移动后的身份、旧状态失效以及物体消失后的证据撤销，需要额外的时间与可见性机制。

**空间判断依赖证据质量和 VLM 能力。** 小目标在缩小后的图像中可能难以辨认，错误检测标签会污染索引，位姿漂移会影响对象合并。图片保留了方向、遮挡和空地线索，但把这些线索变成可安全执行的距离或容纳判断，还需要几何验证。GOAT 的图像目标模态中，本方法成功率略高于 CG 对照，路径效率却更低，作者将其与跨视角匹配困难联系起来。[2，§7–8]

**长时运行需要处理存储和失效。** 局部重聚类降低更新工作量，预筛选降低单次 VLM 输入量，累计候选帧仍随探索增长。后续系统适合分别设计证据保留、过期清理与检索召回，并测量错误召回怎样影响任务成功，而不只统计最终提示中的图像数。

**地图与动作接口限制部署范围。** 本文前沿实现按固定高度的可行走平面组织空间，跨楼层探索受到限制；精确位姿与理想路径规划也需要在真实机器人上落实。可迁移的设计是“对象索引组织原始证据，再由查询决定读哪些证据”；实际部署还要把定位、运动、安全与记忆有效性接上。

## 批注

**易误读**

- 共视聚类追求紧凑覆盖，但 Algorithm 1 是二分聚类启发式，原文没有证明输出全局最少的快照数；对象唯一归属也不表示它只在一张图片中可见。[1，§3.1]
- Frontier Snapshot 是从当前可达观察位置朝待探索区域取得的可见画面，不是生成未知区域的真实内部图像；“探索更新”不等于跟踪动态物体。[1，§3.2；2，§7.3]
- A-EQA 主表的重跑方法与 Multi-Frame 用 184 题；多项从 OpenEQA 引用的分数用完整 557 题。GOAT 主表用 Val Unseen 中每个场景一个 episode，共 36 场景、278 子任务。[1，§4.1、§4.3]
- A-EQA 探索失败时仍让 GPT-4o 在无图像条件下猜答案，但 SPL 置零；仅看 LLM-Match 会混入语言先验答对的情况。[1，§4.1]
- Explore-EQA 的 GOAT 改编版还允许最终图像可见目标作为额外成功条件；LLaVA-7B 结果来自额外微调，不能当作未训练模型的零样本成绩。[1，§4.3；2，§12]
- “扶手椅前放茶几”是动机示例，本文没有给出家具尺寸约束下的放置可行性专项评测；空间关系主要由图像交给 VLM 推断，不能转述为已建立完备的显式关系图。
- 官方代码的帧选择会优先复用本轮已经选中的合格帧，这是主文伪代码以外的实现细节。当前默认 A-EQA 配置指向 41 题快速子集；GOAT 最大步数还按场景面积调整，直接运行默认配置不等于复现主表协议。[3，`select_frame`；4–5]

**与其他论文的关联**

- [ConceptGraphs](../arxiv-2309.16650/README.md) 提供对象关联与几何索引。它本身保存多视角观测并汇总对象描述；3D-Mem 的具体改变，是把共视整帧直接保留为任务时的图像输入。本文 CG 对照采用对象裁剪替换快照，不能把这个对照概括成原始 ConceptGraphs 全部实现的能力边界。[1，§3.1、§4.1]
- [Explore-EQA](https://arxiv.org/abs/2403.15941) 提供基于前沿的探索框架。3D-Mem 将朝向前沿的图像与已有快照并列供 VLM 选择，并保存跨目标记忆；最近前沿消融说明探索接口也是收益来源。[1，§3.2；2，§13.2]
- [OpenEQA](https://github.com/facebookresearch/open-eqa) 的主动与给定历史两种任务，让同一表示可以分别检验“会不会去找证据”和“已有证据组织得好不好”。这两类结果合看，才有助于区分探索策略与记忆选择的作用。

**未核实 / 待验证**

- 未运行论文代码、未独立复现实验；已核对正式版主文、补充材料相关章节及指定提交的聚类、更新、预筛选和评测入口，未审计全部依赖，也未观看全部演示视频。
- 未验证商业模型服务版本漂移、重复运行方差与真实机器人长时位姿误差。主文和所读补充表未提供核心对比的重复运行置信区间。
- 作者因上下文长度限制未进行完全去掉预筛选的消融；K 的变化实验能解释召回预算，但尚不能单独量化预筛选相对全部输入的精度收益。[2，§13.2]
- 几何关系查询接口在补充 §14 被讨论为可调用能力；本次未核实它是否进入报告的问答决策链。论文也没有验证带状态期限、事件历史或动态身份约束的扩展记忆设计。
