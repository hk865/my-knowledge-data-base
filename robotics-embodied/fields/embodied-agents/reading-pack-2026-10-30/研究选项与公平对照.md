# 本项目下一步：先定位收益，再选择改进层

这是基于文献的研究设计，**尚未实施**，不包含新增运行结果。沿用项目已有 B0/B1/B2 概念；新选项不占用旧文档 B3/B4 的编号，以免与原来的类型化结果/记忆方案混淆。背景见 [发展路线](发展路线.md) 和 既有 Harness VLA 研究规划（本地来源，未发布）。

## 推荐先做：同工具的决策对照

研究问题是：当前成功中有多少来自通用 Agent 的在线判断，有多少来自工具、预对位、固定恢复程序或开发期记忆？先做这一项，结果出来后再决定后两项是否值得做。

| 条件 | 核心操作 | 固定什么 | 能回答什么 |
|---|---|---|---|
| B0：直接 VLA | 同一 VLA 接收任务并执行 | checkpoint、动作适配、任务、环境步预算 | 增加整个外层系统的总收益；本身不能隔离 Agent |
| B1：固定 FSM | 调用与 B2 相同的感知、预定位、VLA、搬运和恢复工具 | 工具合同、可用观测、成功判据、预算 | 已知流程和恢复表能做到多少 |
| B2：冻结 Agent | 根据运行时证据选择相同工具 | 不额外增加感知真值或独占工具 | 在匹配信息与工具条件下，在线决策是否有额外收益 |

B0 与 B2 的差异包括新增解析能力，因此只能称外层系统收益。真正区分“Agent 会思考”的关键是 B1 与 B2。FSM 不应被故意设计成一个毫无恢复能力的弱基线；给它同一开发集合、同类规则、可观测信号和合理的流程设计时间，并记录开发成本。

先用少量不同失败类型的任务做诊断试验，例如目标交换、位置变化、抓取滑落；最终选择应依据已有任务清单与开发集，不依据测试成绩挑任务。单任务单 seed 只能调试。开发/验证/最终评估初态预先划开并保存，任何 reference seed 探索不得混入最终评估。小规模结果首先解释机制，不作整个 LIBERO-Pro 的结论。

## 每次只拆一个可能的贡献

在 B1/B2 内做配对消融，比一次关掉所有功能更容易解释。

1. **目标绑定。** 对齐两组可用的对象定位与坐标转换；测试对象/目标替换，记录选错对象和定位失败。不能一组读真实物体位姿、另一组只看图像。
2. **动作前条件。** 保持目标信息一致，只改变是否允许同一预定位工具；记录进入 VLA 前的相对位姿和首次接触成功。改善来自 staging，就不要归因于 VLA 权重变强。
3. **恢复。** 设置同等重试上限，比较相同失败信号下固定恢复与 Agent 恢复；分别报告首次尝试与最终完成。允许多次重抓的最终成功，不能称一次抓取成功率。
4. **记忆。** 固定 reference 探索预算，对比无记忆、同样信息的固定规则、文本/结构化记忆。正式评估冻结库且禁 reset；记录是否包含任务专用坐标、图像或路径。若改进只在原 seed 有效，应优先解释为场景记忆。

所有消融均应保留工具自身的原始终止检查，先审计再添加 verifier，避免所谓新验证器只是重复已有 predicate。Agent 的 `finish`、工具返回“抓住了”和环境顶层成功是不同信号。最终成功采用双方共享的环境原生判据；隐藏判据不作为 Agent 的额外观测。

## 可选第二步：从轨迹到可重算程序

只有当 B2 中出现稳定可复用的任务段时，再做这一项。借鉴 [CaP](../../../papers/arxiv-2209.07753/reading.md)、[ASPIRE](../../../papers/arxiv-2607.00272/reading.md) 与 [RAX](../../../papers/arxiv-2610.22496/reading.md)，保存程序、输入合同、适用前提、失败信号和验证记录；新初态重新感知并计算坐标，避免直接保存一串成功动作或固定世界坐标。

对照“每次由 Agent 完整执行”和“固定已验证程序执行”。两者使用同一工具和训练/开发资料。分别统计完整成功、执行时间、模型调用和开发期探索成本；必要时另设“程序遇不确定再交回 Agent”条件。把程序内辅助 VLM 调用也计入预算，不能把无主 Agent 的运行描述为完全没有模型。

如果收益主要是复用任务专用轨迹，或换 seed 后前提频繁失效，应先修输入与适用范围，不急于扩大技能库。通过留出初态后，再测物体替换或任务组合，区分同任务泛化与跨任务迁移。

## 可选第三步：训练小 planner

只有在工具与任务协议稳定、B2 的高层选择确实优于 B1、并有足够可靠交互轨迹时，才考虑 [AgenticRoboRL](../../../papers/arxiv-2610.28589/reading.md) 的方向。它改的是 planner 参数；不能同时更新 VLA、感知与奖励后仍声称只验证了高层训练的贡献。

至少比较原始小模型、SFT、小模型 SFT+RL，并保留相同 harness 的冻结强模型作参考。教师使用的记忆与特权信息要记录；学生“无外接记忆”不等于教师经验未流入参数。训练、验证、评估初态分开，模型选择不能用测试集。原项目教师 SFT 轨迹未公开，需将数据获得成本列为前置条件，本次没有启动这条训练路线。

## 所有条件共同的记录合同

| 项目 | 需要记录的内容 |
|---|---|
| 版本 | 代码来源、实际改动、checkpoint 标识、planner 版本、prompt、工具与记忆版本 |
| 信息 | RGB/深度/状态/特权位姿分别向谁开放，隐藏成功函数是否泄漏 |
| 动作 | 环境步、action chunk 长度、调用次数、工具内循环和隐式重试 |
| 推理 | 模型输入/输出 token、图像次数、辅助模型调用、实际等待时间 |
| 试验 | 每任务初态列表、随机种子、回合数、可否 reset、操作员介入 |
| 成败 | 原生最终成功、首次尝试成功、恢复次数、超时、碰撞或异常、失败类型 |
| 经验 | reference 探索回合和时长、写入来源、冻结时点、测试反馈是否回流 |

预算至少同时给出物理环境交互量与墙钟时间。仿真可以暂停等待模型，并不意味着真实世界等待是免费的。工具内部做了十次尝试时，外层一次调用不能记为一次尝试；基础设施错误、主动放弃、超时也不能从成功率分母悄悄剔除。

报告每任务分子/分母和整体汇总，配对相同初态；样本足够时给出配对差值与区间。不要只报告最优 seed、最好模型或成功回合平均耗时。若计时只统计成功回合，必须同时给全部回合成本与失败超时，才能看出部署价值。

## 什么时候停止扩展

如果同信息、同工具、同预算下 Agent 与合理 FSM 没有稳定差异，就先报告这个结果，并定位是任务太简单、工具过强还是 Agent 决策不足。若差异主要来自记忆或重试次数，应把它作为具体贡献研究。只有剩余失败确实发生在接触控制层，才进一步讨论训练 VLA；不能因每个失败都发生在机器人运动时，就将其全部归因于动作模型。
