# 长上下文的基线

> 状态：Baseline 页 · v2 · 依据 [synthesis.csv](synthesis.csv) 与各篇原文

[入门页](README.md) · [路线图](ROADMAP.md) · [论文目录](PAPERS.md)

## 基线是谁、为什么是它

结论：本方向有两个基线配方，外加一个评测基线。
- Meta 的"不改结构、只改位置与训练"，定义了怎样把一个短上下文模型扩长。
- Qwen2.5-1M 的"训练到 256K、推理外推到 1M、再用稀疏 prefill 降成本"，定义了一个完整的开源百万上下文方案。
- 2025 年以后，DeepSeek 与 Kimi 的结构改造都拿全注意力加这类训练配方作对照。

| 基线 | 定义了什么 | 为什么后来者拿它当参照 |
|---|---|---|
| [Effective Long-Context Scaling](../../papers/arxiv-2309.16039/README.md)（2023）与 [Llama 3](../../papers/arxiv-2407.21783/README.md)（2024），Meta | **位置**：RoPE，提高基频（10K → 500K）。<br>**训练**：在预训练末段继续训练长序列，分级加长；Llama 3 405B 约 800B token 分六级，从 8K 到 128K。<br>**验收**：每一级要求短上下文评测完全恢复、该长度的大海捞针全部答对。<br>**后训练**：只混 0.1% 的合成长数据 | 结构不变，只改训练，最容易复用。<br>"短任务不退化 + 大海捞针"这对验收标准，被后来的报告普遍采用。<br>Qwen 的 ABF 直接沿用提高 RoPE 基频的做法 |
| [Qwen2.5-1M](../../papers/qwen2.5-1m/reading.md)（2025，阿里巴巴） | **位置**：RoPE 基频随阶段从 1 万提高到 1000 万。<br>**训练**：五级扩到 256K，加入"必须读远处"的合成任务。<br>**后训练**：两段 SFT，加只用 8K 以内样本的偏好优化。<br>**推理**：DCA 加 YaRN 温度，外推到 1M；稀疏 prefill 在 1M 上重新校准。<br>**评测**：passkey、RULER、LV-Eval、LongBench-Chat，并报短任务 | 开放了 7B、14B 权重，并把推理框架并入 vLLM。<br>它的表 4 给出"原版加外推"与"1M 训练"两种对照，后来的报告可以把训练收益与推理修复分开计算。<br>精读第九节列出了它尚缺的消融 |

评测基线：[大海捞针](../../papers/arxiv-2403.05530/README.md)（检索）与 [RULER](../../papers/arxiv-2404.06654/README.md)（合成多任务）。几乎每份长上下文报告都至少报其中一个；RULER 用 Llama2-7B 在 4K 上的分数（85.6%）作阈值，定义"有效上下文长度"。

## 基线的结构拆分

结论：一个长上下文方案可以拆成六个可替换的部件。两个基线在前四个部件上大体相同，分歧在推理端；2025 年以后的结构改造，动的是"注意力结构"这一格。

| 部件 | 含义 | Meta 配方 | Qwen2.5-1M |
|---|---|---|---|
| 位置表示 | 怎样让更远的距离可用 | RoPE，基频 500K（Llama 2 Long）；Llama 3 同为 500K | RoPE，基频随阶段提高到 1000 万 |
| 长依赖数据 | 让预测必须用到远处信息的数据 | 长文档；数据质量比长度分布更重要（Llama 2 Long §4.2） | 自然长文加填空、检索、段落重排等合成任务 |
| 课程 | 在哪个阶段、分几级加长 | 预训练末段，六级到 128K | 预训练末段，五级到 256K，每级 75% 的序列取当前最大长度 |
| 后训练 | 把读取能力变成按指令处理长文的能力 | 混 0.1% 合成长数据的 SFT，DPO 只用短数据 | 先短后长的两段 SFT，偏好优化只用 8K 以内的样本 |
| 注意力结构 | 每个 token 读多少历史、存多少 KV | 稠密全注意力 + GQA | 稠密全注意力 + GQA |
| 推理外推与执行 | 推理时怎样超出训练长度、怎样降低 prefill 与显存 | 不外推，窗口即训练长度 | DCA + YaRN 温度外推到 1M；稀疏 prefill、分块 prefill、推理引擎优化 |

部件之间有依赖：
- **位置表示决定课程能不能分级做**：插值或提高基频后，少量训练就能适应新长度。
- **注意力结构决定课程能走多长**：全注意力在 1M 上训练太贵，所以 Qwen 训练到 256K 后靠推理外推，V4、K3 先改结构再训练到 1M。
- **推理外推与执行会改变注意力的实际行为**：Qwen 发现 DCA 打乱了稀疏选点依赖的斜线模式，要单独修复。

## 后续工作在改哪个部件

| 部件 | 改法 | 代表论文 | 改进了什么 / 付出了什么 |
|---|---|---|---|
| 位置表示 | 旋转位置编码，分数只依赖相对距离 | [RoPE](../../papers/arxiv-2104.09864/README.md) | **改进**：相对位置与长期衰减。<br>**代价**：超出训练长度直接外推会崩（PI 表 1：困惑度超过 1000） |
| 位置表示 | 线性插值：把新位置压回训练范围 | [PI](../../papers/arxiv-2306.15595/README.md) | **改进**：约 1000 步扩到 32K。<br>**代价**：原窗口内下降，7B 的 BoolQ 从 76.1 到 64.7（32K） |
| 位置表示 | 按频段插值，加注意力温度 | [YaRN](../../papers/arxiv-2309.00071/README.md) | **改进**：128K 上 passkey 99.4%。<br>**代价**：短任务小幅下降 |
| 位置表示 | 提高 RoPE 基频（ABF） | [Effective Long-Context Scaling](../../papers/arxiv-2309.16039/README.md)、[Llama 3](../../papers/arxiv-2407.21783/README.md)、[Qwen2.5-1M](../../papers/qwen2.5-1m/reading.md) | **改进**：配合继续预训练，70B 的短任务不降反升。<br>**代价**：要训练，不是免训练外推 |
| 位置表示 | 全局层不用位置编码，位置交给线性注意力层 | [Kimi Linear](../../papers/arxiv-2510.26692/README.md)、[Kimi K3](../../papers/arxiv-2607.24653/README.md) | **改进**：扩上下文不必调 RoPE；同配方下 RULER 128K 84.3，带 RoPE 的变体 78.8。<br>**代价**：依赖混合结构，纯全注意力模型用不了 |
| 长依赖数据 | 质量优先，不刻意上采样长文 | [Effective Long-Context Scaling](../../papers/arxiv-2309.16039/README.md) | **改进**：很少的长文本也能训出长上下文能力。<br>**代价**：只验证到 32K |
| 长依赖数据 | 合成"必须读远处"的任务（检索、重排、读遍 1M） | [Qwen2.5-1M](../../papers/qwen2.5-1m/reading.md)、[Kimi K3](../../papers/arxiv-2607.24653/README.md) | **改进**：K3 写明仅有长度不能带来长程能力，靠这类数据补。<br>**代价**：配比与生成模板都未公开，没有逐项消融 |
| 课程 | 预训练末段分级加长，每级用短任务与大海捞针验收 | [Llama 3](../../papers/arxiv-2407.21783/README.md)；DeepSeek-V4 与 K3 的课程见[预训练方向](../pretraining/README.md)③ | **改进**：避免一开始就付平方代价。<br>**代价**：每一级都要验收；Qwen 的阶段数据不是单变量消融，课程本身的贡献无法单独证明 |
| 后训练 | 少量合成长数据混入短指令 | [Llama 3](../../papers/arxiv-2407.21783/README.md) | **改进**：0.1% 时短、长评测都最好。<br>**代价**：只用短数据会显著损害长上下文能力 |
| 后训练 | 两段 SFT 加短样本偏好优化 | [Qwen2.5-1M](../../papers/qwen2.5-1m/reading.md) | **改进**：LongBench-Chat 7B 从 7.32 到 8.08。<br>**代价**：没有长轨迹 RL，不能推出长时程决策已解决 |
| 注意力结构 | 保留开头的 sink token 加滑动窗口 | [StreamingLLM](../../papers/arxiv-2309.17453/README.md) | **改进**：稳定处理 400 万 token，比重算窗口快 22.2 倍。<br>**代价**：不扩展窗口、不增强记忆，远处信息直接丢掉 |
| 注意力结构 | 训练时就稀疏：压缩、选块、窗口三路 | [NSA](../../papers/arxiv-2502.11089/README.md) | **改进**：LongBench 0.469 对全注意力 0.437；64K 解码快 11.6 倍。<br>**代价**：只验证到 64K |
| 注意力结构 | 索引器选 top-2048 → 压缩后再稀疏（CSA）与重度压缩（HCA）交错 | [DeepSeek-V3.2](../../papers/arxiv-2512.02556/README.md)、[DeepSeek-V4](../../papers/arxiv-2606.19348/README.md) | **改进**：1M 下单 token FLOPs 为 V3.2 的 27%、KV 为 10%；MRCR 1M 83.5。<br>**代价**：128K 以后检索下降；结构复杂；V3.2 的索引器仍是平方复杂度 |
| 注意力结构 | 3:1 线性注意力（KDA）与全注意力混合 | [Kimi Linear](../../papers/arxiv-2510.26692/README.md)、[Kimi K3](../../papers/arxiv-2607.24653/README.md) | **改进**：KV 缓存最多少 75%，1M 解码最多快 6 倍。<br>**代价**：LongBench v2 略低于全注意力；纯线性检索弱，7:1 时泛化变差 |
| 注意力结构 | 用继续训练把已有模型转成 DSA（MLA → 稠密预热 → 稀疏适应） | [GLM-5](../../papers/arxiv-2602.15763/README.md) | **改进**：长序列注意力计算省 1.5–2 倍，128K RULER 78.86 对稠密 79.21。<br>**代价**：RL 中要冻结索引器、用确定性 top-k |
| 注意力结构 | 3:1 的 Gated DeltaNet 与门控注意力混合 | [Qwen3.5](../../papers/qwen3.5/README.md) | **改进**：原生 262K、可扩展到约 1M。<br>**代价**：只有模型卡，缺少长上下文消融 |
| 注意力结构 | Mamba-2 为主、少数注意力层且不用 RoPE | [Nemotron 3](../../papers/arxiv-2512.20856/README.md) | **改进**：1M RULER 54.19（上一代 23.43）；Nano 吞吐为 Qwen3-30B-A3B 的 3.3 倍。<br>**代价**：1M 上仍只有约一半 |
| 注意力结构 | 反例：全部层用全注意力 | [MiniMax-M2](../../papers/arxiv-2605.26494/README.md) | **改进**：避开滑窗混合在多跳推理、检索、上下文学习上的退化。<br>**代价**：长序列成本按平方增长 |
| 注意力结构 | 消除注意力汇聚的输出门 | [Gated Attention](../../papers/arxiv-2505.06708/README.md) | **改进**：YaRN 扩到 128K 后，RULER 128K 从 31.65 到 58.82。<br>**代价**：原训练长度内差别很小 |
| 注意力结构 | 换序列算子：选择性状态空间模型 | [Mamba](../../papers/mamba/reading.md) | **改进**：状态大小固定，不随长度增长。<br>**代价**：精确检索弱，同一缺点推动了 Kimi 的混合结构（见[递推状态谱系](../../../foundations/relations/recurrent-state.md)） |
| 推理外推与执行 | DCA 加 YaRN 温度，免训练外推 | [Qwen2.5-1M](../../papers/qwen2.5-1m/reading.md)（引用 [DCA](https://arxiv.org/abs/2402.17463)） | **改进**：原版 14B 加外推后 RULER 128K 从 53.0 到 78.1。<br>**代价**：DCA 与温度总是一起用，各自贡献未拆开 |
| 推理外推与执行 | 稀疏 prefill，在目标长度上重新校准 | [Qwen2.5-1M](../../papers/qwen2.5-1m/reading.md)（引用 [MInference](https://arxiv.org/abs/2407.02490)） | **改进**：1M 首 token 延迟降低 3.2–6.7 倍。<br>**代价**：不重新校准时，400K 以上的检索掉到 60% 以下 |
| 推理外推与执行 | KV 缓存量化、分页管理 | [KIVI](../../papers/arxiv-2402.02750/README.md)、[vLLM](../../papers/arxiv-2309.06180/README.md)（见[推理时计算方向](../inference/BASELINES.md)） | **改进**：同样显存放下更长的上下文或更多请求。<br>**代价**：量化有精度损失；不改变模型学过的长度 |
| 推理外推与执行 | 把记忆移到上下文之外：查表记忆、外部记忆 | [Engram](../../papers/arxiv-2601.07372/README.md)、[Frozen Memory Is Not Enough](../../papers/arxiv-2608.17050/README.md) | **改进**：Engram 的多查询大海捞针从 84.2 到 97.0。<br>**代价**：解决的是静态知识，不是读当前输入 |
| 推理外推与执行 | 长输入放进代码环境，模型写代码切分并递归调用自己 | [Recursive Language Models](../../papers/arxiv-2512.24601/README.md) | **改进**：处理超出窗口两个数量级的输入，OOLONG-Pairs 上 GPT-5 从 0.1% 到 58.0%。<br>**代价**：依赖写代码能力；子调用串行、成本方差大 |
| 推理外推与执行 | 并行子智能体各持局部上下文，只交回相关结果 | [Kimi K2.5](../../papers/arxiv-2602.02276/README.md) | **改进**：主动的上下文管理，WideSearch 执行时间快 3–4.5 倍。<br>**代价**：子智能体冻结，不联合训练 |
| 评测 | 证据位置 × 文档数的受控实验 | [Lost in the Middle](../../papers/arxiv-2307.03172/README.md) | **改进**：发现 U 形位置效应。<br>**代价**：输入最长约 16K token（30 篇文档；键值检索 300 对） |
| 评测 | 多模态大海捞针、多针、从语法书学翻译 | [Gemini 1.5](../../papers/arxiv-2403.05530/README.md) | **改进**：测到 10M。<br>**代价**：单针接近满分、多针 1M 约 60%，报告自己承认单针不够 |
| 评测 | 合成多任务，定义有效长度 | [RULER](../../papers/arxiv-2404.06654/README.md) | **改进**：区分出声称长度与有效长度。<br>**代价**：不控制位置；与真实任务的相关性未验证 |

## 批注

**易误读**
- 表中的 RULER 数字来自不同报告，口径不同，不能跨行比较：
  - Kimi Linear 是同配方的基座模型对比；
  - Gated Attention 是 YaRN 外推后的对比；
  - Qwen2.5-1M 是对话模型。
- Llama 3 的 0.1% 是合成长数据在 SFT 混合中的最优比例，不是长数据的上限。

**与其他论文的关联**
- "注意力结构"一格的成本对比与注意力汇聚，在[预训练方向](../pretraining/README.md)②③有更细的表格，本页只列与长上下文能力相关的结果。
- "推理外推与执行"一格和[推理时计算方向](../inference/BASELINES.md)"显存与批处理"一格是同一组手段，那里侧重解码与多请求服务。

**未核实 / 待验证**
- DCA、MInference 只核对了 arXiv 摘要页：DCA 免训练地把 Llama2 70B 扩到 10 万 token 以上；MInference 在单张 A100 上把 prefill 延迟最多降低 10 倍。它们在 Qwen2.5-1M 中的用法以 [Qwen2.5-1M 精读](../../papers/qwen2.5-1m/reading.md)为准。
