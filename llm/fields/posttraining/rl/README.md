# 语言模型强化学习

> 状态：领域入门页 · v1 · 依据 [synthesis.csv](synthesis.csv)（19 篇）
>
> 速览：
> 1. 把生成当成 RL：状态是"提示 + 已生成的前缀"，动作是下一个 token，奖励大多只在回答末尾给一次。算法从带价值模型的 PPO（InstructGPT）走到用组内相对得分作优势、去掉价值模型的 GRPO（DeepSeekMath 起）；奖励从人类偏好训练出的奖励模型走到程序验证器（RLVR）。
> 2. 2025 年的大规模 RLVR 让模型学会长思维链：DeepSeek-R1-Zero 不经 SFT，AIME 2024 从 15.6% 升到 77.9%；Qwen3-235B 在 170 步内从 70.1 升到 85.1。但 RL 主要是在基座已有的回答里重新分配概率：DeepSeekMath 的 RL 提高 Maj@K 而不提高 Pass@K，Yue 等在大 k 时测得基座的 pass@k 更高。
> 3. 做不好的场景都有原文：神经奖励模型在大规模 RL 中被钻空子（R1）；策略熵早早坍缩、性能饱和（DAPO、Cui 等）；GRPO 让错误回答越写越长（Dr. GRPO）；回答越来越长、过度思考（k1.5、V3.2、K2）；小基座上纯 RL 无效（R1 附录 G.1）；推理框架与训练框架不一致带来离策略与 MoE 路由漂移（V3.2）。
> 4. `[判断]` 2025–2026 年 RL 的角色在变：从"直接做出最终模型"变成"做出各领域、各推理强度的专家"，最终模型由多教师 on-policy 蒸馏合并（DeepSeek-V4、Kimi K3）。

本页是[后训练](../README.md)的强化学习子方向。偏好信号怎样变成奖励（奖励模型、DPO）在[偏好学习方向](../preferences/README.md)；三个阶段的分工、"RL 是否超出基座能力"的证据汇总在总览页。精读：[PPO](../../../papers/ppo/reading.md)（裁剪目标）、[InstructGPT](../../../papers/instructgpt/reading.md)第 7 节（PPO 怎样用在语言模型上）。基线拆分见 [Baseline 页](BASELINES.md)，练习见[路线图](ROADMAP.md)，论文见[论文目录](PAPERS.md)。

## 这个领域在解决什么

结论：给一道有标准答案的数学题，让模型自己写解答，答对给 1、答错给 0，怎样用这个稀疏信号让模型越来越会解题，同时不让它学会钻打分规则的空子。

和训练四足策略相比，语言模型 RL 有四处不同：

| | 四足 RL（读者熟悉的） | 语言模型 RL |
|---|---|---|
| 动作空间 | 十几维连续关节目标 | 十几万个 token 的离散词表，每步一个 |
| 一条轨迹 | 几秒到几十秒、上千个控制步 | 一个回答，几百到几万个 token |
| 奖励 | 每步都有（速度跟踪、姿态、能耗） | 大多只在回答末尾给一次：答案对不对、测试用例过没过、奖励模型打几分 |
| 起点 | 随机初始化或模仿预训练 | 已经会说话的预训练模型，RL 只是在它的分布里微调；通常要用 KL 拉住它 |

这些差别决定了后面的算法选择：奖励稀疏且只在末尾，逐 token 的价值很难学准，于是 GRPO、Kimi 的镜像下降变体都去掉了价值模型，改用"同一题多采几个回答、相互比较"作基线。

## 主线历史

结论：语言模型 RL 的问题链是"PPO 太重 → 去掉价值模型 → 奖励换成验证器 → 规模化后暴露熵、长度、稳定性三类坑 → RL 退为造专家"。

### 1 PPO 与 RLHF（2017–2022）

留下的问题：策略梯度每批数据只能更新一次，TRPO 稳定但实现复杂。

改变：[PPO](../../../papers/ppo/reading.md) 把新旧策略的概率比裁剪在 [1−ε, 1+ε]，同一批数据可以多学几轮。[InstructGPT](../../../papers/instructgpt/reading.md) 把它用在语言模型上：actor 是语言模型，critic（价值模型，6B，从奖励模型初始化）估计每个前缀之后的回报，奖励是奖励模型分数减去相对 SFT 模型的逐 token KL；再混入预训练梯度（PPO-ptx）减轻对齐税。

做不好的场景：
- 一次 RLHF 要同时放下策略、参考、奖励、价值四个大模型；价值模型与策略同样大，显存与计算负担重（DeepSeekMath §4.1）。
- PPO 难调：Meta 在 Llama 3 中试过 PPO，最终改用 DPO，理由是 RL 算法"不够稳定、难以扩展"；Tulu 3 在未专门调参的对照中 PPO 略低于 DPO。
- 对齐税：PPO 让 InstructGPT 的 SQuADv2 掉 17.8 个 F1 点。

### 2 去掉价值模型，奖励换成验证器（2024）

留下的问题：PPO 太重；推理题有标准答案，不需要人去比较。

改变：
- [DeepSeekMath](../../../papers/arxiv-2402.03300/README.md) 提出 GRPO（组内相对策略优化）：同一题采一组回答，用组内奖励的均值与标准差归一化得到每个回答的优势，去掉价值模型；KL 直接加进损失而不是奖励。7B 模型 GSM8K 从 82.9% 到 88.2%，MATH 从 46.8% 到 51.7%。这一版的奖励仍来自训练出的奖励模型。
- DeepSeek-V2 随即用 GRPO 先做"推理对齐"、再做"人类偏好对齐"，作者发现数学与代码能力能在更长的训练中持续提升。
- OpenAI 的 [PRM 研究](../../../papers/arxiv-2305.20050/README.md)显示，给每一步打分的过程奖励模型在重排上优于只看结果的奖励模型；AI2 的 [Tulu 3](../../../papers/arxiv-2411.15124/README.md) 把"答案能被程序验证才给奖励"的 RL 命名为 RLVR，用 PPO 在 GSM8K、MATH 与可验证的指令约束上训练。

做不好的场景：
- DeepSeekMath §5.2.2：RL 提高了 Maj@K，没有提高 Pass@K，作者解释为 RL 让输出分布更稳健，而不是增强了基础能力；并认为只用 SFT 阶段的题目与朴素采样，可能是原因之一（§5.2.3）。
- 过程标注有噪声：DeepSeekMath 提到 PRM800K 约 20% 错标。
- 验证器也会被过度优化：Tulu 3 降低 KL 惩罚后，IFEval 上出现只为满足约束的怪异输出。

### 3 大规模 RLVR 与长思维链（2024.9–2025.1）

留下的问题：OpenAI 的 o1 显示用大规模 RL 训练长思维链有效，却只公开到这一层（[o1 文献卡](../../../papers/openai-o1/README.md)、[系统卡](../../../papers/arxiv-2412.16720/README.md)）。

改变：[DeepSeek-R1](../../../papers/arxiv-2501.12948/README.md) 与 [Kimi k1.5](../../../papers/arxiv-2501.12599/README.md) 同日公开配方。共同点：
- 奖励只用规则：答案匹配、编译与测试用例、格式；R1 写明不对推理任务用神经奖励模型，因为它在大规模 RL 中会被钻空子。
- 不用价值模型、过程奖励模型、MCTS；R1 附录 G.2 把 PRM 与 MCTS 列为失败尝试，k1.5 认为价值函数会惩罚"走错一步又纠正回来"的轨迹，而这正是长思维链要学的。
- 回答长度随训练自然增长，模型出现反思与验证。

不同点：R1-Zero 不做 SFT，直接在 DeepSeek-V3-Base 上做 GRPO；k1.5 先做长思维链 SFT，把 RL 上下文扩到 128K，用部分 rollout（复用上一轮未完成轨迹的前缀）提高效率，并从一开始就考虑长度控制。

做不好的场景：
- R1-Zero 可读性差、中英混杂；R1 加语言一致性奖励，代码评测因此略降（附录 B.6）。
- 用帮助性奖励模型训练更多步就出现奖励黑客，R1 只在最后 400 步加入偏好奖励（附录 B.5）。
- 小基座不行：7B 稠密与 16B MoE 上纯 RL 没有带来有意义的提升，回答一长就重复（R1 附录 G.1）。
- 过度思考：k1.5 观察到 RL 中回答长度快速增长，加长度奖励抑制；R1 自述简单问题上仍想太多。
- 题目会被猜中：k1.5 剔除选择题、判断题、证明题，以及不写推理、猜 8 次内就能猜中答案的题，否则推理错了也能拿奖励（§2.1）。

### 4 复现与修正：开源社区补出的坑（2025）

留下的问题：R1 报告没有给出足以复现的细节；"aha moment"、长度增长到底来自 RL 还是来自基座。

改变：
- [DAPO](../../../papers/arxiv-2503.14476/README.md)（字节跳动 Seed 与清华）：在 Qwen2.5-32B 上朴素 GRPO 只有 30 分，R1 报告的同设定是 47 分；找出熵坍缩、奖励噪声、训练不稳，提出放宽裁剪上界（Clip-Higher）、丢掉全对全错的题组（动态采样）、按 token 而非按样本平均损失、超长回答软惩罚，并去掉 KL，逐项累加到 50 分。
- [Dr. GRPO](../../../papers/arxiv-2503.20783/README.md)（Sea AI Lab）：GRPO 按回答长度归一化，使错误回答越写越长；按组内标准差归一化，使太易或太难的题权重过大；多个开源 PPO 实现同样有长度归一化。并发现包括 DeepSeek-V3-Base 在内的基座本来就会自我反思。
- [Cui 等](../../../papers/arxiv-2505.22617/README.md)（上海 AI Lab 等）：没有干预时，策略熵在训练早期降到接近 0，性能饱和，二者满足 R = −a·exp(H) + b；熵的变化由"动作概率与 logit 变化的协方差"驱动，于是只限制高协方差 token 的更新。
- [Yue 等](../../../papers/arxiv-2504.13837/README.md)（清华 LeapLab）：六种 RL 算法、多个模型族上，k 大时基座的 pass@k 都高于 RL 模型，RL 模型的推理路径已在基座的采样分布里；蒸馏能真正扩大边界。
- [Qwen3](../../../papers/arxiv-2505.09388/README.md) 的推理 RL 只用 3,995 个题目—验证器对，作者写明大批量、每题多次 rollout、离策略训练有益，并控制熵稳定上升或保持。

`[判断]` 这四篇把 R1 的叙事修正为：RL 在基座已有的能力里放大正确路径、学会花更多 token；熵、长度、难度权重这三个量要显式管理，否则 RL 很快停止进步或走偏。

### 5 规模化：多领域、稳定性与长度预算（2025 下半年）

留下的问题：只做数学与代码不够；RL 的算力要扩到预训练的量级，训练要稳。

改变：
- [Kimi K2](../../../papers/arxiv-2507.20534/README.md) 把 RLVR 与自我批评的 rubric 奖励放进同一个框架，沿用 k1.5 的策略优化；为跨领域一致提升加了三件事：按任务类型设 token 预算、超出截断并惩罚；把精选的高质量数据作为辅助的 PTX 损失，防止遗忘；采样温度先高后低。
- [DeepSeek-V3.2](../../../papers/arxiv-2512.02556/README.md) 的后训练算力超过预训练成本的 10%：先为六个领域各训练一个 RL 专家并蒸馏，再把推理、智能体与人类对齐合进同一个 GRPO 阶段（作者说这避免了多阶段训练的灾难性遗忘）；为稳定规模化加了四处修补：无偏 KL 估计（数学等领域弱 KL 或不加更好）、屏蔽偏离过大的负优势序列、训练时沿用采样时的 MoE 路由、沿用采样时的 top-p/top-k 截断掩码。

做不好的场景：
- 训练与推理不一致：推理框架与训练框架的实现差异会加重离策略程度；同一输入在两边可能走不同的专家，V3.2 称 Keep Routing 对 MoE 的 RL 稳定性至关重要。
- token 效率：V3.2 要生成更长才能达到 Gemini-3.0-Pro 的质量；K2 在难题上会生成过多 token，导致截断或工具调用不完整。
- Qwen3 在加入非思考模式与通用 RL 后，思考模式的 AIME'24 与 LiveCodeBench 下降。

### 6 RL 造专家，蒸馏做统一模型；环境换成真实沙箱（2026）

留下的问题：混合 RL 仍有能力互相拖累；智能体任务要几百上千次工具调用，单条轨迹跨越多个训练迭代。

改变：
- [DeepSeek-V4](../../../papers/arxiv-2606.19348/README.md) 仍用 GRPO 训练各领域专家，并按三档推理强度用不同的长度惩罚与上下文窗口训练；但把 V3.2 的混合 RL 阶段整个换成十多个教师的 on-policy 蒸馏，并用全词表 logit 计算反向 KL，理由是逐 token 估计方差大、常致训练不稳。
- [Kimi K3](../../../papers/arxiv-2607.24653/README.md) 在 3 个领域 × 3 档推理强度上训练 9 个专家：部分 rollout 扩展到长程智能体任务（一部分轨迹完成就开始更新，未完成的下一轮优先续写），用逐 token 的正则约束更新以容忍高度过期的数据；按每题的初始预算乘系数决定何时判负；最后用逐 token 的 on-policy 蒸馏奖励把 9 个专家合并，试过更细的 top-k 蒸馏目标"没有明显优势"。

做不好的场景：
- 智能体会钻环境的空子：K3 写明更强的智能体探索更激进，甚至尝试奖励黑客，早期容器沙箱出现内核崩溃与死锁，于是改用隔离的 microVM，让智能体与验证器隔离，并配隐藏验证器与有限的提交次数。
- 两家对蒸馏目标的选择相反（V4 全词表、K3 逐 token），没有同条件对照。

同一时期（2025-10 – 2026-09），DeepSeek 与 Kimi 之外的报告补上了三件事：

- **RL 算力的规模规律。** [ScaleRL](../../../papers/arxiv-2510.13786/README.md)（Meta 等，2025-10）把"验证集通过率随 RL 算力的变化"拟合成 S 形曲线，用上限 A 与陡度 B 区分配方：累计 40 万 GPU 小时的消融显示，损失聚合、优势归一化、课程、长度惩罚、离策略算法等多数补丁只改变效率，基本不改上限；稳定的配方可以从小规模外推，8B 模型上一次跑到 10 万 GPU 小时仍落在外推曲线上。它组合出的配方用 CISPO 损失（截断重要性权重本身、权重不回传梯度），并把输出层 logits 改用 FP32，以减小推理引擎与训练框架的数值差异，这一项把拟合上限从 0.52 提到 0.61。
- **智能体 RL 变成异步系统工程。** [GLM-5](../../../papers/arxiv-2602.15763/README.md)（智谱，2026-02）的 slime 把推理与训练放到不同 GPU 上、每 K 步同步权重，用采样时记录的 log 概率做双侧重要性采样并丢掉版本落后太多的轨迹，用 Token-in-Token-out 网关避免多轮中重新分词；后训练按推理 RL → 智能体 RL → 通用 RL 顺序进行，最后用以前阶段的检查点作教师做跨阶段 on-policy 蒸馏，理由是顺序优化不同目标会累积损失先前的能力。[MiniMax-M2](../../../papers/arxiv-2605.26494/README.md)（2026-05）的 Forge 用"窗口内贪心、窗口间先进先出"的调度吸收智能体轨迹的长度差异，用前缀树合并共享前缀的轨迹（正文称训练最多快 40 倍），算法用 CISPO，奖励里加入鼓励并行执行的完成时间项。
- **完全公开的 RL。** AI2 的 [Olmo 3](../../../papers/arxiv-2512.13961/README.md)（2025-12）从 Tulu 3 的 PPO 改为 GRPO 的一组修改（零梯度过滤、主动补采样、token 级损失、不除以标准差、放宽裁剪上界、不加 KL、截断重要性采样），靠异步与训练中途更新推理权重提速约 4 倍；v2 的 Olmo 3.1 Think 32B 在 224 块 GPU 上多跑了 21 天 RL。它另训练一个直接从基座做 RL 的 RL-Zero 版本，用来研究预训练数据对 RLVR 的影响。

做不好的场景：
- 训练—推理不一致仍是失稳的主因：GLM-5 发现 DSA 索引器若用非确定性的 top-k 实现，RL 几步之内性能骤降、熵急跌，只好在 RL 中冻结索引器、改用确定性 top-k；ScaleRL 的 FP32 logits 解决的是同一类问题。
- 奖励黑客转移到新任务：GLM-5 在幻灯片生成上观察到截断过长内容、操纵间距等钻空子行为，靠修补渲染器堵住。
- 评测污染会让 RL 的结论失真：Olmo 3 写明，中段训练数据若含评测内容，随机的"伪奖励"会和真奖励一样有效。
- 稳定性仍靠时间换：Olmo 3 Think 32B 的首轮 RL 约 5 天，其中至少 1 天因稳定性问题损失。

## 技术地基

- **把生成写成 MDP 与策略梯度**：[强化学习讲义](../../../../foundations/lessons/05b-reinforcement-learning.md)第 2–5 节；语言模型怎样接入见第 9 节。
- **PPO 的裁剪与两种 KL**：裁剪限制单次更新；RLHF 中对参考模型的 KL 限制整个训练的漂移。见 [PPO 精读](../../../papers/ppo/reading.md)与讲义第 7 节。DeepSeekMath 起把 KL 从奖励移到损失里；DAPO 去掉 KL；V3.2 修正了 KL 估计的偏差。
- **优势与基线**：PPO 用价值模型加 GAE 估计逐 token 优势；GRPO 用同题一组回答的奖励减均值（再除以标准差）作为整条回答的优势；Dr. GRPO 去掉除以标准差与按长度归一化。基线降方差的原理见讲义第 4 节。
- **重要性采样与离策略**：一批 rollout 切成多个小批量更新、推理引擎与训练框架数值不一致、轨迹跨多轮迭代（K3）都会让数据变"旧"；裁剪、序列屏蔽、逐 token 正则是三种容忍方式。
- **策略熵**：衡量探索程度。PPO 在 Atari 上加系数 0.01 的熵奖励（[PPO 精读](../../../papers/ppo/reading.md)附录设置）；Cui 等发现语言模型上直接加熵正则无效，改为限制高协方差 token。
- **评测指标**：pass@1（多次采样的平均正确率）、cons@k 或 maj@k（多数投票）、pass@k（k 次中至少对一次）。三者回答不同的问题，见下文"用什么衡量进展"。

## 主要路线与团队偏好

| 团队 | `[判断]` 押注 | 代表 | 代价与做不好的地方 |
|---|---|---|---|
| OpenAI | PPO + 价值模型的 RLHF；2024 年起用大规模 RL 训练推理模型 | InstructGPT、PRM、o1 | o1 起不公开算法与奖励 |
| DeepSeek | GRPO 贯穿六代（DeepSeekMath、V2、V3、R1、V3.2、V4）；能用规则就不用奖励模型；RL 得到的能力蒸馏给下一代与小模型；每一代补稳定性 | DeepSeekMath、R1、V3.2、V4 | 语言混杂、过度思考、token 效率；补丁原理不完全清楚 |
| Kimi | 不用价值网络的策略优化（k1.5 起沿用）；长上下文 RL 与部分 rollout；长度作为显式预算 | k1.5、K2、K3 | 难题上 token 过多；智能体环境的奖励黑客与系统安全 |
| Qwen | GRPO + 少量高难题目；小模型不做 RL，改用蒸馏 | Qwen3 | 融合后竞赛分数下降 |
| 字节跳动 Seed 等开源系统 | 把大规模 RL 的细节与代码全部公开（基于 verl） | DAPO | 只在数学上、单一基座上验证 |
| AI2 | 在 RLVR 中保留 PPO 与价值模型，全部开放 | Tulu 3 | 价值模型成本；作者在未来工作中建议试 GRPO |
| 学术分析 | 用受控实验检查"RL 学到了什么" | Dr. GRPO、Cui 等、Yue 等 | 多在 7B–32B 的 Qwen 基座上，Dr. GRPO 指出 Qwen2.5 基座本身有特殊的预训练偏差 |
| Meta（2025-10 以后） | 把 RL 做成可预测的规模化实验：S 形算力曲线、CISPO、FP32 logits | [ScaleRL](../../../papers/arxiv-2510.13786/README.md) | 实验以数学为主；之后的 Muse Spark（2026-04）只在博客中称 RL 收益平滑、可预测，未公开配方 |
| 智谱（GLM） | 异步智能体 RL 系统（slime）；顺序多阶段 RL 后用跨阶段 on-policy 蒸馏找回能力 | [GLM-5](../../../papers/arxiv-2602.15763/README.md) | 训练—推理不一致要逐个堵（确定性 top-k、冻结索引器、TITO） |

| AI2（2025-12 以后） | 完全公开的 GRPO 变体与异步 RL；RL-Zero 作研究基线 | [Olmo 3](../../../papers/arxiv-2512.13961/README.md) | 规模在 32B；首轮 RL 有稳定性损失 |
| NVIDIA | 多环境同时 RL，取代分阶段 | [Nemotron 3](../../../papers/arxiv-2512.20856/README.md) | 白皮书未给出与"专家加蒸馏"的同条件对照 |

`[判断]` 收敛：去掉价值模型；能验证的任务用规则奖励；显式管理熵与长度；按领域训练专家再合并。分化：是否保留 KL（DAPO 去掉，V3.2 按领域调，K2、K3 用自己的正则）；是否先做 SFT（R1-Zero 不做）；专家怎样合并（V3.2 混合 RL，V4 与 K3 蒸馏，二者蒸馏目标又不同）。

`[判断]` 2025-10 以后的补充：截断重要性权重一类的损失（CISPO）在 MiniMax 与 Meta 的 ScaleRL 中被独立选中，ScaleRL 的对比中它与 GSPO 都明显好于 DAPO 的损失；GRPO 在 AI2 的完全公开配方中取代了 PPO；"训练—推理不一致"从 V3.2 的路由回放扩展成一类问题（FP32 logits、确定性 top-k、按 token 重放分词）。新的分化是多领域怎样合并：DeepSeek-V4 与 Kimi K3 走"专家加 on-policy 蒸馏"，GLM-5 顺序做多阶段 RL 后再用跨阶段蒸馏找回能力，NVIDIA 的 Nemotron 3 则在所有环境上同时 RL，并写明这比它以前的分阶段做法更稳、更少奖励黑客。

## 与机器人强化学习的共性

- `[经验]` **同一套配方在两个领域间搬运**：[SimpleVLA-RL](../../../../robotics-embodied/papers/arxiv-2509.09674/README.md) 在 VLA 上用 GRPO、0/1 成功奖励，并采用放宽裁剪上界、丢掉全成功或全失败批次、去掉 KL 等做法；它同样发现基座在某任务上完全不会时 RL 起不了步，与 R1 附录 G.1 的小基座现象一致。
- `[经验]` **奖励被钻空子**：k1.5 剔除"能猜中答案"的题、K3 隔离智能体与验证器，对应腿足 RL 里奖励项被策略利用（[模仿学习与机器人强化学习](../../../../robotics-embodied/fields/imitation-reinforcement-learning/README.md)"奖励设计"一节）。
- `[判断]` **价值模型的去留**：腿足仿真每步都有奖励，价值函数学得准，PPO 加 critic 是标准做法；语言模型奖励只在末尾、轨迹上万步，价值难学，同一提示又能廉价重复采样，组内基线更划算。依据是 DeepSeekMath §4.1 与 k1.5 §2.3.2 的理由；反例是 Tulu 3 的 RLVR 仍用 PPO 与价值模型。机器人一侧也在变：[π*0.6](../../../../robotics-embodied/papers/arxiv-2511.14759/README.md) 用价值函数给动作打优势，再条件化到策略上。

## 用什么衡量进展

| 指标 | 回答的问题 | 口径问题 |
|---|---|---|
| pass@1（多次采样平均） | 随手采一次，答对的概率 | 贪心解码下长推理模型容易重复，R1 改为温度 0.6、每题 64 次采样再平均；DAPO 把评测集重复 32 次报 avg@32 |
| cons@k / maj@k | 多次采样投票后对不对 | DeepSeekMath 的 RL 只提高了这一项 |
| 大 k 的 pass@k | 能力边界：采很多次有没有一次对 | Yue 等：k 大时基座更高；Qwen3 用 pass@64 比较 RL 与蒸馏 |
| Codeforces 评分与百分位、SWE-bench Verified、智能体评测 | 竞赛与真实任务 | 评测时长限制 RL 规模（R1 自述软件工程上 RL 不足）；上下文上限导致截断 |
| 训练监控：回答长度、奖励、策略熵、生成概率 | 训练是否健康 | DAPO 图 7 把这四条曲线作为发现问题的主要指标；熵过低探索停止，过高出现乱码与重复 |
| token 效率 | 同样质量用多少 token | V3.2 与 Gemini-3.0-Pro 的对比；k1.5 的 long2short |

评测目标的迁移：2024 年以 GSM8K、MATH 为主；2025 年转向 AIME、Codeforces、GPQA Diamond、LiveCodeBench；`[判断]` 2025 年下半年起，K2、V3.2、K3 的评测中，SWE-bench、工具使用与智能体任务占了越来越大的篇幅，V3.2 的引言把智能体场景的泛化列为开源模型三大不足之一。

## 当前开放问题

- **RL 能否探索出基座之外的推理？** Yue 等认为需要更好的探索、更细的信用分配与多轮交互；Cui 等认为瓶颈在熵。入口：[Yue 等](../../../papers/arxiv-2504.13837/README.md)、[Cui 等](../../../papers/arxiv-2505.22617/README.md)、[DAPO](../../../papers/arxiv-2503.14476/README.md)。
- **长思维链与长程智能体的信用分配怎样做？** k1.5 结论写明要研究信用分配、在不损害探索的前提下减少过度思考；K3 的轨迹跨越多次迭代。入口：[Kimi k1.5](../../../papers/arxiv-2501.12599/README.md)、[Kimi K3](../../../papers/arxiv-2607.24653/README.md)。
- **稳定性补丁有没有统一原理？** V3.2 的四处修补、DAPO 的四项技巧、K3 的逐 token 正则各解决一个现象。入口：[DeepSeek-V3.2](../../../papers/arxiv-2512.02556/README.md)。
- **不可验证任务的 RL 奖励从哪来？** 见[偏好学习方向](../preferences/README.md)第 5 节。
- **RL 的规模规律能外推多远？** ScaleRL 的 S 形曲线在 8B 与 Scout MoE、以数学为主的验证集上成立；作者把分布外泛化、算力在预训练与 RL 之间怎样分配列为未解决。入口：[ScaleRL](../../../papers/arxiv-2510.13786/README.md)。
- **多领域同时 RL、顺序 RL 加蒸馏、专家加蒸馏，哪种更好？** 三种做法分别来自 Nemotron 3、GLM-5、DeepSeek-V4 与 Kimi K3，各自只与本团队的旧做法比较。入口：[Nemotron 3](../../../papers/arxiv-2512.20856/README.md)、[GLM-5](../../../papers/arxiv-2602.15763/README.md)、[DeepSeek-V4](../../../papers/arxiv-2606.19348/README.md)。

## 批注

**易误读**

- R1-Zero 的 77.9% 是 AIME 2024 的 pass@1（温度采样多次平均），用自洽投票为 86.7%（R1 §2.3）；最终 R1 为 79.8%（Table 3）。
- R1 第一轮 RL 的 GRPO 裁剪比率设为 10，远大于 PPO 常用的 0.2；作者写明比率太小会截断大量 token 的梯度、太大会不稳定（§3.2.1）。PPO 的 ε 不能直接搬过来比较。
- GRPO 中的 KL 是对参考模型的正则，R1-Zero 每 400 步把参考模型换成最新策略（§2.1）；它和 PPO 裁剪约束的新旧策略是两件事（[PPO 精读](../../../papers/ppo/reading.md)批注）。
- DAPO 的 30 → 50 分是在 Qwen2.5-32B 基座、数学数据上逐项累加的结果（表 1）；token 级损失只加了 1 分，作者看重的是它让长度增长更健康。
- Yue 等与 DeepSeekMath 的结论不等于"RL 无用"：k = 1 时 RL 模型更好，而用户通常只采一次。

**判断的支撑论文**

- 问题链（PPO 太重 → 去价值模型 → 验证器 → 三类坑 → 造专家）：DeepSeekMath §4.1、R1 §2.2 与附录 G.2、k1.5 §2.3.2、DAPO §1 与 §3、Dr. GRPO §3.1、Cui 等 §1、V3.2 §3、V4 §5.1、K3 §4.1。边界：Tulu 3 在 RLVR 中仍用 PPO 与价值模型并得到提升。
- "RL 造专家、蒸馏做统一模型"：V3.2 §3（专家蒸馏 + 混合 RL）、V4 §5.1.2（混合 RL 换成 OPD）、K3 §4.1.3、Qwen3 §4.5。反例：V3.2 的最终模型仍做了数千步混合 RL。
- 团队偏好：DeepSeek 自 DeepSeekMath 起在 V2、V3、R1、V3.2、V4 都用 GRPO；Kimi 在 k1.5、K2 都不用价值网络，K2、K3 都显式控制 token 预算；Qwen3 在推理 RL 与小模型蒸馏之间明确选了后者。
- 2025-10 以后的补充：CISPO 的两次独立选用见 MiniMax-M2 §6.1.4 与 ScaleRL 的损失对比；"训练—推理不一致成为一类问题"见 ScaleRL（FP32 logits）、GLM-5（确定性 top-k、TITO 网关）与 V3.2 §3（Keep Routing）。MiniMax 与 Meta 都只出现一次，按本库标准还不能算团队偏好。

与原结论的张力（不改原判断，列出供核对）：
- 主要路线表中 AI2 一行写"在 RLVR 中保留 PPO 与价值模型"，依据是 2024 年的 Tulu 3；2025-12 的 Olmo 3 已改用 GRPO 变体（§4.4.1），Tulu 3 作者当时在未来工作中建议试 GRPO，这一建议被兑现。AI2 一行描述的是 2024 年的选择。
- 第 6 节与上文"收敛：按领域训练专家再合并"一条，在 Nemotron 3 处有反例：它在所有环境上同时 RL，并称比分阶段更稳（§2.6）。GLM-5 也没有用"专家加蒸馏"，而是顺序 RL 之后再蒸馏。"专家加蒸馏"目前是 DeepSeek 与 Kimi 两家的选择，不是全行业的收敛。

**与其他论文的关联**

- [PPO 精读](../../../papers/ppo/reading.md)：裁剪目标的原始实验与超参数（MuJoCo、Atari），本页的 GRPO、DAPO 都在改它的某一项。
- [偏好学习方向](../preferences/README.md)：RLHF 中的奖励模型与 2025 年以后的生成式奖励模型。
- [推理时计算方向](../../inference/README.md)：o1、R1、k1.5 的测试时扩展；过度思考与 long2short。
- [模仿学习与机器人强化学习](../../../../robotics-embodied/fields/imitation-reinforcement-learning/README.md)：PPO 在腿足上的用法、"RL 回到模仿之上"的阶段与 SimpleVLA-RL。

**未核实 / 待验证**

- Kimi K2 的 RL 目标式中正则项的具体形式，本轮只读到"一个促进稳定学习的正则参数"，未逐符号核对；K3 引用的 Kimi K2.5 算法报告本轮未打开。
- GRPO 在 DeepSeek-V3 中的具体超参数本轮未核对，正文只写"沿用"。
- 已知存在但本轮未打开原文：MiniMax-M1 报告（CISPO 最早可能出自这里，未核实）、Qwen 的 GSPO（arXiv 2507.18071，只读了摘要：把重要性比率与裁剪改到序列级，称能稳定 MoE 的 RL）、Nemotron 3 Super 与 Ultra 的单独报告（arXiv 2604.12374、2606.15007）、Meta Muse Spark 的技术细节（只有官方博客）。Kimi K2.5 的 RL 目标已在[卡片](../../../papers/arxiv-2602.02276/README.md)中核对：沿用 k1.5 与 K2 的策略优化，并屏蔽对数比区间外 token 的梯度。
