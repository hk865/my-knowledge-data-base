# 语言模型强化学习路线图

> 状态：路线图 · v1

[入门页](README.md) · [Baseline](BASELINES.md) · [论文目录](PAPERS.md) · [后训练总览](../README.md)

结论：五步，按"先把 PPO 搬到 token 上 → 看 GRPO 为什么去掉价值模型 → 读两份大规模 RLVR 报告 → 看复现时补出的坑 → 看规模化与蒸馏合并"排列。读者已有四足 RL 经验，每一步都附一个可以对照机器人做法的检验。

## 第 1 步：把 PPO 搬到 token 上

读 [PPO 精读](../../../papers/ppo/reading.md)，再读 [InstructGPT 精读](../../../papers/instructgpt/reading.md)第 6–8 节；基础见[强化学习讲义](../../../../foundations/lessons/05b-reinforcement-learning.md)第 7、9 节。

为什么在这里：这是 [Baseline 页](BASELINES.md)的第一个基线。读者熟悉 PPO 在腿足上的用法，这一步只需看清对象换成 token 后多了什么：参考模型的 KL、从奖励模型初始化的价值模型、PPO-ptx。

检验：画出一次 RLHF 迭代里当前策略、采样时的旧策略、参考模型、奖励模型、价值模型各做什么、哪些在更新、哪些只在训练时存在（部署时只剩策略）；说清"PPO 裁剪约束的新旧策略"与"KL 惩罚约束的参考模型"是两件事（PPO 精读批注）。再在一个简单环境里去掉裁剪或改内层 epoch 数，同时看回报、近似 KL、熵与价值误差怎样变化。

## 第 2 步：为什么去掉价值模型

读 [DeepSeekMath](../../../papers/arxiv-2402.03300/README.md)第 4.1 与 5.2 节，对照 [Kimi k1.5](../../../papers/arxiv-2501.12599/README.md)第 2.3.2 节。

为什么在这里：两家给出了去掉价值模型的两种理由（显存与"只有末尾奖励时价值难学"；价值函数会惩罚走错再纠正的轨迹）；§5.2.2 的 Maj@K 与 Pass@K 是后面"RL 边界"讨论的起点。

检验：给一组 4 个回答的奖励 [1, 0, 0, 1]，手算 GRPO 的组内优势（减均值、除以标准差）；再想一想，为什么腿足 PPO 里你不会用"同一初始状态重复采样 4 次"来代替价值函数。

## 第 3 步：两份大规模 RLVR 报告

读 [DeepSeek-R1](../../../papers/arxiv-2501.12948/README.md)第 2–3 节、附录 B.5、F、G，对照 [Kimi k1.5](../../../papers/arxiv-2501.12599/README.md)第 2.1–2.4 节；o1 只看 [o1 文献卡](../../../papers/openai-o1/README.md)写明的部分。

为什么在这里：这是 GRPO 规模化的出处；两家独立做出相同选择（规则奖励、无价值模型、无 PRM 与 MCTS），也各自记录了坑（语言混杂、奖励黑客、过度思考、能猜中的题）。

检验：列出 R1 从 R1-Zero 到最终 R1 的五个检查点，说出每一步改了什么、哪项评测升降（Table 3）；解释 k1.5 为什么剔除选择题和"不推理就能猜中"的题。

## 第 4 步：复现时补出的坑

读 [DAPO](../../../papers/arxiv-2503.14476/README.md) → [Dr. GRPO](../../../papers/arxiv-2503.20783/README.md) → [Cui 等](../../../papers/arxiv-2505.22617/README.md) → [Yue 等](../../../papers/arxiv-2504.13837/README.md)。

为什么在这里：四篇分别对应 [Baseline 表](BASELINES.md)中的裁剪、损失聚合、优势估计、评测口径四行；它们把"RL 涌现推理"的叙事修正为"RL 放大基座已有的正确路径"。

检验：用 DAPO 的例子（旧概率 0.01 与 0.9，ε = 0.2）算出两个 token 能被提到的上限，说明为什么上界会压住探索；再说明 GRPO 按长度归一化时，同为错误的长回答与短回答，哪个每个 token 受罚更轻。

## 第 5 步：规模化与蒸馏合并

读 [Qwen3](../../../papers/arxiv-2505.09388/README.md)第 4 节 → [Kimi K2](../../../papers/arxiv-2507.20534/README.md)第 3.2 节 → [DeepSeek-V3.2](../../../papers/arxiv-2512.02556/README.md)第 3 节 → [DeepSeek-V4](../../../papers/arxiv-2606.19348/README.md)第 5.1 节与 [Kimi K3](../../../papers/arxiv-2607.24653/README.md)第 4.1 节。

为什么在这里：这是当前形态：RL 的算力到了预训练的一成以上，靠一组稳定性补丁撑住；多领域合并从混合 RL 转向 on-policy 蒸馏；智能体环境带来新的奖励黑客。

检验：说出 V3.2 四项稳定性修改各防哪种问题，其中哪一项只对 MoE 有意义；比较 V4 与 K3 的蒸馏目标，各自给出的理由是什么。

## 动手时先查什么

自己跑 GRPO 一类训练时，先看四条曲线：奖励、平均回答长度、策略熵、生成概率（DAPO 图 7 的做法）；熵很快掉到接近 0 说明探索停了，熵持续上升往往伴随乱码与重复。再查三件事：奖励能否被不写推理就猜中（k1.5 的剔除法）；训练框架与推理引擎算出的对数概率是否一致（V3.2 的离策略问题）；每批里有多少题组全对或全错、优势为 0（DAPO 的动态采样）。基座太小时先别指望纯 RL：R1 在 7B 稠密与 16B MoE 上没有成功。
