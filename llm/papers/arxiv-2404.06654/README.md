# RULER: What's the Real Context Size of Your Long-Context Language Models?

> 状态：文献卡 · 2024 · [原文](https://arxiv.org/abs/2404.06654)

[返回大语言模型目录](../../README.md) · [原文与阅读记录](source.json)

- **解决什么**：长上下文模型普遍用大海捞针（在长文本里埋一句话让模型找回）证明自己的窗口，原文认为这只反映表层的检索能力，说明不了模型能否在长输入上追踪、聚合、推理（摘要、§1）。
- **核心方法**：可控的合成评测：在检索之外加入多针与多值检索、变量追踪（多跳）、高频词与常见词统计（聚合）、在长干扰文本中做问答，共四类 13 个任务，长度从 4K 到 128K 可调。以 Llama2-7B 在 4K 上的 85.6% 为阈值，模型能保持在阈值之上的最大长度叫"有效上下文长度"。评测的 17 个模型都声称支持 32K 以上，摘要写明只有一半能在 32K 保持令人满意的表现；GPT-4 声称 128K、有效长度 64K，Gemini-1.5-Pro 超过 128K（Table 3）。
- **为什么在这个库里**：[长上下文方向](../../fields/long-context/README.md)"用什么衡量进展"的中间层：比大海捞针难、比真实长文任务可控，Qwen2.5-1M、Gated Attention、Kimi Linear 等报告都以它为主要长上下文指标。自述局限：不控制证据位置、与真实任务的相关性未验证、没有短上下文评测、没有检验提示鲁棒性（§8）。优先级：必读。
