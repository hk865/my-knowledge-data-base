# The Llama 3 Herd of Models

> 状态：文献卡 · 2024 · [原文](https://arxiv.org/abs/2407.21783)

[返回大语言模型目录](../../README.md) · [原文与阅读记录](source.json)

- **解决什么**：做一组原生支持多语言、代码、推理与工具使用的开放基座模型。作者把开发过程归结为三个杠杆：数据、规模、管理复杂度；旗舰 405B 模型训练了 15.6T token，用了 3.8×10²⁵ FLOPs，比 Llama 2 最大版本多近 50 倍。
- **核心方法**：相对 Llama 2，主要改数据与规模，结构只做小改动。为了最大化训练稳定性，选标准稠密 Transformer 而不用 MoE（混合专家，每个 token 只激活少数几个专家 FFN），用 GQA（分组查询注意力，几个查询头共享一组 K、V，这里 8 个 KV 头），RoPE 基频提到 500,000。预训练分三段：8K 上下文的主训练；约 800B token 分六级把上下文从 8K 加到 128K，每一级以"短上下文评测完全恢复、该长度的大海捞针全部答对"判断是否适应；最后 40M token 把学习率线性降到 0，同时上采样极高质量的数据（退火），并对退火期间的检查点取平均。数据配比用知识分类器和小模型的规模定律确定，最终约 50% 通用知识、25% 数学与推理、17% 代码、8% 多语言；评估一个小数据集值不值得加入，用"训练到一半的 8B 模型在 40B token 上退火、新数据占 30%"的办法。下游表现分两步预测：先拟合正确答案的负对数似然与训练 FLOPs 的关系，再拟合负对数似然与准确率的关系。
- **为什么在这个库里**：[预训练方向](../../fields/pretraining/README.md)的稠密基线（[Baseline 页](../../fields/pretraining/BASELINES.md)"基线是谁"一节）。"预训练与后训练的分工"一节引用它对预训练的表述：模型在这一阶段学到语言结构，并获得大量关于世界的知识；"更多知识""中途评估"两节引用它的配比、退火与下游预测。它也写出两个做不好的场景：用 GSM8k、MATH 训练集退火，8B 分别提高 24.0% 和 6.4%，405B 几乎没有提升；54 天里 466 次作业中断，419 次是意外，约 78% 与硬件有关。优先级：必读。
