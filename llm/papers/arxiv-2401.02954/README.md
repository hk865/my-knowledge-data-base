# DeepSeek LLM: Scaling Open-Source Language Models with Longtermism

> 状态：文献卡 · 2024 · [原文](https://arxiv.org/abs/2401.02954)

[返回大语言模型目录](../../README.md) · [原文与阅读记录](source.json)

- **解决什么**：Kaplan 等（2020）与 Chinchilla（2022）两套规模定律对"算力增加时模型与数据怎样分配"给出了不同结论，而且都没有交代批量大小、学习率怎样随规模设定；开源社区多数只训练固定尺寸（7B、13B、70B）的模型，缺少自己的规模研究。
- **核心方法**：结构沿用 LLaMA（预归一化、SwiGLU、RoPE），67B 用分组查询注意力 GQA，并把参数加在深度上（95 层）而不是加宽 FFN。相对前作改了三处：一是用三段阶梯学习率（80%、10%、10% 的 token 处各降一次）替代余弦衰减，最终效果与余弦相当，第一段可以直接复用于更长的继续训练；二是先拟合"最优批量与学习率随算力变化的幂律"，再用 Chinchilla 的 IsoFLOP 方法拟合模型与数据的分配，模型规模改用不含嵌入的每 token FLOPs 表示，用最多 3e20 FLOPs 的小实验准确预测了 7B、67B（约 1000 倍算力）的验证损失；三是发现数据质量越高，新增算力越应分给模型（模型规模指数从早期自有数据的 0.450 升到 OpenWebText2 上的 0.578），作者认为这可能是此前各家结论不一致的原因。讨论一节记录了一个反例：微调时加入 2000 万道中文选择题，MMLU 从 49.4 升到 60.9，生成式问答 TriviaQA 保持 57.9 不变，作者因此在预训练和微调中都不使用选择题数据。
- **为什么在这个库里**：[预训练方向](../../fields/pretraining/README.md)"开源团队把规模科学做细"一节的起点，也是"中途评估"手段的代表：先用小模型定超参与配比，再训练大模型，并把选择题与生成题分开看。DeepSeek 后续的 [DeepSeekMoE](../arxiv-2401.06066/README.md) 与它用同一份 2T 语料对照，[DeepSeek-V2](../deepseek-v2/README.md) 以它的 67B 模型为成本对照。优先级：必读。
