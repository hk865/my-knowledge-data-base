# The MiniMax-M2 Series: Mini Activations Unleashing Max Real-World Intelligence

> 状态：文献卡 · 2026 · [原文](https://arxiv.org/abs/2605.26494)

[返回大语言模型目录](../../README.md) · [原文与阅读记录](source.json)

- **解决什么**：用很小的激活参数做长程智能体（写代码、办公任务、深度搜索）：智能体轨迹长、长短差异大，RL 系统要能吞下这种轨迹，奖励要能对齐真实产物。
- **核心方法**：229.9B 总参数、每 token 激活 9.8B 的 MoE（256 个专家激活 8 个，sigmoid 门控，带 MTP）。注意力在全部 62 层都用全注意力（GQA，8 组 KV），放弃了前代 MiniMax-Text-01 的 Lightning Attention 混合；作者在数千亿到数万亿 token 上试过多种滑动窗口混合，标准评测上看似持平，复杂多跳推理、检索与上下文学习上却明显变差，SFT 后在 32K 以上差距更大，且线性与稀疏注意力的基础设施不成熟（§2.2.2）。RL 用 CISPO（只裁剪重要性权重本身、权重不回传梯度，下界为 0，允许大幅压低已变得不可能的动作）；Forge 系统用"窗口内贪心、窗口间先进先出"的调度吸收轨迹长度差异，用前缀树合并共享前缀的多条轨迹（正文称训练最多快 40 倍）。奖励由过程奖励（惩罚语言混杂与工具格式错误）、完成时间奖励（鼓励并行执行）与结果奖励组成。推理时采用交错思考：每轮的思考与工具调用都保留在历史里，消融中把以前各轮的思考块剥掉会在智能体评测上一致变差，深度搜索与软件工程任务最明显（§7.1）。
- **为什么在这个库里**：[强化学习方向](../../fields/posttraining/rl/README.md)"智能体 RL 系统"一格的代表，[长上下文方向](../../fields/long-context/README.md)"线性或稀疏混合是否成为默认"一问的反例，也是[推理时计算方向](../../fields/inference/README.md)"跨轮保留思考"的证据。优先级：选读。

## 批注

**易误读**
- 放弃高效注意力是 M2 在其规模与任务上的结论；作者同时写明，随上下文变长、GPU 算力增长放缓，次平方注意力会越来越重要，他们在为这一转变准备数据、评测与基础设施（§2.2.2）。
- "最多快 40 倍"是前缀树合并在共享前缀很长的智能体轨迹上的上限，不是整体训练吞吐。

**未核实 / 待验证**
- 交错思考消融的具体分数未逐项核对；系列中 M2、M2.5、M2.7 各版本的发布日期报告未给出。
