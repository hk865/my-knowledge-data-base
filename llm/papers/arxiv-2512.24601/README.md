# Recursive Language Models

> 状态：文献卡 · 2025 · [原文](https://arxiv.org/abs/2512.24601)

[返回大语言模型目录](../../README.md) · [原文与阅读记录](source.json)

- **解决什么**：即使在上下文窗口之内，模型的表现也会随输入变长、任务变复杂而下降（作者称为 context rot）；超出窗口的输入则只能靠截断、压缩摘要或检索，丢掉的信息找不回来。
- **核心方法**：不把长提示直接送进网络，而是放进一个 Python REPL 环境，作为一个字符串变量；模型只看到长度、开头片段等元信息，自己写代码去查看、切分、筛选这段文本，并可以调用 `llm_query()` 在选出的片段上递归调用自己（或另一个模型），只有被截断的执行输出回到它的上下文；设置 `Final` 变量即结束。实验用 GPT-5 等模型做外层，在四类任务（单针检索 S-NIAH、1000 篇文档上的 BrowseComp-Plus、需要线性聚合的 OOLONG、需要两两配对的 OOLONG-Pairs）上比较：基座模型的表现随长度与任务复杂度下降，RLM 在 2²⁰ token 以上仍保持，能处理超出窗口两个数量级的输入；例如 OOLONG-Pairs 上 GPT-5 直接作答 0.1%，RLM 为 58.0%。中位成本与基线相当或更低，但少数轨迹会反复调用、成本方差大。作者还用 1000 条筛选过的 RLM 轨迹微调 Qwen3-8B（RLM-Qwen3-8B），四个任务上比原模型中位提升 28.3%。
- **为什么在这个库里**：[长上下文方向](../../fields/long-context/README.md)"窗口之外怎么办"一线的代表：把长上下文从模型结构问题改写成推理时的程序问题，与[推理时计算方向](../../fields/inference/README.md)的智能体式多算相连。MIT 的学术工作，代码开放。优先级：选读。

## 批注

**易误读**
- "超出窗口两个数量级"指外层模型每次只读元信息和片段，并没有改变模型自身的上下文窗口；效果依赖外层模型的写代码能力，作者写明代码能力不足的模型当不好 RLM。

**未核实 / 待验证**
- 作者列出的局限：子调用同步阻塞、递归深度实验以 1 为主、子调用成本可能失控、输出 token 不足的思考模型会失败；各基线（压缩、检索）的完整数字未逐项核对。
