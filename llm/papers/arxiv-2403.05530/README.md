# Gemini 1.5: Unlocking multimodal understanding across millions of tokens of context

> 状态：文献卡 · 2024 · [原文](https://arxiv.org/abs/2403.05530)

[返回大语言模型目录](../../README.md) · [原文与阅读记录](source.json)

- **解决什么**：当时的上下文窗口最大是 Claude 3 的 200K、GPT-4 Turbo 的 128K；要让一个模型直接读入整本书、几小时的视频或音频，并在其中检索和推理（摘要、§1）。
- **核心方法**：报告只写明 Gemini 1.5 Pro 是稀疏 MoE Transformer，长上下文靠"一系列重要的架构改动"，不给细节（§3.1）。文本大海捞针在 530K 内 100%、1M 超过 99.7%、10M 为 99.2%，视频（10.5 小时）与音频（107 小时）同样接近满分（§5.2.1）。只给一本约 250K token 的卡拉曼语语法书和词表，英译卡拉曼语的人工评分 5.46，接近学习了同样材料的人类的 5.60（Table 5）。同时承认单针测试不够：插入 100 根针时，128K 以内召回约 70%，到 1M 约 60%以上（§5.2.1.5），并在讨论中呼吁用多针与需要复杂推理的新评测（§10）。
- **为什么在这个库里**：[长上下文方向](../../fields/long-context/README.md)"百万窗口"阶段的起点：闭源模型第一次把窗口推到 1M 以上，也第一次在官方报告里指出单针大海捞针不足以评测长上下文；它用的 MRCR 后来进入 DeepSeek-V4 的长上下文评测。架构与训练配方不公开，只能作为能力与评测的参照。优先级：选读。
