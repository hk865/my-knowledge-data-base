# DeepSeek-V4.1-Flash：KV 再沿层与精度各压一次，长程智能体的缓存小到可以常驻

> 状态：技术精读 · 原文 arXiv:2609.19969v1 · 未复现

## 一句话

DeepSeek-AI（2026 年 9 月）在 V4-Flash 之上，从三个层面压 KV 缓存：结构上让多层共用同一份全局 KV 与选读结果（CSA2），并让后一半层的全局 KV 直接由前一半的输出投影得到（因果编码器-解码器 CED）；精度上把全局 KV 存成 FP4；部署上不再持久化滑窗 KV，缺失时只近似重算最近 128 个 token。结果是全局 KV 每 token 890 字节，约为 V4-Flash 的 1/4，持久化缓存约为 1/8。模型有 552B 骨干参数加 196B 的 Engram 查表参数，预填充每 token 激活 8B、解码激活 16B，在 45T token 的图文语料上预训练。

## 它要解决的问题

[DeepSeek-V4](../arxiv-2606.19348/reading.md) 已经把 1M 上下文下的单步计算降到 V3.2 的 10%–27%。作者认为瓶颈随之移位（摘要、§1）：长程智能体的工作负载以输入为主，每次工具调用都追加一段新输入。

- **预填充**（prefill，一次性处理整段输入、生成它的 KV）在前缀缓存未命中时仍然昂贵。
- **KV 的存放与搬运**：全局 KV 常驻显存（HBM），限制并发；为前缀复用而持久化的 KV 占满 SSD 与主机内存，搬运又受 I/O 与互联带宽限制。

V4 在部署中暴露了一个具体的坑：持久化缓存里，滑窗 KV 占了将近一半；V4 报告提出的"不存滑窗 KV、命中后精确重算"需要重算 L × n_win 个 token，在生产中代价过高（§3.2.1）。

## 核心想法

**V4 压的是"位置条数"（沿序列合并 token），V4.1 改压"层数"与"每条的位宽"，并接受部署时的近似。** 作者在 §2.3 把 KV 压缩拆成三个相乘的维度：每条的大小（GQA、MLA 压这一维）、序列方向（V4 的 CSA/HCA）、层方向（若干层共用一份缓存）。V4.1 第一次同时压三维，而序列方向反而放松了：压缩率从 4 和 128 降到 2 和 1。

相对 V4-Flash 的部件变化：

| 部件 | V4-Flash | V4.1-Flash |
|---|---|---|
| 层组织 | 43 层，每层自算全局 KV（前两层只有滑窗） | 40 层：20 层因果编码器 + 20 层解码器，解码器全局 KV 由第 20 层输出投影 |
| 全局注意力 | CSA（m = 4，重叠压缩）与 HCA（m′ = 128）交错 | 只有 CSA2：编码器 m = 2、解码器 m = 1，无重叠、无绝对位置偏置；每组只有一层算 KV，其余层复用 KV 或连选读结果一起复用 |
| 索引器 | 每个 CSA 层扫描全部历史 | 解码器内分层索引：后面的层只在前面选出的 16,384 个候选里打分 |
| 全局 KV 精度 | 448 维 FP8 + 64 维 BF16 | FP4（每 16 维一个 E4M3 缩放），滑窗 KV 保持 FP8 |
| 残差 | mHC | Single-Pass mHC：输入混合系数用上一块的，访存减半 |
| 记忆 | 无 | [Engram](../arxiv-2601.07372/README.md)，196B 参数，放在第 1、14 层，去掉原设计中的短卷积 |
| 投机解码（小草稿器先猜几个 token，主模型一次验证） | MTP 与骨干一起预训练 | 骨干去掉 MTP；DSpark 草稿器在预训练后单独训练 |
| 优化器 | Muon（对梯度动量矩阵近似正交化后再更新）+ AdamW | Q、K 权重按头分块做 Muon；嵌入、输出头、Engram 表改用"动量 + Sinkhorn 行列均衡"的更新，省掉 Adam 的状态 |
| 训练课程 | 32T token，先稠密预热再转稀疏 | 45T 图文 token，稀疏注意力在 64K 上从头训练，34T 处扩到 1M；原文称全程没有不稳定 |
| 模态 | 文本 | 原生图文输入（自训 DeepSeek-ViT，文本与多模态 token 比 7:1） |

## 机制

### 1 CSA2：三种模式，按组共用

每个 CSA2 层静态地属于三种模式之一（§2.3.1）：

- **Full**：自己算主 KV，从主 KV 投影出索引键，自己打分选 top-512。
- **Reindex**：复用前面最近一个 Full 层的主 KV 和索引键，只用自己的索引查询重新打分、重新选。
- **Reuse**：连 top-k 下标也复用，直接做稀疏注意力。

三种模式下，每层都保留自己的查询和自己的滑窗 KV，所以各层的输出仍然不同。编码器除前两层滑窗层外的 18 层分为 3 组，每组 6 层，首层 Full、其余 Reuse；解码器 20 层分为 5 组，每组 4 层，第一组首层 Full，其余四组首层 Reindex，其余全是 Reuse（§4.2.1）。官方配置中产生 KV 的层是第 2、8、14、20 层（从 0 计数）。

解码器内还有分层稀疏索引器（§2.3.2）：第一个 Full 层按块取最高分，选 2,048 个块、每块 8 个位置，组成 16,384 个候选；之后的 Reindex 层只在这些候选里打分。它在后训练阶段引入，训练与推理用同样的候选限制。

### 2 CED：后一半层的全局 KV 不必算完整个网络

受 [YOCO](https://arxiv.org/abs/2405.05254)（Sun 等 2024，上半部分层直接共用下半部分生成的 KV）启发，第 l > L/2 层的全局 KV 与压缩权重都由第 L/2 层的隐藏状态 H_{L/2} 加各层自己的投影得到（式 1）。预填充一段输入时，只要跑完前 20 层就拿到了所有层需要的全局 KV。滑窗 KV 仍由每层自己的隐藏状态产生，所以解码器还要处理最后 n_win 个 token（见第 6 小节）。

示例数值：一段 100K token 的新输入，标准做法要算 100K × 40 = 400 万"层·token"；CED 算编码器 100K × 20 加解码器 128 × 20，共约 200.3 万，即约 50%。原文据此称预填充计算减半，复杂度从 O(NL) 降到 O(NL/2 + n_win·L/2)（§2.2）。

### 3 FP4 全局 KV

全局 KV 用 E2M1（4 位浮点）存储，每 16 个通道一个 E4M3（8 位浮点）缩放因子，即 NVFP4（NVIDIA 的 4 位浮点格式）去掉第二级全局缩放（§2.4.4）。去掉全局缩放的理由是数值范围够用：这种格式最大可表示 448 × 6 = 2,688；而 KV 经过 RMSNorm、RMSNorm 权重最大约 1，512 维向量的 L2 范数不超过约 √512 ≈ 22.6，RoPE 旋转不改变范数，训练中观测到的最大值约 10。量化放在 RoPE 之后，在后训练中做量化感知训练。滑窗 KV 对量化敏感，保持 FP8。

### 4 KV 缓存的账（示例数值）

条目格式取自官方 FlashMLA 说明：V4.1 的 FP4 条目 288 字节（256 字节数据 + 32 个缩放），V4 的条目 584 字节；索引键按 128 维 MXFP4（64 + 4 字节）计，这是我的假设。

| | V4-Flash | V4.1-Flash |
|---|---|---|
| 每 token 的全局 KV 条数 | 21 层 CSA × 1/4 + 20 层 HCA × 1/128 ≈ 5.41 条 | 编码器 3 层 × 1/2 + 解码器 1 层 × 1 = 2.5 条 |
| 每条主 KV + 索引键 | 584 + 68（HCA 无索引键） | 288 + 68 |
| 全局 KV 字节/token | 3,514 | 2.5 × 356 = 890 |
| 1M（10⁶）token | 约 3.5 GB | 约 0.89 GB |
| 持久化缓存 | 全局 KV + 滑窗 KV（后者约占一半） | 只存全局 KV |

890 与 3,514 都与原文图 1(b) 逐字节吻合。拆开看，3.95 倍的缩小来自两项：条数从 5.41 降到 2.5（约 2.2 倍），每条（按 CSA、HCA 加权平均）从约 650 降到 356 字节（约 1.8 倍）。层方向的共用抵消了序列方向的放松：V4.1 解码器的全局 KV 完全不压缩（m = 1），20 层却只存一份。持久化缓存的 1/8 是两项相乘：去掉滑窗 KV 约省一半，全局 KV 再降到 1/4（§3.2.1）。三代对比（V2、V3.2、V4）见 [V4 精读](../arxiv-2606.19348/reading.md)第 4 小节。

### 5 为什么解码计算几乎不随长度涨（示例数值）

上下文 L = 1,048,576，解码一个新 token：

- 需要扫描全部历史的只有 4 个 Full 层：编码器 3 层各打分 L/2 = 524,288 条，解码器 1 层打分 1,048,576 条；4 个 Reindex 层各只打分 16,384 个候选；合计约 269 万次，索引头 32 个。
- 其余 38 层的主注意力每层读 512 + 128 = 640 条，与长度无关。

V4-Flash 的对应数字是 21 层 × 262,144 ≈ 550 万次、索引头 64 个，主注意力合计约 18 万条（HCA 层随长度增长）。按"打分次数 × 索引头数"算，V4.1 约为 V4-Flash 的 1/4。原文图 2 给出的结果是：上下文从 4K 增到 1M（256 倍），V4.1-Flash 的单 token 解码 FLOPs 只增加 1/4。从同一张图还能读出，4K 处 V4.1 的解码 FLOPs 略高于 V4-Flash（激活 16B 对 13B），两条曲线在 64K–256K 之间交叉。

### 6 滑窗有界重放：用近似换掉落盘

滑窗注意力的依赖逐层累积：第 l 层的滑窗 KV 依赖上一层最近 n_win 个位置，所以精确重建 L 层的滑窗 KV 要重放 L × n_win 个 token。V4.1 只重放最近 n_win 个，并把滑窗截断在重放段内：起点为 s 的重放中，位置 i 的查询只看 [max(s, i − W + 1), i]（§3.2.2）。

示例数值：n_win = 128、L = 40，精确重建要重放 5,120 个 token，有界重放只要 128 个，约 1/40。

两处用法：

- **编码器侧**：滑窗 KV 不再进持久化缓存，改放在每台机器 10% 主机内存组成的池里，存活几分钟；全局 KV 留在持久化缓存里，保证至少 72 小时。命中全局 KV 而滑窗 KV 已被淘汰时，用有界重放补回。
- **解码器侧**：每次预填充都只让最后 128 个 token 走解码器，生成的解码器滑窗 KV 只用于本次解码、不缓存。后训练中模拟同样的重放，让模型适应。

作者写明，近似重建的状态与完整前向不等价，后续 token 的全局 KV 与滑窗 KV 会依赖缓存命中的位置。

### 7 其余扩展

- **Single-Pass mHC**：原 mHC 的三步（残差更新、由残差预测系数、输入混合）有数据依赖，实现上总访存为 (4n + 4)d。把输入混合系数改用上一块预测的 A_{l−1}，三步可在一次遍历里完成，访存降到下界 (2n + 2)d；n = 4 时每层从 20d 降到 10d。作者称性能损失可忽略（§2.4.1）。机制背景见 [mHC](../arxiv-2512.24880/README.md)。
- **Engram**：两个模块各 98B，N-gram 阶数 2、3、4，每阶 8 个哈希头，每头约 1,600 万条，表与投影都用 FP8；查表地址只取决于输入 token，推理时可从主机内存提前预取（§2.4.2）。
- **DSpark**：3 个 Transformer 块的草稿器，一次前向给出 5 个草稿位置，配置信度头按系统负载决定每个请求验证多长（§2.4.3）。

## 局限与后续

原文 §6 自述：新结构带来的鲁棒性边界还没有完全刻画；内部评测没有发现系统性退化，但有限的测试覆盖不了所有极端输入，CSA2 的选择误差和有界重放的近似状态可能在未测试的边界情形下损害能力；下一步重点压力测试长上下文的稀疏检索，以及缓存恢复边界处的滑窗状态重建。另外承认与最强闭源模型在最难任务上仍有差距，基准分数接近不代表能力相当。

**做不好的场景（原文写明）。** 需要专家级领域知识的科学类智能体任务差距明显：Terminal-Bench 4.0 为 31.2，Opus-5 为 51.8；漏洞利用类 ExploitGym（网络安全类智能体基准）为 15.3，GPT-5.6 Sol 为 33.7（表 3）。同一检查点换智能体框架，DeepSWE 在 65.5（OpenCode）到 74.2（mini-SWE）之间变化（表 4）。评测中观察到钻空子行为，例如在 CyberGym 中反编译 Ubuntu 系统包找漏洞（§5.3.1）。思考预算的最后一档提到 100 时，智能体轨迹变长 1.6–1.8 倍，准确率只微增（§5.3.2）。

**原文没有披露的。** 压缩各部件（CSA2 复用、FP4 KV、有界重放、CED、分层索引）的逐项消融；V4 报告过的 MRCR、CorpusQA 等 1M 检索评测，V4.1 一项也没有报告，长上下文只有基座的 LongBench-V2；实测的首 token 时延、每 token 时延与吞吐（只有每层核函数个数：Reuse 层预填充 15 个、解码 11 个）；训练算力与硬件；是否保留 V4 的哈希路由、Anticipatory Routing 与 attention sink。

**站在现在看。** `[判断]` 三点值得留意。

- **"可复现"让位于"能部署"。** V4 花了一整节做逐位可复现的核函数，并强调预训练、后训练、推理逐位对齐（V4 §3.3）；V4.1 的有界重放让同一段输入的输出取决于缓存在哪里命中，作者为此在后训练中模拟重放。依据：V4 §3.3 与本篇 §3.2.2。
- **选择误差成为主要风险，而且放大了。** 编码器每 6 层共用一份 top-k，解码器 20 层的候选全部来自第一个 Full 层，这一层若漏选，后面的层都读不到；V4 的 HCA 层"全部读"的兜底被去掉。原文 §6 把选择误差列为第一项风险，却没有给出 1M 检索评测。依据：§2.3.1、§6，以及 V4 图 9 中 128K 之后检索已在下降。
- **同期其他团队的取舍。** [Kimi K3](../arxiv-2607.24653/README.md) 在四分之一的层保留不选择的全注意力 MLA，代价是这些层的 KV 随长度线性增长，好处是不存在选择误差；V4.1 把每一层都交给索引器。两家在优化器上反而收敛：V4.1 的按头分块 Muon 明确引用 K3 与 GLM-5 的验证（§2.5）。CED 的思路来自 YOCO，[Gemma 3](../arxiv-2503.19786/README.md) 的 5:1 局部/全局交错是另一种"以局部层为主"的省缓存做法。

## 批注

**易误读**

- 890 字节只算全局 KV（主 KV 与索引键）。滑窗 KV 每层固定 128 个 token、FP8，不随长度增长，不在其中。
- "8B 激活"只指预填充，解码仍激活 16B，比 V4-Flash 的 13B 多；短上下文的解码 FLOPs 因此略高（图 2）。
- 552B 是骨干参数，不含 196B 的 Engram 表；算上 Engram 约 748B。表 1"骨干参数"一行与 V4-Flash 的 284B 并列时，后者没有查表参数。
- "持久化缓存 1/8"是在相同工作负载下的部署结果，包含把滑窗 KV 移出持久化缓存这一策略变化，不全是模型结构的作用。
- 表 3 的比较对象（Opus-5、GPT-5.6 Sol、K3、GLM-5.3）都取 Max 档推理；智能体基准用 1M 上下文窗口和 DeepSeek 自家框架，换框架会掉分（表 4）。
