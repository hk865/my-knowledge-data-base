# Qwen2.5-1M：训练到 256K，外推到 1M，再用稀疏 prefill 让它跑得起

> 状态：技术精读 · 原文 arXiv:2501.15383v1 · 未复现

## 一句话

Qwen 团队（2025）不改 Qwen2.5 的 Transformer 骨架，用"含长距离依赖的合成数据 + 分阶段加长"的预训练练到 256K，两段 SFT 与短样本偏好优化补上长文指令能力，推理时用 DCA 加注意力温度把窗口外推到 1M，再用稀疏 prefill 与推理引擎优化把 1M 输入的首 token 延迟降低 3–7 倍。

## 它要解决的问题

上下文窗口（context window，一句话：模型一次前向能读入的最大 token 数）在 2023–2024 年从 4K、8K 普遍扩到 128K，包括 Qwen2.5 的 128K 版本。作者的动机是仓库级代码生成与调试、基于大量文档的研究这类任务，128K 仍然装不下。Gemini、GLM-9B-Chat-1M、Gradient AI 的 Llama-3-1M 已经尝试 1M。[§1]

把"支持百万上下文"拆开，是四个独立的验收条件：

1. **位置泛化**：推理时出现训练中没见过的远距离，位置编码仍然可用。
2. **信息利用**：远处的关键内容真的改变答案，而不只是塞进窗口。
3. **任务表达**：模型按长文问题给出好答案，而不只是续写。
4. **资源可行**：显存、首 token 等待时间和多请求调度都可接受。

下文的各个模块分别对应其中一条：RoPE 频率调节、DCA 与温度缩放处理第 1 条；长依赖数据与训练课程提供第 2 条的学习信号；SFT 与偏好优化处理第 3 条；稀疏 prefill、分块、kernel 与引擎协同处理第 4 条。

## 核心想法

骨架不变：仍是 Qwen2.5 的 Transformer，GQA（分组查询注意力，一句话：多个查询头共享一组 K、V 头以缩小 KV 缓存）、SwiGLU 前馈层、RoPE（旋转位置编码，一句话：按位置把 Q、K 的各维度旋转不同角度，使点积只依赖相对距离）、QKV 偏置、预归一化 RMSNorm。7B 为 28 层、28 个 Q 头 / 4 个 KV 头；14B 为 48 层、40 个 Q 头 / 8 个 KV 头。Qwen2.5-Turbo 是只通过 API 提供的 MoE 模型。[§2、表 1]

增量集中在训练配方和推理工程上：

1. **训练信号**：合成"必须读远处才能答对"的任务，与自然长文混合，分五个阶段把训练长度从 4K 加到 256K。
2. **后训练**：先短后长的两段 SFT，再用 8K 以内的短样本做离线偏好优化。
3. **外推**：DCA 把远距离映射回训练见过的相对位置，配合注意力温度缩放，从 256K 推到 1M，推理时不再训练。
4. **部署**：MInference 式稀疏 prefill，加分块 prefill、与 DCA 的耦合修复、百万长度的稀疏度校准，以及 BladeLLM 引擎优化。

## 机制

### 1 训练数据：让正确预测依赖远处的信息

自然语料来自网页、arXiv、书籍、代码仓库；另加入三类合成任务：FIM（fill-in-the-middle，把文档切成前、中、后三段，让模型根据两侧补中间）、按关键词或相对位置检索段落、打乱段落后恢复顺序。[§3]

这里最值得带走的想法是**让正确预测必须依赖远处的信息**。一篇自然长文中，大部分词仍由附近几句决定，每个样本再长，优化器也主要获得局部建模的收益。位置检索让答案取决于"某段之前或之后"的材料，对抗只按局部关键词续写的捷径；段落重排要求恢复全局结构。

### 2 训练课程：先学会较短跨度，再逐级加长

| 阶段 | 最大训练长度 | RoPE base | 说明 |
|---|---:|---:|---|
| 初始 | 4,096 | 10,000 | 继承 Qwen2.5 早期训练 |
| 扩展 | 32,768 | 1,000,000 | 接续 Qwen2.5 中间检查点，用 ABF 调整 |
| 长上下文 1 | 65,536 | 1,000,000 | 新增 |
| 长上下文 2 | 131,072 | 5,000,000 | 新增 |
| 长上下文 3 | 262,144 | 10,000,000 | 报告中的最大训练长度 |

ABF（adjusted base frequency，一句话：调大 RoPE 的基频，让每个维度旋转得更慢，使更远的位置不至于转过一整圈）。后三个阶段每阶段的序列中，75% 取当前最大长度，25% 取较短长度。[§3，p.3–4]

课程的作用可以从 14B 各阶段的 RULER（一套合成的多任务长上下文评测，含检索、多跳追踪、聚合）看出：训练上限从 32K 加到 256K，RULER 128K 一列从 37.6 升到 87.6，其中最后一个阶段（128K→256K）又加了 3.8 分；64K 一列在最后一阶段反而从 93.0 降到 91.9。[表 2]

### 3 后训练：把读取能力变成长文指令能力

**合成长指令数据**。先取长文档，从随机抽取的文段生成问题，任务覆盖摘要、检索、多跳问答、推理、代码；再让 Qwen-Agent（Qwen 的智能体框架）基于全文作答，过程中使用检索增强、逐块阅读和逐步推理。学生模型最终看到的是"完整文档 + 问题 + 智能体生成的答案"。[§4]

**两段 SFT**。第一段只用 32K 以内的短指令，步数与 Qwen2.5 对应阶段相同；第二段混合短指令和最长 256K 的长指令。目的是保住短任务能力，同时学会长文指令。SFT 只在答案位置算损失，但答案通过注意力依赖整段长输入，梯度因此也在训练长距离信息的使用。

**离线偏好优化**。作者称之为"类似 DPO"的离线 RL，复用其他 Qwen2.5 模型的偏好数据，样本全部在 8K 以内。LongBench-Chat（评测长文任务中人类偏好对齐的数据集，最长约 100K）上，7B-1M 从 7.32 升到 8.08，14B-1M 从 8.56 升到 8.76，Turbo 从 7.60 升到 8.34。短样本偏好训练的收益迁移到了长文对话上。[§4、表 3]

### 4 外推：DCA 改位置，温度改注意力分布

注意力的计算可以拆成三个独立的坐标：

A(i,j) ∝ exp(position-adjusted-score(i,j) / temperature)，j 属于允许集合。

- 因果约束：允许集合先受 j≤i 限制。
- DCA：调整 score 中位置关系的表示。
- 稀疏化：在允许的历史 key 中再选子集。

**DCA**（Dual Chunk Attention，一句话：把长序列分块，使任意两个位置的相对距离都落在训练见过的范围内）。块内保留原距离；跨块用重复的位置模式；相邻块额外保护局部距离的连续性，避免块边界附近的局部关系被打乱。图 2 用 8-token 训练长度、5-token 块、3-token 局部窗口举例。[§5.1、图 2]

**注意力温度**。原文式（1）：softmax(qᵀk / (t√D))，其中 √(1/t)=1+0.1 ln(s)，s 为推理长度与训练长度之比。这是 YaRN（一种 RoPE 外推方法）中的温度缩放部分。[§5.1、式 1]

示例数值：s=4 时，√(1/t)=1+0.1×ln4≈1.1386，1/t≈1.2965、t≈0.7713，logit 约放大 1.30 倍，分布更尖锐。候选位置变多会让注意力分散，放大 logit 抵消这种分散。

普通 7B、14B 只训练到 32K，启用 DCA 加温度后，1M 范围的简单 passkey（在大段无关文本里埋一个密码让模型找回）可以超过 80%；训练到 256K 的 1M 版本更强。[图 3]

### 5 稀疏 prefill：少算一部分 Q–K 配对

prefill（一句话：生成第一个 token 之前，把整段输入一次过前向、建好 KV 缓存的阶段）是 1M 输入的主要开销，注意力的计算随长度平方增长。TTFT（time to first token，首 token 延迟）主要由它决定。

**稀疏注意力**。MInference（Jiang 等 2024 的稀疏 prefill 方法）先离线为每个头确定"竖线"和"斜线"的预算；推理时用部分 query 探测重要的 key，再只计算这些位置。竖线对应很多 query 共享的重要历史位置，斜线对应随 query 平移的相对局部结构。[§5.2、图 4]

**分块 prefill**。1M 输入时，7B 单个 MLP 层的激活可达 71GB；按 32,768 分块 prefill，这部分激活占用减少 96.7%。每块用自身最后 64 个 query 寻找重要的 key。[§5.2，p.7]

**与 DCA 的冲突与修复**。作者认为 DCA 让相对位置不连续，破坏了斜线模式，导致关键 token 选择失准；于是**选点时**恢复更连续的相对位置，**最终计算注意力时**仍用 DCA 的重映射位置。[§5.2、图 5]

**百万长度的校准**。MInference 原来的稀疏配置在 32K 以内搜索。Qwen 改用 1M 序列重新校准，借 FlashAttention 返回的 log-sum-exp（LSE，softmax 分母的对数）计算稀疏注意力保留了多少注意力质量：

recall = exp(LSE_sparse − LSE_full)

达不到阈值的头增加竖线、斜线预算。[式 2–4、算法 1，p.8–9] 示例数值：若稀疏选点的 LSE 比完整注意力低 0.01，recall = exp(−0.01) ≈ 0.990，即保留了约 99% 的 softmax 分母质量。

两处改进的效果：7B-1M 在 400K 以上长度直接用原稀疏方案，NIAH（needle in a haystack，大海捞针检索）准确率可能降到 60% 以下；改进选点和校准后恢复大部分性能，并保持约 4 倍 prefill 加速。[图 6]

### 6 引擎层

BladeLLM（阿里 PAI Engine 团队的推理引擎，Qwen2.5-1M 的 API 服务基于它）另有三类优化：稀疏 KV 加载与 kernel 流水；动态分块流水并行 DCPP，按历史长度调整块大小以减少流水线气泡；把调度、模型执行和解码分到不同进程的异步 TAG。A100 上 1M 稀疏注意力 kernel 相对 FlashAttention 的加速，MInference 为 13.7 倍，BladeLLM 为 27.8 倍；Turbo 的 MoE kernel 在 H20 上达到 3.4 TB/s，比 FusedMoE 高 55%。[§5.3、图 7–8]

## 局限与后续

**作者自述**：结论（§7）写明长上下文模型仍有很大提升空间，后续要继续探索更高效的训练策略、模型架构和推理方法，让模型在资源受限的环境中也能部署。报告本身给出的证据也划出了边界：RULER 主表最长 128K，LV-Eval 最长 256K，LongBench-Chat 约 100K，1M 长度上只有 passkey 与 NIAH 一类检索测试；离线偏好优化只用了 8K 以内的样本。

**站在现在看，后续工作修补了什么：**

- **检索题高估了长上下文能力**。NoLiMa（2025，[Long-Context Evaluation Beyond Literal Matching](https://arxiv.org/abs/2502.05167)）让问题和"针"之间几乎没有字面重叠，必须推断隐含联系才能找到。13 个声称支持至少 128K 的模型中，11 个在 32K 时已降到自身短上下文表现的一半以下，GPT-4o 从 99.3% 降到 69.7%。`[判断]` 本报告 1M 长度上的证据（passkey、NIAH）恰好是字面匹配类任务，"1M 窗口可访问"与"1M 信息可利用"之间的差距，在本报告的测法里看不出来；本报告自己的 72B 对 14B-1M 的 LV-Eval 结果已经提示了这一点。
- **事后稀疏化被原生稀疏训练取代**。NSA（DeepSeek 2025，[Native Sparse Attention](../arxiv-2502.11089/README.md)）在第 2 节把只在 prefill 稀疏的方法（点名 MInference）列为加速不完整的一类：解码阶段的开销仍与全注意力相当；并指出事后稀疏化迫使模型偏离预训练的优化轨迹，top 20% 的注意力只覆盖约 70% 的注意力分数，预训练形成的检索头容易在推理时被剪掉。`[判断]` 本报告 §5.2 遇到的"400K 以上 NIAH 掉到 60% 以下、要重新校准"，正是这个问题的表现；后来的 [DeepSeek-V4](../arxiv-2606.19348/README.md) 在预训练中从稠密注意力转为稀疏、[Kimi Linear](../arxiv-2510.26692/README.md) 用线性注意力混合替换大部分全注意力，都把稀疏或压缩写进训练，而不是推理时再近似。
- **外推被更长的原生训练取代**。`[判断]` 本报告训练到 256K、推理外推到 1M；DeepSeek-V4 在预训练中直接把序列长度加到 1M。随着注意力本身变便宜，"训练长度 × 外推倍数"的组合正在让位于直接训练到目标长度，DCA 这类免训练外推的价值主要留在已有模型的低成本扩窗上。
- **长窗口与长轨迹 RL 是两件事**。`[判断]` 一个智能体调用 100 次工具、最后才拿到成功奖励，即使所有历史都放得进 1M 窗口，"哪一步决定成败"的信用分配问题仍然存在。本报告让历史更可能被读到，改善的是状态表征；它没有长轨迹优势估计、过程奖励或在线探索。输入跨度、输出长度、环境步数、奖励跨度四个量相关但不等价。

本方向的整体脉络见[长上下文方向](../../fields/long-context/README.md)。

## 批注

**易误读**

- 1M 是推理窗口：训练最长 256K，推理靠外推到 1M；开源 7B、14B 的生成长度上限为 8K（§2–5、表 1）。预训练长度、输入窗口、输出预算是三件事。
- DCA 和稀疏注意力都保持因果性，原文式（2）仍对 j≤i 求和；文中的 full attention 指完整的因果注意力，不是双向注意力（§5.2）。
- 后三阶段"75% 当前最大长度"按序列数计，不是按 token 数；短序列的长度分布未公开（§3）。
- RoPE base 的变化改变各维度的旋转频率，不是换了一个更长的因果掩码。
- 表 2 各阶段之间同时增加了训练量、调整了 base、改变了数据长度，不能当成"训练超过目标长度"的独立因果证据；论文也没有等算力的"一步训到 256K"对照。
- 教师（Qwen-Agent）作答时用了检索增强和逐块阅读，学生推理时并不调用这些工具；问题只从一个文段生成，"多跳任务类别存在"不保证每个样本都需要跨全文整合。
- "类似 DPO"是原文措辞，精确算法与超参数没有公开。表 3 给 7B 标注 "+0.75"，端点相减是 0.76，可能是显示精度或笔误。
- 论文实验总把 DCA 与温度缩放一起使用，"有无 DCA"的标签不能把增益全部归给 DCA；这里的 YaRN 只指温度缩放，并非完整 YaRN 的全部插值技巧（§5.1）。
- "无需额外训练"只指外推这一步；1M 版本整体经过了长预训练和长 SFT。
- 稀疏 prefill 的"稀疏"指少算的 Q–K 位置，与 MoE 的参数激活稀疏无关。
- 96.7% 指单个 MLP 层的激活占用，不是整模型显存，也不是 KV 缓存减少 96.7%；分块 prefill 的 32,768、DCA 的位置块、DCPP 的调度块是三个不同参数（§5.2）。
- recall 是 softmax 分母中被选中 key 保留的概率质量，不是任务答案的召回率；保留 0.99 的注意力质量不等于 99% 的任务准确率。校准不更新权重，但需要长序列上的完整注意力计算，并非零算力（§5.2）。
- 选点修正与长校准的效果来自组合方案，缺少两个改动分别开关的 2×2 对照（图 6）。
- kernel 加速（13.7 倍、27.8 倍）与整体 TTFT 加速（3.2–6.7 倍）是不同层级；MoE kernel 的 55% 也不能挪用成端到端吞吐。TTFT 是单请求首 token 延迟，不是整段生成时间、并发吞吐或训练速度；109 秒仍是可感知的等待（§6.3、图 11）。倍率来自图示，时间来自正文，舍入后不必精确相等。
- RULER 主表最长 128K，把它当成 1M 的 RULER 会把证据范围扩大八倍。LV-Eval 的指标被作者修改以减少严格匹配造成的假阴性，不能直接与原始排行榜混排；表 4 某行写 "GPT-4"、正文写 GPT-4o，存在命名不一致（§6.1）。
- 短任务表现应读成"大致保持同档、有升有降"，不是逐项无损；也没有重复运行，不能断言哪些升降是稳定的（表 6）。

**与其他论文的关联**

- `[历史]` 底座是 [Qwen2.5](../arxiv-2412.15115/README.md)，骨架来自 [Transformer](../transformer/reading.md)；长上下文训练放在预训练末段、分级加长的做法，与 Llama 3、DeepSeek-V2/V3 一致，比较见[预训练方向](../../fields/pretraining/README.md)"更长更大的注意力"一节，其中"只有长度不够，要合成必须读远处的任务"一条引用了本篇。
- 偏好优化阶段使用"类似 [DPO](../dpo/reading.md)"的离线方法，并且只用短样本；DPO 的离线、固定数据集性质决定了它无法直接产生长轨迹上的信用分配。
- 推理侧的稀疏 prefill 继承 MInference；[DeepSeek-V4](../arxiv-2606.19348/README.md) 与 [Kimi Linear](../arxiv-2510.26692/README.md) 代表把稀疏或线性注意力移到训练阶段的路线，NSA 的批评直接针对本篇所用的这类方法。
- 外推所用的 DCA（[arXiv:2402.17463](https://arxiv.org/abs/2402.17463)）与 YaRN（[arXiv:2309.00071](../arxiv-2309.00071/README.md)）、稀疏方法 MInference（[arXiv:2407.02490](https://arxiv.org/abs/2407.02490)）、评测 RULER（[arXiv:2404.06654](../arxiv-2404.06654/README.md)）与 LV-Eval（[arXiv:2402.05136](https://arxiv.org/abs/2402.05136)）都是本报告引用的技术来源，细节以各自原文为准。
