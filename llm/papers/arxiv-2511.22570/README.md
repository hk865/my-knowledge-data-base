# DeepSeekMath-V2: Towards Self-Verifiable Mathematical Reasoning

> 状态：文献卡 · 2025 · [原文](https://arxiv.org/abs/2511.22570)

[返回大语言模型目录](../../README.md) · [原文与阅读记录](source.json)

- **解决什么**：以最终答案为奖励的 RL 有两个缺口：答案对不等于推理对；定理证明这类任务根本没有可比对的最终答案。没有可靠的验证器，推理时多采样、多修改也无从挑选。
- **核心方法**：在 DeepSeek-V3.2-Exp-Base 上训练两个角色。验证器读一份证明，先指出问题，再打 0、0.5、1 三档分；只用分数做奖励时，验证器会给对分数却编造不存在的问题，于是加一个元验证器检查"指出的问题是否真实、是否支撑这个分数"，并把它的判断并入验证器的奖励。生成器以验证器为奖励模型，同时要对自己的证明做一次自我评估，奖励由证明得分（权重 0.76）与自评是否与验证器一致（0.24）组成，促使它在交卷前自己发现并修正问题。生成器变强后，用"多次验证 + 多次元验证、按足够多确认的最低分定标"的流程自动标注难证明，取代人工标注，维持验证始终比生成更强。推理时：每题先生成 64 份证明、每份做 64 次验证，再挑出最好的 64 份配 8 次分析迭代修改，最多 16 轮，直到某份证明通过全部 64 次验证。结果：IMO 2025 解出 6 题中的 5 题、CMO 2024 达到金牌线、Putnam 2024 得 118/120。
- **为什么在这个库里**：[推理时计算方向](../../fields/inference/README.md)"没有可靠验证器的任务怎么多算"一问的直接回答之一：用训练出来的验证器与自我验证替代答案比对；也是[偏好学习方向](../../fields/posttraining/preferences/README.md)中"评委变成会推理的模型"在数学证明上的形态。优先级：必读。

## 批注

**易误读**
- IMO、CMO、Putnam 的成绩都是在上面这套大规模推理时计算（每题数千次生成与验证）下取得的，不是单次采样的结果。
- 0.76 与 0.24 是生成器奖励中两项的权重，不是准确率。

**未核实 / 待验证**
- 作者写明最难的 IMO 级题仍然困难；验证器在几何、组合等子领域的失误率未单独核对。
