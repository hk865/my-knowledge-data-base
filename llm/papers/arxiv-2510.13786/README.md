# The Art of Scaling Reinforcement Learning Compute for LLMs

> 状态：文献卡 · 2025 · [原文](https://arxiv.org/abs/2510.13786)

[返回大语言模型目录](../../README.md) · [原文与阅读记录](source.json)

- **解决什么**：RL 的算力预算越来越大，却没有预训练那样的规模规律：不知道一个配方加算力后能涨到哪里，也无法用小实验判断哪种算法改动值得放大。
- **核心方法**：把"验证集通过率随 RL 算力的变化"拟合成一条 S 形曲线，用三个参数描述一个配方：渐近上限 A（算力无穷时能涨到多少）、陡度 B（多快接近上限）、C_mid（涨到一半所需的算力）。在 8B 稠密模型与 17B×16 专家的 Llama-4 Scout MoE 上做了累计超过 40 万 GPU 小时的消融，得出三条结论：不同配方的上限不同；损失聚合、优势归一化、课程、长度惩罚、离策略算法等细节主要改变效率（B），基本不改上限（A）；稳定的配方可以从小规模外推大规模的结果。据此组合出 ScaleRL：PipelineRL 式异步训练（策略最多落后 8 步）、强制截断过长生成、截断重要性采样的 CISPO 损失、按提示平均损失、按批量归一化优势、输出层 logits 用 FP32、丢掉全对或全错的题组、已经稳定答对的题不再重复采样。8B 模型上单次 RL 跑到 10 万 GPU 小时，曲线与前段拟合的外推一致。单项对比中，logits 改用 FP32（减小推理引擎与训练框架的数值差异）把拟合的上限从 0.52 提到 0.61；CISPO 与 GSPO 明显好于 DAPO 的损失。
- **为什么在这个库里**：[强化学习方向](../../fields/posttraining/rl/README.md)第 6 节"RL 能否像预训练一样预测"一问的主要证据，也是"稳定性补丁有没有统一原理"一问的系统性回答之一：它把各家补丁按"改上限还是改效率"分了类。Meta 参与的研究，实验以数学为主。优先级：必读。

## 批注

**易误读**
- A、B、C_mid 是在作者自己的数学验证集上拟合的通过率曲线参数，不能跨任务、跨模型直接比较数值（§2、§7 局限）。
- "细节只改效率不改上限"是在作者的配方族与 8B、Scout 两个模型上得出的；作者写明泛化到分布外任务、算力在预训练与 RL 之间怎样分配，都不在本文范围内。

**未核实 / 待验证**
- 各项消融的完整数字表未逐项核对；FP32 logits 的 0.52 → 0.61 取自正文对拟合上限的描述。
