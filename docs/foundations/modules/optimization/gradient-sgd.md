## 先分清损失 梯度 学习率和更新量

用 θ 表示全部可训练参数，把训练集平均损失写成：

L(θ) = (1/N) × Σᵢ ℓ(fθ(xᵢ), yᵢ)

这里 L 是一个数，θ 是一个很长的向量。梯度 g = ∇θL 与 θ 形状相同，第 j 个分量表示：“其他参数暂时不动，第 j 个参数稍微增大，损失变化得多快？”梯度为正时，该参数向负方向移动才是局部下降方向。

为什么采用负梯度？一阶近似给出 L(θ + Δθ) ≈ L(θ) + gᵀΔθ。在欧氏距离下限制更新长度时，负梯度方向让这个线性近似下降最快。因此最基本的梯度下降是：

Δθₜ = −ηₜgₜ

θₜ₊₁ = θₜ + Δθₜ

必须分清三个量：g 是损失对参数的敏感度；η 是学习率，即更新规则里的比例系数；Δθ 才是参数实际移动的向量。例如 g = 10、η = 0.01，实际变化为 −0.1，不是 −10，也不是 −0.01。采用 Adam 等算法后，Δθ 通常连方向都不再严格等于 −g 的方向。

负梯度只保证“足够小的局部步子”有下降依据，不保证任意步长都下降，更不会自动指向远处的全局最小值。这一点从下一节的数值例子就能直接看出来。[梯度下降分析](https://proceedings.mlr.press/v49/lee16.pdf)

## 反向传播是高效求导 不是另一个优化器

![链式法则分步计算](../../../../assets/foundations/02a-chain-rule.svg)

图 1 先顺着上排计算数值，再沿依赖关系反向传递导数。下排展示两个参数分别收到的梯度，最后同时更新。

假设一个最简单的两层模型是 h = w₁x、ŷ = w₂h，损失为 ℓ = ½(ŷ − y)²。要知道 w₁ 如何影响损失，就沿着计算路径使用链式法则：

∂ℓ/∂w₁ = (∂ℓ/∂ŷ) × (∂ŷ/∂h) × (∂h/∂w₁) = (ŷ − y)w₂x

而 ∂ℓ/∂w₂ = (ŷ − y)h。若 x = 2、y = 3、w₁ = 1、w₂ = 0.5，则 h = 2、ŷ = 1、ℓ = 2，两个梯度分别为 −2 和 −4。学习率取 0.1，用同一次前向结果算出的梯度同时更新，得到 w₁ = 1.2、w₂ = 0.9；新预测为 2.16，新损失为 0.3528。

真正的网络只是这条链更长、分支更多：前向时保存需要的中间结果，反向从损失出发，把已经算好的局部导数复用；同一变量影响损失的多条路径，其贡献相加。自动微分系统沿计算图完成这些乘法与加法。因此，反向传播解决“怎样高效算 g”，SGD、Adam、Muon 解决“得到 g 后怎么动 θ”。[PyTorch 自动微分说明](https://docs.pytorch.org/tutorials/beginner/basics/autogradqs_tutorial.html)

链式法则也解释了梯度消失和爆炸：多层导数或雅可比连乘，某些方向的信号可能不断缩小或放大。残差连接、合适的初始化、归一化和梯度裁剪各自改变不同环节，换一个优化器不一定能修好计算图本身的问题。[Pascanu 等的梯度分析](https://arxiv.org/abs/1211.5063)

## 为什么不用全部数据算完梯度再走一步

全批量梯度下降每次使用全部 N 个样本；单样本 SGD 每次抽一个样本；mini-batch SGD 每次抽 B 个样本。实际说“用 SGD 训练”，经常指小批量版本：

gₜ = (1/B) × Σᵢ∈批次 ∇θℓᵢ(θₜ)

在均匀抽样等合适条件下，它是全训练集梯度的无偏估计。单步方向会偏，但许多步共同推动学习。独立、有放回抽样时，批均值的方差等于单样本梯度方差除以 B；真实数据相关性、非均匀抽样等会改变这个关系。小批量还能利用 GPU 的矩阵并行，并减少“算完昂贵的全量梯度后才更新”的等待。[Bottou 等关于大规模机器学习优化的研究](https://arxiv.org/abs/1606.04838)

代价是曲线有噪声：当前批次 loss 上升，可能只是这一批更难，并不等于总体训练恶化。更大 batch 通常降低梯度估计噪声，却增加单步成本并减少固定样本预算内的更新次数；它需要配合学习率与训练时长判断。噪声有时影响探索和最终解，但不是“噪声越大越好”的通用正则化。[SGD 噪声与泛化分析](https://arxiv.org/abs/1710.06451)

step 是一次优化器更新；epoch 是完整遍历训练集一次。梯度累积则把若干微批次的梯度累积起来再更新，以较少显存近似大批量。要正确处理平均系数；存在依赖批统计的运算时，也不能一概说它与直接大 batch 完全等价。[PyTorch 梯度累积示例](https://docs.pytorch.org/docs/2.14/notes/amp_examples.html#gradient-accumulation)

## 一个可以手算的病态山谷

考虑并不存在坏局部最小值的凸函数：

L(x,y) = ½(x² + 100y²)

∇L = (x, 100y)

唯一最优点是 (0,0)。但 y 方向比 x 方向弯得陡，二阶导数组成的 Hessian 为 diag(1,100)，两个特征值的比值，即这个正定问题的条件数，为 100。直接梯度下降满足：

xₜ₊₁ = (1 − η)xₜ

yₜ₊₁ = (1 − 100η)yₜ

从 (1,1) 出发，初始损失为 50.5：

| 学习率 | 第一步的新参数 | 新损失 | 发生了什么 |
|---|---|---:|---|
| 0.01 | (0.99, 0) | 0.49005 | y 恰好到零，x 后续仍慢慢下降 |
| 0.019 | (0.981, −0.9) | 40.9811805 | y 来回换符号，振荡幅度逐步缩小 |
| 0.03 | (0.97, −2) | 200.47045 | y 振荡幅度扩大，持续使用会发散 |

要求两个方向的乘数绝对值都小于 1，得到本例的稳定范围 0 < η < 0.02。要避免陡方向发散，平缓方向又得走得很慢。这就是病态条件的核心困难：**一个全局学习率很难同时照顾所有方向。** 它与“卡在局部最优”完全是不同的问题。以上均为本章自设函数的直接计算，不是任何优化器的性能榜。

![同一凸函数上不同学习率的轨迹与损失](../../../../assets/foundations/02-optimization-trajectories.svg)

图 2 原创数值示意。左图按参数坐标画前 30 步；右图画相同更新规则下的损失，纵轴使用对数尺度。振荡可以收敛，也可以发散，要看幅度与趋势。

预条件方法会先变换梯度再更新。在这个已知 Hessian 的玩具例子里，左乘 diag(1, 1/100) 能把两个方向的有效尺度拉齐；真实大网络通常不知道完整曲率，也承担不起显式存储全部二阶信息。动量和自适应方法由此提供了不同的低成本近似方案。[动量与曲率的实验分析](https://proceedings.mlr.press/v28/sutskever13.html)

## 局部最小值 鞍点和过参数化该怎样理解

局部最小值是在附近怎么小幅移动都不更好；全局最小值是在整个参数空间里最好。鞍点附近有的方向向上，有的方向向下，梯度却可能很小，例如 x² − y² 的原点。训练走得慢，还可能因为平坦区、病态曲率、梯度消失或噪声掩盖信号，不能只看一段平的 loss 曲线就诊断“陷进局部最优”。Dauphin 等人的工作强调了高维鞍点及其附近平台的重要性，但不是针对所有深度网络的万能定理。[高维鞍点原论文](https://proceedings.neurips.cc/paper_files/paper/2014/hash/04192426585542c54b96ba14445be996-Abstract.html)

理论结论要连同条件一起读：对足够光滑、满足相应步长条件的目标，连续随机初始化的梯度下降几乎必然不会收敛到严格鞍点；这不意味着有限训练时间内一定很快离开所有平坦区域，更不等于找到全局最小值。某些足够宽、适当初始化、满足数据和结构假设的过参数化网络，也能证明梯度下降达到零训练误差；这些证明不能直接推广到任意 Transformer 和真实训练配置。[严格鞍点结果](https://proceedings.mlr.press/v49/lee16.pdf)、[过参数化 ResNet 的条件性结果](https://proceedings.mlr.press/v97/du19c.html)

“数据更多”与“模型过参数化”也不是同一个条件。更多数据不能保证没有坏局部解，更多参数更不能保证泛化。即使训练损失达到了全局最小，测试表现仍可能差；优化成功与泛化成功是两件需要分别检查的事。

## Loss 突然变大时先诊断 再判断是否要重来

损失的绝对大小与定义、缩放、类别数、平均方式有关，详见[损失函数目录](../../03-tasks-losses.md)。把整个目标乘以 100，数值就放大 100 倍，并不等于模型坏了。不过这会放大原始梯度，训练配置也应相应检查。**单个大 loss 不是“模型再也救不回来”的证据。**

| 观察到的现象 | 需要区分的原因 | 先检查与处理 |
|---|---|---|
| 只有一两个 batch 出现尖峰 | 困难样本、异常标签、长度或数据分布变化 | 记录样本与各项 loss，核对归一化；不要只凭尖峰改模型 |
| loss 持续抬升，更新幅度同步变大 | 步长过大、调度错误、优化器状态异常 | 看学习率及 ‖Δθ‖/‖θ‖，用最近正常检查点重试更保守的配置 |
| 梯度范数突然极大 | 梯度爆炸、异常输入或不稳定算子 | 找最早异常层，检查输入、初始化和精度；有限梯度可做裁剪 |
| loss、梯度出现 Inf 或 NaN | 溢出、除零、非法对数等 | 找第一个非有限值；修根因，不把 NaN 裁剪当修复 |
| 权重或 Adam 状态已出现 NaN | 非有限更新污染训练状态 | 从正常检查点恢复模型和优化器；仅降低学习率不会把 NaN 变回有限值 |
| 新任务变好，旧任务变差 | 灾难性遗忘或任务分布变化 | 同时评估新旧任务；讨论数据混合、回放或约束，而非只盯当前 loss |
| 训练 loss 降，验证 loss 升 | 可能过拟合，也可能验证流程问题 | 核对评估模式与分布，再检查数据、正则化和早停 |

梯度裁剪通常限制梯度整体范数，例如 g ← g·min(1, c/‖g‖)，用来防止有限但过大的梯度导致巨幅更新。它不是修好任意训练故障的按钮。混合精度训练中若使用梯度缩放，应先 unscale 再裁剪；检测到溢出时可跳过这一步更新，但仍需观察异常是否持续。[梯度裁剪原论文](https://arxiv.org/abs/1211.5063)、[PyTorch 混合精度说明](https://docs.pytorch.org/docs/2.14/notes/amp_examples.html#gradient-clipping)

检查点也不只是一份权重：要延续训练轨迹，通常还需要优化器的动量和二阶统计、调度器、训练步数；混合精度时还要考虑 scaler 状态，精确复现还涉及随机数与数据迭代状态。恢复旧权重后换新配置是一个合理的新分支，但不能冒充“完全无缝接着原来那一步”。[PyTorch 检查点教程](https://docs.pytorch.org/tutorials/beginner/saving_loading_models.html)、[AMP 状态恢复](https://docs.pytorch.org/tutorials/recipes/recipes/amp_recipe.html)

灾难性遗忘尤其容易误判：新任务的 loss 可以正常下降，模型对旧任务的能力却退化。这是任务间学习冲突，和数值 NaN、文件损坏并不是同一问题。[Kirkpatrick 等的持续学习研究](https://arxiv.org/abs/1612.00796)

## 把训练理解成一个可检查的闭环

一次可靠的训练循环是：取数据并核验 → 前向和 loss → 清理或正确累积旧梯度 → 反向传播 → 检查有限性与必要的裁剪 → 优化器更新 → 记录学习率、梯度和真实更新量 → 定期验证和保存检查点。

遇到训练不动时，先看计算图、数据和更新是否正确，再讨论优化器；遇到验证变差时，转向泛化、正则化和数据分布。优化器选择没有脱离任务的总冠军：SGD 加动量提供简洁基线，AdamW 提供常用的自适应方案，Muon 对合适的矩阵参数提供另一种结构化更新。要验证的是“这套模型与数据在给定预算内是否更好地学到目标”，而不是算法名字是否更新。

**自检题**：若反向传播得到 g = (2, −4)，普通 SGD 的学习率为 0.1，参数变化是什么？若换成 Adam，能否只凭这个 g 算出实际更新？

答案：SGD 的 Δθ = (−0.2, 0.4)。Adam 还要知道一阶、二阶历史状态、步数和超参数；当前梯度本身不够。能解释这一点，就已经抓住了“梯度不等于更新”的关键。

## 关联论文精读

### 梯度消失和爆炸并非同一种故障

阅读 [Pascanu 等 2013 原论文](https://arxiv.org/abs/1211.5063) 的梯度分析和梯度范数裁剪部分。作者研究循环网络中长时间依赖的求导，关键对象是多个雅可比矩阵的乘积。读到乘积时，先用一维例子替代它：反复乘 0.5 会衰减，反复乘 2 会增长；真实矩阵中，不同方向可以有不同增益。这是教学类比，不是说每层只有一个统一的放大系数。

作者提出用范数裁剪限制过大的梯度。请把这个结论与计算图对上：裁剪发生在求完梯度之后、参数更新之前；它并未重写网络前向函数，也没有为消失的梯度重新制造信息。若梯度已经含 NaN，有限向量的裁剪公式不再是修复手段。

### 鞍点论文的结论必须带上量词

阅读 [Lee 等 2016 原论文](https://proceedings.mlr.press/v49/lee16.pdf) 的 Section 2 定义和 Section 4 主结论。严格鞍点要求 Hessian 至少有一个严格负特征值；定理依赖光滑性、梯度 Lipschitz 条件、足够小的步长和连续随机初始化等假设。这里“几乎必然不收敛到严格鞍点”讲的是渐近极限与概率，不能改写成“跑几百步就必然脱困”。

精读时自问三件事：对象是不是我的网络？步长和初始化是否满足假设？证明的是避免哪种点，还是找到全局最优？如果把后两者混为一谈，就会得出“数据多就不存在坏局部解”的错误结论。
