# 样本接口与数据集选择：先说清楚我们要让模型做什么

## 1. 先从一个容易说错的任务开始

假设你把手机放进口袋，记录一段运动数据，希望模型判断你在走路还是跑步。你可能会说：“我已经有一个 IMU 数据集了，接下来选网络就行。”但这句话还缺少几个决定性信息。

手机每次记录了什么？是三个方向的加速度，还是同时有三个方向的角速度？模型看多长时间？标签“跑步”描述最后一个时刻，还是整段时间？如果一段数据里先走后跑，应该怎样标注？训练时能拿到运动视频，使用模型时也能拿到吗？

这些问题不属于实现细节。答案不同，实际上就是不同的学习任务。所谓**样本约定**，就是先把“一道题给什么、要求答什么、哪些地方有效、题目来自哪里”写清楚。只有约定明确，读数据、写模型、计算损失和评价结果的人，才是在解决同一个问题。

本篇不要求你先会写神经网络。我们从一条样本开始，把需要的概念逐个补齐。

## 2. 一条样本可以拆成四个部分

把一条样本写成 `(x, y, m, meta)`，这里只是给四类信息起名字，并不要求程序必须使用这种容器。

**x 是输入。** 它是模型做判断时允许看到的信息。在手机例子中，x 可以是过去一秒的六轴 IMU 读数。IMU 是惯性测量单元；这里的六轴指三轴角速度和三轴加速度计读数。训练文件中还有视频，并不意味着视频可以偷偷成为输入。如果实际使用时只有手机传感器，训练输入也应遵守这个限制。

**y 是目标，也常叫标签。** 它是我们希望模型预测的答案。走路/跑步是离散类别，可以约定走路为 0、跑步为 1。这两个数字是类别编号，不表示跑步在数值上比走路多一个单位。如果目标换成“一秒内移动了多少米”，y 就成了连续数值，这类任务叫回归。类别预测与回归可以读取同一份传感器文件，却不是同一个任务。

**m 是有效性掩码，英文是 mask。** 它告诉程序哪些位置可以参与某一步计算。设一段数据有五个位置，但只有前三个有可靠标签，就可记录 `m=[1,1,1,0,0]`。1 表示有效，0 表示应忽略。假设五个位置的误差分别为 `[2,4,6,100,100]`，有效位置的平均误差应为 `(2+4+6)/3=4`，不能除以 5，也不能让无效位置的 100 参与计算。没有任何有效位置时，不能继续除以零，必须按预先写好的规则跳过或报错。

同一个任务可能需要不止一种 mask。例如文本补齐的位置不应进入句子平均，而缺少目标的位置不应进入损失。两者用途不同，不要只凭一个变量名就认为可以通用。没有缺失也没有补齐的定长分类样本，可以约定全部有效。

**meta 是元信息。** 它用于解释和追踪样本，包括样本编号、原文件、受试者、设备、时间、单位、坐标系和所属数据划分。它通常不进入模型，但对排查错误非常重要。例如，训练和测试的样本编号不同，却来自同一人同一分钟的相邻片段，仅检查编号就发现不了两者高度相关。

![一条样本的输入、目标、有效性与来源信息](../../../../assets/foundations/data/a-overview.svg)

读这张图时，从“输入”走向模型，把“目标”看作训练和评价时的对照答案；mask 决定哪些位置纳入计算，meta 则帮助我们检查来源。图中把这些信息放在一起，是为了描述一个完整样本，不表示四部分都要拼接后送进网络。

## 3. 方括号里的数字究竟在说什么

机器处理的是数值数组。**形状 shape** 描述数组沿每个方向有多少个元素；**张量 tensor** 在这里可以先理解为带有若干个轴的数值数组。

一张彩色小图可以写成 `[3,32,32]`。按本篇约定，三个轴依次是颜色通道、高、宽，所以它包含 `3×32×32=3072` 个数。单个数可能表示某个像素在红色通道上的亮度。另一套程序可能用 `[32,32,3]`，元素数相同，但轴顺序不同，不能不转换就交给同一个模型。

一秒的六轴 IMU 输入可以写成 `[200,6]`。第一个轴表示 200 条按时间排序的读数，第二个轴表示每条读数的六个通道。沿第一个轴移动，是换时刻；沿第二个轴移动，是换传感器分量。网络怎样利用相邻元素，必须与这些含义一致。

**batch 是一次一起处理的多条样本。** 若一次处理 64 张图，堆叠后是 `[64,3,32,32]`；若一次处理 64 个 IMU 窗口，则是 `[64,200,6]`。常用 B 代替批量大小，于是写成 `[B,3,32,32]`。B 是后来加上的批量轴，不是一张图片原本的属性。

还要写明 **dtype，也就是数值类型**。浮点数用于表示连续量，例如 `float32`；整数常用于类别或词的编号，例如 `int64`。文本里的 token 是分词后得到的词、子词或字符单位，token ID 是这些单位在词表中的编号。编号 20 并不表示编号 10 的两倍含义，因此不能像处理加速度那样，对 token ID 减均值、除标准差。

形状正确只是第一关。两个数组都叫 `[200,6]`，一个使用 rad/s，另一个使用 deg/s；一个通道顺序先角速度后加速度，另一个相反。程序可能照常运行，学到的含义却已经错了。

## 4. 同一张照片为什么能对应三种任务

假设照片里有一只猫和一辆汽车。

**分类**问：“按照事先约定的标注规则，这张图属于哪一类？”目标可能是一个类别编号。若任务允许同时标猫和汽车，就是多标签分类，不能继续假设每张图只有一个正确类别。

**检测**问：“有哪些对象，各自在哪里？”目标需要包含对象类别和边界框。边界框常用四个数描述位置，但还要约定是左上角加宽高，还是两个对角点，以及数值单位是像素还是归一化坐标。一张图有多少个对象不固定，目标长度也可能变化。

**分割**问：“每个像素属于什么？”目标常是一张与图像空间对应的类别图。例如高 32、宽 32 的图像，可以有 `[32,32]` 的像素类别目标。

![同一幅图像对应分类、检测和分割的不同问题](../../../../assets/foundations/data/a-task.svg)

图的重点是输入可以一样，问题和答案却不同。翻转一张分类图片时，猫仍然是猫；翻转检测图片时，框的位置必须同步改变；翻转分割图片时，类别图也要一起翻转。因此，更换任务不能只改网络最后一层，还会改变目标组织方式、增强和评价。

训练中的 **loss，也就是损失**，是把预测与目标的差异变成可优化的数值。单标签分类常用交叉熵，它会惩罚模型给正确类别过低的概率；连续位移可以用平方误差，它会惩罚预测位置与目标位置的数值差。**评价指标**则回答我们真正关心的效果，例如分类正确率、位移误差多少米。损失和评价可以有关联，但不能因为两个数字都下降，就把它们当成同一种量。

## 5. 下载之前，先填写一张完整任务卡

下面给出一张教学用任务卡。它是设计示例，不表示已经采集或训练。

- 任务：根据手机过去一秒的 IMU 读数，判断该窗口是走路还是跑步
- 输入：六轴读数，按固定通道顺序排列；约定采样率、物理单位和手机坐标方向
- 可用信息：只使用窗口结束时及之前的传感器读数，不使用未来视频
- 目标：0 表示走路，1 表示跑步；转场窗口先排除，并报告排除规则
- 输出：每条样本两个类别分数，一批为 `[B,2]`
- 训练损失：单标签分类交叉熵
- 评价：正确率、两类各自的召回率，以及按受试者分组的结果
- 划分：若目标是适用于新用户，训练、验证和测试按人分开
- 版本：保存原始文件版本、划分名单、处理配置与随机种子

这里的训练集用于学习参数，验证集用于选择设置，测试集用于在方案固定后做最终检查。所谓**泛化**，就是在这些未用于学习和选择的对象上还能表现得好。要泛化到新的人，就必须真正拿没参与训练和选择的人来测试；换几条同一个人的记录，只回答了较窄的问题。

如果任务变成机器人动作预测，任务卡还必须写清：动作是关节角、关节力矩、速度，还是末端位置和朝向的增量；单位是什么；每隔多久执行一次。一个 `[7]` 的输出只说明有七个数，并不能说明控制器应该怎样执行，更不能证明真实硬件上的安全性。

## 6. 数据集很大至少有四种不同含义

第一种是**磁盘大小**，指下载包和解压文件占多少空间。第二种是**内存占用**，取决于解码、缓存和同时预取多少样本。第三种是**显存占用**，包括模型参数、中间结果、梯度、优化器状态和当前批次输入。第四种是**独立来源的覆盖程度**，例如来自多少人、设备、场景和轨迹。

前三种影响能否存下和算动，第四种影响我们有多少证据支持泛化。它们不能互相代替。

做一个小计算：一张 `[3,32,32]` 图像若以每元素 1 字节的 uint8 保存，纯像素部分是 3072 字节；转换成每元素 4 字节的 float32 后，是 12288 字节。文件大小没有变化，并不代表解码后的内存占用没变。而把它送进网络后产生的中间结果，也没有包含在这个数字里。

再看另一种“变大”：一条十分钟轨迹切成很多相互重叠的窗口，训练实例数会增加，但设备、场景和运动来源没有自动增加。窗口多有助于优化，不等于获得同样数量的独立实验。

![磁盘、内存、显存和独立数据覆盖回答四种不同问题](../../../../assets/foundations/data/a-scale.svg)

图中的四个部分应分别记录。看到“十万个样本”时，要继续问十万个是什么、来自多少独立来源，而不是直接推断模型已经见过足够多的世界。

## 7. 怎样选择第一个数据集

先用任务卡筛选，再看知名度。希望练习小图分类，可以选 CIFAR-10；它提供固定大小图像和十类标签。[1] 希望练习英文影评情感分类，可以选 IMDb；它提供有标签的影评和既有训练/测试划分。[2] 希望理解传感器时间同步和局部运动回归，可以选 EuRoC，但必须面对坐标、参考状态和物理可观性的问题。[3]

如果后来转向人体运动或机器人动作，AMASS、robomimic、Open X-Embodiment 可以作为继续调查的方向，但不能仅凭“都是序列”就互换。人体姿态参数不等于 IMU 测量，更不等于可以直接发送给机器人的动作命令。选型时仍要逐项核对输入、目标、单位、许可和可用于评价的划分。

数据公开下载也不等于用途不受限制。没有确认到数据专用许可时，应写“未确认”，再查看数据包、官方条款或询问发布方；不能把网站或下载工具的代码许可证自动当作数据许可证。

## 8. 读论文时先找一个实例是什么

《Datasheets for Datasets》建议记录数据集的动机、组成、采集、处理和使用等信息，并允许把无法确认的事项明确标为未知。[4] 对初学者最有用的不是背下一张长表，而是学会区分：**程序读入的一条实例，和我们想研究的总体，不一定是同一层次。**

例如，一条一秒 IMU 窗口是训练实例；它来自某次飞行；某次飞行又来自某台设备。想研究新设备性能时，只把窗口随机分开，无法自动制造出新设备证据。这是根据论文的问题框架作出的教学分析，不是论文替我们的实验提供了正确性保证。

## 9. 用两道题检查自己

**题一：走路/跑步识别和位移预测都输入 `[200,6]`，能否使用同一种标签？**

不能。前者可以使用类别编号，后者必须定义时间跨度、坐标系和以米计的位移。输入形状相同，并没有决定目标是什么。

**题二：模型测试很好，但测试窗口与训练窗口大量重叠，能否说明它适用于新用户？**

不能。首先需要排除共享片段造成的泄漏；随后还要检查是否真的按用户留出。完成本篇的标准，是能够把这两种任务各写成一张没有歧义的任务卡，而不是记住几个数据集名称。
