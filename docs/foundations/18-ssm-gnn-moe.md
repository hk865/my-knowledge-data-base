# SSM GNN与MoE 扩展导读

[返回学习导航](00-learning-navigation.md) · [架构模块地图](01-architectures.md)

## 先读两分钟

本页是三条扩展路线的入口，不代替各自完整机制课：SSM改变历史状态的保存方式；GNN按图上的邻居传播信息；MoE选择本次调用的参数子集。

![三条扩展路线](../../assets/foundations/architecture-extensions.svg)


**SSM与Mamba：从状态空间直接借结构。** 线性状态空间系统 h_t=bar Ah_(t-1)+bar Bx_t, y_t=Ch_t+Dx_t可同时理解为递推与长卷积。S4在可训练性和高效计算上发展结构化参数化；Mamba让部分参数依赖输入，实现内容相关的选择，并用适配硬件的scan处理。这里与控制系统的联系比泛泛的RNN类比更直接，但仍不等于具备物理可解释性的Kalman滤波器。适合长流式序列和固定状态内存预算；压缩历史与内容精确检索仍存在权衡。[S4](https://arxiv.org/abs/2111.00396)；[Mamba](https://arxiv.org/abs/2312.00752)

**GNN：当连接来自图。** 消息传递可写 m_i=Σ_(j∈N(i))φ(h_i,h_j,e_(ij))，再以 h_i′=ψ(h_i,m_i)更新节点。图像卷积的规则网格邻域，推广为由图定义的邻域。机器人关节图、场景关系图和位姿图提供自然输入，但“在位姿图上跑GNN”不等于求解了几何最小二乘；是否保留SE(3)结构、规范自由度和误差模型要另查。局部消息多层传播也可能遭遇过平滑和信息瓶颈。[神经消息传递原文](https://arxiv.org/abs/1704.01212)

**MoE：选择参数子集来算。** y=Σ_(e∈TopK(r(x)))g_e(x)f_e(x)，路由器选择少量专家。它主要回答“如何增加容量而控制每个token的激活计算”，常替换Transformer中的FFN，不是与Transformer并列的完整概率建模范式。输入输出维度可以保持不变，训练需处理负载均衡、路由稳定及通信开销；专家也不保证自动对应人类命名的学科。[稀疏门控MoE](https://arxiv.org/abs/1701.06538)


## 接下来怎样读

熟悉控制和SLAM可先读S4状态方程，再看Mamba哪些参数依赖输入。熟悉位姿图可把一个GNN消息步骤与一次几何优化迭代分别画出，找出是否真的优化同一个目标。MoE则从“总参数、每token激活参数、跨设备通信”三项成本入手。这三者与CNN、Transformer、生成目标可以组合，勿强行排成一个取代顺序。
