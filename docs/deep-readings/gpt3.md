# GPT-3：自回归预训练与上下文学习的基线

论文：Brown 等，Language Models are Few-Shot Learners，2020。本文以 [arXiv v4 完整论文](https://arxiv.org/pdf/2005.14165v4) 为依据；正文、训练与污染分析附录已核读，具体覆盖范围见 coverage.md。机制图：[SVG](../../assets/baselines/training/gpt3.svg) / [PNG](../../assets/baselines/training/gpt3.png)。

## 1 为什么选它作基线

GPT-3 的核心问题不是“怎样设计新损失”，而是：把统一的自回归语言模型扩大后，能否仅在输入里放少量示例，就完成原本需要专门微调的任务？它给这条路线提供了清楚的实验坐标：八个规模、相同的训练 token 数、零样本/单样本/少样本三种推理设置，以及广泛且不全成功的任务评测。175B 是其中最大模型，不是论文唯一实验对象。

因此，它适合做“因果语言建模预训练＋ICL”的历史基线，不代表掩码语言模型、去噪编码器解码器、多模态预训练或现代计算最优训练的全部路线。也不能把这里的 few-shot 当成“拿几个样本做梯度微调”：论文专门排除了评测时的参数更新。[§1–2，pp.3–10](https://arxiv.org/pdf/2005.14165v4#page=3)

## 2 目标函数到底教会了什么

把输入文本分词为 z₁,…,zₜ，自回归分解为 pθ(z)=∏ₜpθ(zₜ|z＜ₜ)。训练最小化负对数似然 L_NTP=−E_z∑ₜlog pθ(zₜ|z＜ₜ)，实现中通常再对有效 token 平均。这是对文中自回归训练描述的标准数学展开，并非论文提出的新编号公式。因果注意力使当前位置只能利用前缀；teacher forcing 则让训练时每个位置看到真实历史，可在一次前向中并行算多个位置的预测损失。

损失鼓励“像训练文本那样继续写”，没有直接定义“满足用户意图”“回答真实”“更受人偏好”。这解释了一个重要边界：文章写得逼真与内容可靠是两个问题。论文 §5 已明确指出各 token 等权、目标缺少重要性区分，而且实用助手可能需要目标导向行为而不只是预测。后来指令微调和偏好对齐的动机，在这里已经出现。

推理时，在上下文里组织“任务说明＋K 组输入输出示例＋新输入”，再生成答案。训练更新的是权重 θ；ICL 改变的是前向计算条件和激活，权重不变。示例可能帮助模型识别任务、确定格式、调动已有知识，也可能支持某些临时规则归纳；论文没有证明所有任务都在上下文中从零学会。[§2、§5](https://arxiv.org/pdf/2005.14165v4#page=6)

## 3 数据管线与架构

训练混合物包含过滤后的 Common Crawl、WebText2、Books1、Books2 和英文 Wikipedia。表2.2列出的规模分别约410B、19B、12B、55B、3B token；训练采样权重约60%、22%、8%、8%、3%，合计的微小偏差来自表格取整。权重并不按数据集大小分配，因此少数高质量来源会重复看到，不能把“总训练300B token”解释为“300B不重复的原始文本”。

Common Crawl 先用高质量参考语料训练的逻辑回归分类器进行重采样，再做文档级模糊去重；附录A说明质量筛选仍保留一部分低分文档以保持分布覆盖。MinHashLSH 去重平均减少约10%数据，并额外移除 Crawl 与 WebText 的重复。这是整条训练路线的一部分，不能只复现网络结构而忽略语料选择。

网络沿用 GPT-2 的主要设计，包括预归一化和可逆分词，但各层交替使用稠密注意力与局部带状稀疏注意力。最大模型为96层、隐藏维12288、96个注意力头；上下文长度均为2048。这里的局部稀疏注意力不等于稀疏激活的专家模型。所有八个模型都训练300B token；规模变化同时伴随层数、宽度、学习率和批量调整，不能把对照误称为“只改一个参数”。[表2.1–2.2，pp.8–9；附录A，p.43](https://arxiv.org/pdf/2005.14165v4#page=8)

## 4 训练和推理流程如何复现理解

训练流程可分为四步：清洗和混合语料；打包到2048-token序列；以因果语言模型计算下一个 token 的交叉熵；反向传播并更新权重。短文档之间以结束标记隔开，但没有额外文档隔离注意力掩码。附录B给出 Adam β₁=0.9、β₂=0.95、梯度全局范数裁剪1.0、权重衰减0.1、375M token学习率预热；随后余弦下降，到260B token降到初始学习率的10%。175B的最大批量为3.2M token、学习率6×10⁻⁵。模型并行同时沿矩阵与网络深度展开。[附录B，p.43](https://arxiv.org/pdf/2005.14165v4#page=43)

评测也不只是把题目直接丢给模型。选择题比较候选补全文本的条件概率，多数任务按 token 数归一化；ARC、OpenBookQA、RACE还采用相对无条件答案概率的校正。自由生成按任务用F1、BLEU或exact match，文中采用beam width 4、length penalty 0.6。K通常在10–100之间，但受上下文限制；有开发集时会选择K。复现时必须固定分词、提示格式、示例抽样、评分方式和数据拆分，否则同名few-shot结果不可直接相比。[§2.4，p.10；附录G](https://arxiv.org/pdf/2005.14165v4#page=10)

## 5 定量证据应怎样读

最直接的证据不是一个汇总排名，而是同一模型在不同上下文设置下的变化：

- LAMBADA准确率：zero-shot 76.2%、one-shot 72.5%、few-shot 86.4%（表3.2）。单示例反而变差，说明示例并非越多越自动有效；few-shot同时换成了填空格式，不能把全部增益归于数量
- 闭卷TriviaQA：64.3%→68.0%→71.2%；Natural Questions：14.6%→23.0%→29.9%（表3.3）。同为问答，难度、知识覆盖和提示适配差别很大
- SuperGLUE test平均71.8，BERT-Large微调基线69.0，当时微调SOTA89.0；其中WiC仅49.4%，接近随机（表3.8）。超过某个基线不代表普遍推理能力解决
- 算术表3.9中，两位数加法few-shot 100%，三位数加法80.4%，五位数加法9.3%。正文附近给出80.2%的不同表述，本笔记采用表格80.4%，不把两者混用
- 短新闻辨别人机来源的平均准确率为52%，95%区间49%–54%（表3.11）。这是特定受试者、提示与文章长度下的来源辨别实验，不是真实性测试，更不是通用图灵测试

[表3.2–3.3，pp.12–13；表3.8–3.9，pp.19–23；表3.11，p.26](https://arxiv.org/pdf/2005.14165v4#page=12)

## 6 哪些对照真正支撑机制判断

八个规模与三种示例设置说明：模型规模增加时，很多任务能力改善，且上下文示例收益在大模型上更明显。图1.2还同时改变符号插入任务的示例数量与是否提供自然语言描述；图3.8在SuperGLUE改变K。这比只看175B最终分数更有解释力。

但它不是完整的因果消融：没有在同一计算预算下穷举数据量与参数量，没有直接比较等规模掩码/去噪目标，也没有隔离每种语料的独立贡献。图1.3的42个准确率任务汇总，作者自己提示并非严格、含义统一的benchmark。把它读成“规模使一切能力稳步增加”会错过WiC、ANLI以及个别one-shot退化。[图1.2–1.3、图3.8、§5](https://arxiv.org/pdf/2005.14165v4#page=4)

## 7 测试污染不能只看作者一句结论

论文尝试在训练前去除测试重叠，但过滤错误使部分重叠残留，成本又使重训不可行。之后按n-gram重叠构造clean子集重新评测。附录C给出精确规则：非合成任务的n取数据长度分位数并限制于8–13，不是所有任务机械采用13-gram。

这一审计同时揭示两类风险。第一，文本重叠不必然泄露答案：阅读理解可能只见过背景文章。第二，去除重叠后分数近似不变，也不能严格证明不存在记忆，因为clean子集难度可能变化。PIQA和Winograd结果因此带星号；若干维基语言建模数据集几乎完全重叠，作者干脆不报告。表C.1的数值还用了不同ICL抽样种子，不能与主表当成完全同一次实验。这个处理过程本身就是今天训练基线必须继承的评测纪律。[§4；附录C，pp.43–45](https://arxiv.org/pdf/2005.14165v4#page=31)

## 8 局限及路线中的位置

GPT-3仍会自相矛盾、编造事实、长文失去连贯，且数据偏见不会因规模自然消失。§6对性别、族群与宗教偏见的分析也承认其方法和维度有限。论文没有解决因果推断、可靠长程计划、工具使用或真实环境反馈；也未评测SFT/RLHF后的助手。

在训练路线中，先用它建立“token似然→通用表示与生成能力→上下文调动”的模型。接下来读InstructGPT，问为什么已有能力还需要示范和偏好改变行为；读PPO，理解有评分器后怎样做在线策略更新；再读DPO，理解如何在成对偏好假设下省去显式RM与在线RL循环。相邻方向应补掩码语言建模和去噪序列到序列论文，避免把GPT-3的目标当成预训练唯一选项。这是方法关系图，不是声称所有现代模型都遵循同一配方。

## 9 建议的精读与最小验证路线

第一次按§2→表2.1/2.2→附录B读清数据、网络和更新；第二次按表3.2/3.3/3.8→§4→附录C检验结果；第三次回到§5，区分作者的实验证据与未来解释。用一个小型开源因果模型即可做机制级验证：固定模型，改变0/1/8个示例；再固定K，打乱标签或调换示例顺序，记录exact match及方差。该练习不等于复现175B分数，目的是确认ICL发生在输入条件而不是参数更新，并暴露提示敏感性。

检查自己是否真懂：为什么训练损失下降不保证服从指令？为什么beam search、候选概率归一化与自由采样会产生不同结果？为什么clean子集不能提供绝对无污染证明？能回答这三问，比记住175B这个数字更接近掌握这篇基线。

## 10 从规模实验延伸的研究问题

附录D以近似计算量对比训练预算，最大模型约3.14×10²³ FLOPs，计算中忽略了占比较小的注意力操作。这个数是作者估算，不是云平台账单，也不能转换成一个通用训练价格。论文按当时的缩放分析选择较大的模型和较少的训练token；今天若研究计算最优方案，应另设同计算预算的模型规模与数据量网格，不能只继承其300B设定。机制研究则可问：示例主要提供标签映射、输出格式，还是新规则？通过保留格式但打乱标签、替换实体、改变顺序等受控干预，才能逐步区分这些解释。上述是由论文局限延伸的实验建议，并非该论文已经完成的结论。
