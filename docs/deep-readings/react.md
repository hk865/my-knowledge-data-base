# ReAct 精读：把工具反馈放回语言模型的决策上下文

论文：Yao 等，ReAct: Synergizing Reasoning and Acting in Language Models。本文固定阅读 arXiv:2210.03629v3（2023-03-10，ICLR 2023），33 页；正文、A–E 附录均已阅读。它在本系列中是单 Agent 交互方法及实验基线，不是新的基础模型，也不是强化学习训练算法。[原文](https://arxiv.org/pdf/2210.03629v3)

## 一句话抓住机制

让语言模型交替产生文字推理与环境动作，再把真实环境返回的观察接回上下文。推理用于拆任务、记进度、决定下一步查什么；动作使模型获得参数记忆以外的信息。主实验使用冻结模型加少量示例，闭环中变的是上下文，不是模型权重。

## 1 输入怎样变成状态与输出

输入可以是 HotpotQA 问题、FEVER 待验证命题、ALFWorld 家务目标，或 WebShop 商品需求。模型还收到少量人工编写的完整示例轨迹。论文把历史记作 cₜ=(o₁,a₁,…,oₜ)，策略为 π(aₜ|cₜ)。ReAct 将动作空间扩为 Â=A∪L：A 是环境支持的动作，L 是语言表达空间。若本步是 thought，只有 cₜ₊₁=(cₜ,thought)；若本步是 search、click、go to 等动作，执行器先调用环境，新的 observation 再进入下一轮上下文。这里的“状态”是可见交互历史，不能直接视作完整、正确的环境状态。[§2，pp3–4]

知识任务采用密集 thought→action→observation 交替。长程决策允许稀疏思考，由模型在重要节点插入计划或检查，连续几个动作之间未必都有一段文字。把 ReAct 简化成必须逐动作写长推理，会遗漏这个关键设计。[§2、§4]

维基百科工具只有三类：search[entity] 命中后取页面前五句，未命中给相近条目；lookup[string] 返回当前页面下一条匹配句；finish[answer] 提交答案。作者故意使用弱于现代检索器的接口，以研究语言驱动的检索过程。模型选择查询、接收查询结果、再改查询，才是闭环；仅在提示词里放一句“使用工具”不构成同样的系统。[§3.1]

## 2 为什么这个最小改动可能有效

Act-only 已经有工具反馈，却要求一次隐式推断直接决定动作。ReAct 给中间状态一个文字载体。例如寻找并清洗刀具时，拿到刀和清洗完刀是不同子目标；把已完成阶段写入上下文，能降低“再找一把刀”或“尚未去水槽就清洗”的循环错误。反向作用同样重要：模型的计划如果建立在错误事实之上，外部搜索可能迫使它改写计划。[§4；附录 D.2]

但文字状态仍可能写错。作者展示人工修改两处 thought 后使 ALFWorld 个例成功，说明这是一种可干预接口；它不证明文字轨迹完整解释了网络内部计算，更不构成可靠性保证。本笔记将“可检查的决策记录”和“忠实、因果性的内部解释”分开理解。[附录 A.3、Figure 5]

## 3 反馈、损失与训练不能混淆

主提示实验没有新增 ReAct 损失函数，没有在线梯度更新，也没有把环境成功奖励送入 PPO。评估指标是任务反馈的另一层用途：HotpotQA 用答案 exact match，FEVER 用分类准确率，ALFWorld 用任务成功率，WebShop 同时报属性覆盖分数及全部要求满足的成功率。一次工具返回是后续决策的输入，成功率是跨样本统计，两者不是同一个训练信号。

论文另做小模型微调：用模型生成且最终答案正确的 3,000 条轨迹，训练 PaLM-8B/62B 根据问题解码 thoughts、actions、observations。机制可概括为自回归轨迹负对数似然 L=−Σᵢ log pθ(yᵢ|x,y＜ᵢ)；这是对叙述的标准化表达，原文未把它编号为专门的 ReAct 目标。推理时 observation 仍应来自环境，不能用模型预测的观察代替工具事实。[§3.2；附录 B.1]

B.1 明确 batch size 64；Act/ReAct 两种规模均训练 4,000 steps，Standard/CoT 在 8B 训练 2,000、62B 训练 1,000 steps。不同最佳步数与正确答案筛选都是结果的条件，不能把微调提升完全归给一种提示格式。

## 4 实验到底说明了多少

知识任务主要用 PaLM-540B；HotpotQA 有六条人工示例，FEVER 三条。CoT-SC 以温度 0.7 采样 21 次多数投票。Table 1 的 HotpotQA EM：Standard 28.7、CoT 29.4、Act 25.7、ReAct 27.4。因而“ReAct 在所有知识任务上胜过 CoT”是错的；此处它优于 Act，却低于 CoT。FEVER 则分别是 57.1、56.3、58.9、60.9。[Table 1，p5]

作者结合两种知识来源：ReAct 在 7 步 HotpotQA 或 5 步 FEVER 内无答案时退回 CoT-SC；反方向在多数答案不足样本数一半时切到 ReAct。ReAct→CoT-SC 得 HotpotQA 35.1；CoT-SC→ReAct 得 FEVER 64.6。它们有额外采样和工具预算，不可当作与单次生成等成本的比较。Table 1 的监督系统达到 67.5、89.5，也说明这里的目标不是宣称当时两个数据集的总榜第一。[§3.2–3.3，Table 1、Figure 2]

Table 2 分析 ReAct/CoT 各 50 条成功、50 条失败轨迹，共 200 条人工检查。ReAct 成功例中 94% 被判为正确推理与事实，CoT 为 86%；失败例中的幻觉标签为 0% 与 56%。这只是该抽样及分类下的占比，不是“ReAct 幻觉率为零”。ReAct 失败中的推理错误占 47%，搜索结果错误 23%，说明外部证据换来了检索依赖和循环风险。[Table 2，p6；附录 E]

ALFWorld 在 134 个 unseen games、六类任务上测试。每类标三条示例，取两条的六种排列构成六套提示。Table 3 的 ReAct 平均成功率 57%，best-of-six 71%；Act best 45%，BUTLER best-of-eight 37%。摘要所谓提高 34 个百分点，来自 71−37 的最佳设置比较，不能把 71% 写成随机提示平均值。ReAct-IM 的平均/best 为 48/53%，支持稀疏、灵活的子目标和常识推理比该受限反馈模板更有效，但不证明对全部 Inner Monologue 实现占优。[§4，Table 3，p8；B.2]

WebShop 有 118 万商品、1.2 万人类需求，测试 500 条需求。Table 4 的 ReAct 分数/成功率为 66.6/40.0；Act 为 62.3/30.1，IL 为 59.9/29.1，IL+RL 为 62.4/28.7，人类专家 82.1/59.6。主要结论是少示例语言模型在这个研究环境中优于所列训练基线；仍明显落后人类，也没有测试真实付款、登录、网页变动或安全审批。[§4、Table 4]

## 6 在路线图上的位置和边界

ReAct 的最小学习价值是“语言上下文维护＋有限动作接口＋真实观察回写”。它连接 GPT 式序列模型与 Agent 工具交互，适合做 Act-only、reason-only、混合策略的对照。它不提供多 Agent 协作、长期记忆管理、工具权限、可靠终止或安全沙箱的完整方案，也不能凭文字动作直接替代四足机器人高频关节控制。

作者结论是推理与行动协同能提高多类任务表现，并提出更多人工轨迹、微调及 RL 的后续可能。本笔记的分析是：最重要的工程抽象不是“写得更长”，而是明确哪些内容来自模型、哪些来自外界、失败如何改变下一步。复现时应同时记录模型版本、提示排列、采样/步数预算、工具返回快照、无效动作率和循环率；只报最终成功率会掩盖成本与脆弱点。

## 7 从一个最小复现实验检查自己是否读懂

可以先固定同一批问题、同一底座模型和同一工具接口，准备三份由同一示例轨迹删改出的提示。第一份保留动作和观察、删去思考；第二份保留思考、删去动作和观察；第三份全部保留。前两份分别隔离“只有行动”和“只有内部知识推理”，第三份才测试协同。不能给第三份额外更好的示例，却把差距都解释为交替机制。

执行器需要能识别工具名和参数，并在收到工具返回前暂停模型生成；否则模型可能自行续写一个看似合理的观察。每轮应存下原始返回和被截断后真正进入上下文的内容。遇到搜索无结果，下一步是改实体名、改查询或终止，不能悄悄换一个更强检索系统而仍声称复现论文的三动作接口。

评估时先锁定最大工具步数、最大生成长度和采样数。对有回退的组合策略，分别报告单次模型调用、总生成 token、工具调用和端到端时间。本论文的优势包含结构设计，也可能消耗更长轨迹；统一预算能回答“相同成本下是否更好”这个主表没有完全隔离的问题。这是本笔记提出的复现检查，不是作者已经完成的额外实验。

还应把两类失败分开：一类是工具没找对页面，另一类是页面给了足够证据却推理错误。前者可能需要检索接口改造，后者可能需要更好的底座或训练数据。轨迹中连续重复动作是第三种工程症状，可设置循环检测供诊断；但若加入新终止规则，就应作为改进版另报结果。

最后确认权限边界。论文伦理声明说 WebShop 不会真实购买，维基百科接口也不能编辑页面。把这些无副作用动作替换成真实支付或文件修改，会新增执行风险。ReAct 只说明怎样组织决策和反馈，并没有替使用者解决行动授权问题。
