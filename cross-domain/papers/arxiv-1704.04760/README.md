# In-Datacenter Performance Analysis of a Tensor Processing Unit

> 状态：文献卡 · 2017 · [原文](https://arxiv.org/abs/1704.04760)

[返回跨方向方法目录](../../README.md) · [原文与阅读记录](source.json)

- **解决什么**：数据中心里神经网络推理的需求快速增长，通用 CPU 与 GPU 为平均吞吐做的优化（缓存、乱序执行、多线程）不适合推理应用严格的第 99 百分位响应时间要求。
- **核心方法**：一块专用 ASIC（自 2015 年部署）：核心是 65,536 个 8 位乘加单元组成的脉动阵列（数据按固定节拍在相邻单元之间流动，权重预先载入，从片上缓存读一次就被多次复用，以省下读写 SRAM 的能耗），峰值 92 TOPS，配 28 MiB 软件管理的片上存储。在占其数据中心推理需求 95% 的六个生产应用（MLP、CNN、LSTM 各两个）上，平均比同期 K80 GPU 与 Haswell CPU 快 15–30 倍，每瓦性能高 30–80 倍。用 roofline 模型分析后，六个应用中有四个（MLP 与 LSTM）受内存带宽限制，只有 CNN 受计算限制；把内存带宽提高 4 倍，性能平均提高约 3 倍，提高时钟几乎无用。
- **为什么在这个库里**：[观点：深度学习的规模化](../../../perspectives/scaling.md)中算力线“设计结构·特化”一步的原始证据，同时说明特化之后瓶颈移到了内存带宽。它只做推理，作者写明训练当时仍用现成的 GPU（原文 §2 开头的项目起源一段）。优先级：选读。
