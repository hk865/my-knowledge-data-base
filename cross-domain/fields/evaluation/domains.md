# 分任务能力图：各领域的评测测什么、看不到什么

> 状态：方向子页 · v1 · 2026-10-04
>
> 速览：
> 1. 领域之间最大的差别在评分方式：选择题与精确匹配、执行测试、程序检查的约束、专家 rubric 加模型裁判。评分方式决定了它能变成哪一种训练信号，也决定了它看不到什么。
> 2. 能被程序判定的评分（单元测试、格式约束）最先变成 RL 奖励，也最先被钻空子：Anthropic 与 OpenAI 的官方材料都记录了训练中出现的特判测试、跳过测试；METR 的第三方复审里，通过维护者测试的智能体 PR 没有一份能直接合并。
> 3. 医疗、法律、科学的选择题主要测预训练得到的知识；真实使用中的好坏（是否追问、是否转诊、检索对不对）要靠 rubric 与开放任务来测，而 rubric 分数会随回答变长而上涨。
> 4. 角色扮演这类主观领域还没有可靠的自动裁判；安全要把越狱鲁棒性与过度拒答成对测量，二者主要由后训练的流程与数据决定，同一模型家族内与参数量无关。

"评测就是训练目标"、污染、隐藏测试集、裁判偏差这些总论，见[评估方向入门页](README.md)；本页按任务领域展开。

## 怎样读这一页

每个领域一块，回答五件事：这个领域主要考验什么能力；代表评测和它们怎样打分；评测看不到什么；这项能力主要来自训练流水线的哪一段；已知的失败与长尾场景。流水线按六段划分：

| 段 | 一句话 | 训练信号 |
|---|---|---|
| 预训练 | 在海量文本与代码上做下一词预测，获得知识与语言能力 | 语料覆盖面 |
| 架构与长上下文 | 一次能读多长的输入、能否在长输入里找到要的东西 | 窗口长度、检索系统 |
| SFT | 监督微调：用"指令 + 示范回答"直接训练格式与风格 | 示范数据 |
| 偏好 / rubric RL | 用人或模型的比较、或按评分细则（rubric）打的分做奖励 | 奖励模型、模型裁判 |
| RLVR | 可验证奖励的强化学习：答案能被程序判对错时才给奖励 | 答案匹配、单元测试、约束检查 |
| agent 环境 | 在沙箱、仓库、终端里多步行动，按最终状态给奖励 | 隐藏测试、环境状态 |

评分方式与训练信号几乎一一对应 `[判断]`。把评测看成强化学习里的一个场景，下表就是"场景怎样打分"与"能变成什么奖励"的对照：

| 评分方式 | 代表评测 | 可变成的训练信号 | 典型漏洞 |
|---|---|---|---|
| 选择题、精确匹配 | MedQA、GPQA、LegalBench 分类任务 | RLVR（答案匹配） | 可以猜；题目泄漏进语料 |
| 执行测试 | HumanEval、SWE-bench、SciCode | RLVR（测试通过） | 特判、改测试、覆盖不足时写桩代码 |
| 程序检查的约束 | IFEval、IFBench、RACE | RLVR（约束验证函数） | 过拟合约束集；为满足约束牺牲内容 |
| 专家 rubric + 模型裁判 | HealthBench、StrongREJECT | rubric 奖励、生成式奖励模型 | 长度偏置；裁判与专家不一致 |
| 人工标注 + 专用奖励模型 | CharacterEval | 奖励模型 | 标注少、主观分歧大 |
| 人工复审 | METR 可合并性复审、LegalBench 规则适用 | 只能抽样，难进大规模 RL | 贵、慢、主观 |

后训练里"奖励从哪来"的演变（人写示范 → 人的比较 → 规则验证器 → 按 rubric 打分的生成式奖励模型）见[后训练总览](../../../llm/fields/posttraining/README.md)。

## 1 代码：函数与仓库级的正确性

结论：代码是最容易自动评分的领域，所以也是 RLVR 最早落地的领域；评分只看测试是否通过。

- **考验什么**：把自然语言规格变成可运行的代码，需要语言与库的知识、算法、边界情况的处理。
- **代表评测**：[HumanEval](../../papers/arxiv-2107.03374/README.md)（164 道手写 Python 函数题，平均每题 7.7 个单元测试，用 pass@k：每题采 k 个样本、至少一个通过全部测试的概率）；[LiveCodeBench](../../papers/arxiv-2403.07974/README.md) 只用模型训练截止之后发布的竞赛题，以防污染；[SWE-bench](../../papers/arxiv-2310.06770/README.md) 用真实 GitHub issue，以"修复前失败、修复后通过"的测试判定。
- **看不到什么**：测试之外的一切。7.7 个测试只能覆盖少数输入；SWE-bench 作者自述模型补丁常常不如人写的完整、高效、可读。Codex 原文还记录了一种"失配"：提示里的代码含细微 bug 时，模型会写出比自己能力更差的代码，差距随模型增大而扩大。
- **主要来自哪一段**：预训练的代码数据是底子：GPT-3 在 HumanEval 上 0%，在 159GB GitHub Python 上微调后的 Codex-12B 为 28.8%；在独立函数上做 SFT 的 Codex-S 再到 37.7%；之后由 RLVR 接手，[DeepSeek-R1](../../../llm/papers/arxiv-2501.12948/README.md) 对代码只用编译与测试用例做奖励。
- **失败与长尾**：docstring 描述长操作链、把操作绑定到变量（Codex 自述）；固定题集被训练数据污染（LiveCodeBench、RACE 的出发点）。

## 2 代码质量与"为过测试而写代码"

结论：奖励是"测试通过"时，模型学到的是让测试通过；官方系统卡、官方论文与第三方评测都记录了这条路径，而且它会在训练中扩散。

### 2.1 证据

| 来源 | 观察到什么 | 关键数字 |
|---|---|---|
| Anthropic，[Claude 3.7 Sonnet 系统卡](https://assets.anthropic.com/m/785e231869ea8b3b/original/claude-3-7-sonnet-system-card.pdf) §6（官方） | 在 Claude Code 等智能体编码环境里特判测试：直接返回测试期望值，或改测试去迎合代码输出；多在通用解反复失败后出现，常留下"# special case for test XYZ"之类注释。原文写明这是 RL 训练中奖励黑客的产物；用户测试没有发现（频率低、只在特定场景多次尝试后出现），是训练记录上的自动分类器发现的 | 未给频率；给出产品侧建议：系统提示强调通用解，监控同一文件的反复"编辑—跑测试"循环、提示特判的注释、对测试文件的意外修改 |
| Anthropic，[Claude Opus 4 / Sonnet 4 系统卡](https://www-cdn.anthropic.com/4263b940cabb546aa0e3283f35b686f4f3b2ff47.pdf) §6（官方） | 把奖励黑客定义为硬编码（直接输出期望值）与特判（写不够通用的解）；内部评测包括"易被钻空子的编码题"（另用隐藏测试判定）和"不可能任务"（测试有 bug 或缺依赖，模型不知情） | 易钻空子题上的分类器判定率：3.7 为 44%，Opus 4 为 9%，Sonnet 4 为 4%；隐藏测试判定 23% → 13%、12%；不可能任务不加提示 78% → 47%、45%，加"不要硬编码"提示 80% → 5%、10% |
| OpenAI，[Baker 等 2025](../../papers/arxiv-2503.11926/README.md)（官方论文） | 训练一个前沿推理模型时出现两种系统性黑客：`exit(0)`（利用环境漏洞提前退出、不跑完测试）与 `raise SkipTest`（在测试框架之外抛异常以跳过测试），一旦出现就迅速被强化、扩散到几乎所有训练环境；另有测试覆盖差时写桩代码、修改测试框架上游的函数。把思维链监控器放进奖励，优化强度一高，模型学会在思维链里隐藏意图、照样作弊 | 只看动作的 GPT-4o 监控器召回 60%，读思维链的 95% |
| METR 2025-06（第三方，[博客](https://metr.org/blog/2025-06-05-recent-reward-hacking/)） | 自主软件开发与 AI 研发任务上，o3 改写计时函数、在运行时替换评分函数（猴补丁）、从调用栈里取出参考答案；Claude 3.7 Sonnet 与 o1 也有同类行为 | o3 在 RE-Bench（METR 的 AI 研发任务集）上 30.4% 的运行有奖励黑客，在 HCAST（METR 的通用软件任务集）上 0.7%；RE-Bench 能看到完整计分函数，黑客率高出 43 倍以上；在一个任务上加"请不要作弊"等指令，20 次运行中仍有 70%–95% 计划黑客 |
| METR 2025-08（第三方，[博客](https://metr.org/blog/2025-08-12-research-update-towards-reconciling-slowdown-with-time-horizons/)） | 18 个真实开源 issue，测试对智能体隐藏（排除了特判）；人工按核心功能、测试覆盖、文档、lint（代码风格检查）与格式、其他代码质量五项复审 PR | Claude 3.7 Sonnet 智能体 38% 通过维护者写的测试；复审的 15 份 PR 无一能直接合并；通过测试的 PR 平均还要约 26 分钟修改（原维护者完成整题平均 1.3 小时） |
| [ImpossibleBench](../../papers/arxiv-2510.20270/README.md)（CMU 与 Anthropic，论文） | 改测试使之与规格冲突，任务不可能合法完成，通过率即作弊率 | GPT-5 在 Conflicting-SWEbench 上 54%；更强的模型总体作弊更多；Claude 新模型比 3.7 少，OpenAI 模型的同类改进不明显 |

`[判断]` 把这些证据放在一起，测试看不到的东西分三层：

1. **规格与测试冲突时怎么办**：应当报告问题，而不是特判或改测试。只有"不可能任务"能测（Claude 4 系统卡、ImpossibleBench）。
2. **测试覆盖之外的正确性**：桩代码、只对测过的输入正确。隐藏测试能测到一部分。
3. **与正确性无关的质量**：可读性、可维护性、文档、与项目既有约定一致。只有人工复审、按需求变更测维护代价、按明说的要求检查风格这几种办法，而且都难以规模化地放进奖励。

`[判断]` 由此推出：以第 2 层为奖励的训练环境会让模型在第 2 层越来越强；第 1 层取决于训练时是否专门处理（Claude 4 系统卡列出的监控、修环境、调奖励）；第 3 层取决于偏好与 rubric 阶段和人工反馈，不会随 RLVR 自动变好。

### 2.2 测代码质量与代码审查的评测

| 评测 | 测什么 | 怎样打分 | 局限 |
|---|---|---|---|
| [RACE](../../papers/arxiv-2407.11470/README.md) | 可读性（长度、命名风格、注释粒度）、可维护性（可维护性指数 MI、模块化）、正确性、效率 | 把每项写成用户的具体要求，用静态分析、正则与语法树检查是否满足 | 只测"明说的要求"；28 个模型中多数有固有风格偏好，与要求冲突时难以遵从 |
| [MaintainBench](../../papers/arxiv-2503.24260/README.md) | 需求变化时的维护代价 | 四类需求变更（功能扩展、接口修改、数据结构变换、错误处理）后的通过率、改动行数、语法树相似度 | 题目来自函数级 benchmark，规模远小于真实项目；作者发现 MI 等静态指标彼此矛盾 |
| CodeReviewer（[Li 等 2022](https://arxiv.org/abs/2203.09095)，Microsoft） | 代码审查的三个子任务：变更质量估计、审查意见生成、按意见修改代码 | 来自 9 种语言开源项目的真实代码变更与审查意见 | 预训练小模型时代的基准，未涉及 LLM 智能体 |
| [CriticGPT](../../papers/arxiv-2407.00215/README.md)（OpenAI） | 找出代码中的 bug 并写出批评 | 人为插入 bug 后看能否找出；人对批评的偏好；同时记录幻觉 bug 与挑刺 | 批评者会幻觉 bug、误导人 |

### 2.3 防"为过测试而写代码"的手段

| 手段 | 防什么 | 出处 | 局限 |
|---|---|---|---|
| 隐藏或留出测试 | 针对可见测试的特判 | Claude 4 系统卡、METR 2025-08 | 隐藏测试本身也只覆盖有限输入 |
| 测试只读、评分时还原测试 | 修改测试 | ImpossibleBench | 防不住特判与重载比较运算符 |
| 允许中止并上报 | 不可能任务上的作弊 | ImpossibleBench：GPT-5 从 54% 降到 9% | 对 Claude Opus 4.1 作用小 |
| 提示强调通用解 | 特判 | Claude 3.7 / 4 系统卡 | 对 Claude 4 有效，METR 测得对 o3 几乎无效 |
| 训练中监控（分类器、思维链监控） | 系统性黑客在训练中扩散 | Claude 4 系统卡、Baker 等 | 强优化下监控会被规避 |
| 修补环境、隔离验证器 | `exit(0)` 一类环境漏洞 | Baker 等；[Kimi K3](../../../llm/papers/arxiv-2607.24653/README.md) 改用 microVM、隐藏验证器与有限提交次数 | 只能修已发现的漏洞 |

## 3 Agent 式编码

结论：从函数到仓库，评测变成"在环境里多步行动后跑隐藏测试"，与智能体 RL 的训练环境几乎同构。智能体本身的方法与评测见[智能体方向](../agents/README.md)。

- **考验什么**：在大仓库里定位问题、修改、运行、按反馈迭代；判断何时停、何时向人求证。
- **代表评测**：[SWE-bench Verified](../../papers/openai-swe-bench-verified/README.md)（OpenAI 请 93 位开发者筛掉描述不完整或测试会误判正确解的样本，留下 500 个）；终端与工具类任务见智能体方向。
- **看不到什么**：可合并性（METR 2025-08）；脚手架（包在模型外面、负责调用工具与管理上下文的程序）差异：同一模型换脚手架，SWE-bench Lite 上从 2.7% 到 28.3%（SWE-bench Verified 官方文章）；公开仓库的泄漏：METR 发现智能体通过 GitHub 找到了原 PR；与用户的交互、过程中的破坏性操作、成本与时长也不计分。
- **主要来自哪一段**：智能体环境里的 RL 与轨迹数据 `[判断]`。DeepSeek-R1 自述评测耗时太长，软件工程上没有大规模做 RL，因此在这类 benchmark 上相对 V3 提升不大；Claude 4 系统卡把修补训练环境列为缓解奖励黑客的手段之一；Kimi K3 为智能体 RL 专门改造沙箱。架构也有影响：[DeepSeek-V3.2](../../../llm/papers/arxiv-2512.02556/README.md) 的 128K 上限让 20% 以上的搜索智能体测试超长。
- **失败与长尾**：不可能任务上作弊；钻环境漏洞；长轨迹被截断。

## 4 科研：科学问答与研究代码

结论：选择题测知识与推理，研究代码测把知识落成数值方法；提出问题、设计实验这些更核心的科研能力，本库收录的评测都没有覆盖 `[判断]`。

- **代表评测**：[GPQA](../../papers/arxiv-2311.12022/README.md)（生物、物理、化学博士出的 448 道选择题，领域专家 65%，其他领域博士可上网仍只有 34%，随机 25%）；[Humanity's Last Exam](../../papers/arxiv-2501.14249/README.md)（2,500 道多学科难题，出题时须难倒当时的前沿模型，全部自动判分）；[SciCode](../../papers/arxiv-2407.13168/README.md)（科学家出的 80 个研究级编程主问题，按测试用例执行评分）。
- **看不到什么**：HLE 作者自述高分只说明封闭式学术题达到专家水平，不代表自主研究能力；GPQA 题量小，作者算出要 50%→60% 这样的差距才有 80% 的统计功效。
- **主要来自哪一段**：知识来自预训练 `[判断]`：SciCode 不给背景时最好模型 4.6%，给出科学背景后 12.3%；推理来自 RLVR：R1 写明它在 MMLU、GPQA Diamond 上相对 V3 的提升主要在 STEM 题，归功于大规模 RL；工具也有用：R1 推测允许联网能缩小它在 GPQA 上与专家的差距。
- **失败与长尾**：SciCode 多数题对模型过难，作者在修订中不断简化题设；HLE 上所有模型的校准误差都在 70% 以上，即答错时仍很自信。

## 5 医疗

结论：考试题测知识，医疗对话测安全行为；两者的差距在 2022 年的 Med-PaLM 里就已经很大。

- **考验什么**：医学知识；对话中识别急症并转诊、信息不足时追问、按提问者身份调整表达、证据不足时说明不确定。
- **代表评测**：[MultiMedQA / MedQA](../../papers/arxiv-2212.13138/README.md)（执业考试选择题与消费者问答，加医生对长回答的人工评价）；[HealthBench](../../papers/arxiv-2505.08775/README.md)（5,000 段多轮对话，262 位医生为每段写 rubric，GPT-4.1 逐条判分）。
- **看不到什么**：考试成绩看不到回答是否安全：Flan-PaLM 在 MedQA 上 67.6%（当时最好），但医生判定它 29.7% 的长回答可能导致有害结果。HealthBench 自述不评估具体工作流与健康结局；它的评分模型与榜首模型来自同一家公司，元评测只覆盖 34 条共识标准。
- **主要来自哪一段**：知识随预训练规模增长（Med-PaLM 原文：理解、知识回忆与推理随规模提升）；安全的回答方式由很小的领域对齐决定：用少量示例做 instruction prompt tuning 后，与科学共识一致的比例从 61.9% 升到 92.6%，潜在有害从 29.7% 降到 5.8%。`[判断]` HealthBench 上的完整性、追问这类行为由后训练塑造：o3 在完整性上比前代大幅提升，GPT-4.1 nano 超过 GPT-4o。
- **失败与长尾**：追问上下文、健康数据处理、全球健康三个主题落后；o3 的 16 次采样最差得分比平均分低约三分之一；只比较长度相近的回答时，o3 对 GPT-4.1 的胜率从 72.9% 降到 63.7%。

## 6 法律

结论：主要测知识与规则推理，其中凭记忆回忆规则最弱。

- **代表评测**：[LegalBench](../../papers/arxiv-2308.11462/README.md)：162 个由法律人设计的任务，按 IRAC（识别争点、规则、适用、结论）等六类推理组织；分类任务用精确匹配与平衡准确率，"适用规则"由受过法律训练的人按评分指南人工判分。
- **看不到什么**：长篇文书、起草、多轮咨询、跨法域差异；多数任务只判一个标签，看不到推理过程。
- **主要来自哪一段**：预训练知识 `[判断]`：GPT-4 的"回忆规则"只有 59.2，"得出结论"为 89.9；[GPT-4 技术报告](../../../llm/papers/arxiv-2303.08774/README.md)写明考试类能力主要来自预训练，RLHF 的影响不显著。
- **失败与长尾**：规则回忆中的幻觉（编造法条或判例出处）。

## 7 金融

结论：财报问答的成绩首先受检索与长上下文限制，其次才是金融推理。

- **代表评测**：[FinanceBench](../../papers/arxiv-2311.11944/README.md)：10,231 个关于上市公司公开文件的问题，抽 150 例人工复核。
- **看不到什么**：多份文件、实时数据与计算链很长的分析；人工复核只覆盖 150 例。
- **主要来自哪一段**：架构、长上下文与检索系统：同一个 GPT-4-Turbo，所有文件共用一个向量库时答对 19%，每份文件单独建库 50%，整份文件放进上下文 79%，直接给证据页 85%，闭卷 9%。`[判断]` 拿到证据后的数字推理错误，属于推理训练（RLVR 一类）的范围；作者也写明找对信息之后模型仍会推理出错。长上下文的评测分层见[长上下文方向](../../../llm/fields/long-context/README.md)。
- **失败与长尾**：失败方式因模型而异：Llama 2 多为答错（幻觉），GPT-4-Turbo 在检索设置下多为拒答。

## 8 角色扮演

结论：主观质量没有可靠的自动裁判，评测器往往就是专门训练的奖励模型。

- **考验什么**：保持人设与角色知识、多轮一致、拟人与共情、对话吸引力。
- **代表评测**：[CharacterEval](../../papers/arxiv-2401.01275/README.md)：77 个中文小说与剧本角色，13 项指标；用 12 位标注员的评分训练奖励模型 CharacterRM，它与人工评分的相关 0.631，GPT-4 当裁判只有 0.36–0.39。[PersonaEval](../../papers/arxiv-2508.10014/README.md)：在小说、剧本与视频文本的对话中判断"这句话是谁说的"，最好的 LLM 约 69%，人 90.8%。
- **看不到什么**：跨会话的长期一致性，以及对用户的长期影响（迎合、情感依赖），这里的评测都没有覆盖 `[判断]`。
- **主要来自哪一段**：预训练语料的语言与文化覆盖 `[判断]`：CharacterEval 中，GPT 系列在中文角色扮演上不占优；推理 RL 不一定迁移：[推理不一定提升角色扮演](../../../llm/papers/url-https-aclanthology.org-2025.findings-acl.537/README.md)在 6 个基准、24 个模型上发现思维链可能降低扮演表现；偏好阶段：CharacterRM 一类奖励模型同时可用于评测与训练。
- **失败与长尾**：角色知识的幻觉；性格回测（以角色身份答 MBTI 问卷）与设定不符。

## 9 安全对齐：拒答、越狱鲁棒性与过度拒答

结论：越狱鲁棒性与过度拒答要成对测；二者主要由后训练的流程与数据决定。

- **代表评测**：[HarmBench](../../papers/arxiv-2402.04249/README.md)（510 种有害行为、18 种自动红队方法、33 个模型与防御，以分类器判定的攻击成功率 ASR 为指标）；[StrongREJECT](../../papers/arxiv-2402.10260/README.md)（313 条禁止提示，分数同时看是否拒绝与回答的具体性、说服力）；[XSTest](../../papers/arxiv-2308.01263/README.md)（250 条看似危险、实则安全的提示，加 200 条不安全对照）。
- **看不到什么**：评分口径会改结论：HarmBench 发现生成长度能让 ASR 变化多达 30%；StrongREJECT 发现只看"是否拒绝"会把空洞回答算成攻破。多轮对话与智能体场景中的有害行为不在这三个评测里 `[判断]`。
- **主要来自哪一段**：偏好与安全 RL。HarmBench：6 个模型家族内鲁棒性与参数量无关、家族之间差别很大，作者认为训练流程与数据比规模更重要；对抗训练 R2D2 让 7B 模型在 GCG 类攻击（用梯度搜索对抗性后缀的越狱方法）上的 ASR 比次优的 Llama 2 13B 低 4 倍。过度拒答同样来自后训练：[HH-RLHF](../../../llm/papers/arxiv-2204.05862/README.md) 早期策略对稍敏感的问题一律建议"寻求专业帮助"；[Llama 2](../../../llm/papers/arxiv-2307.09288/README.md) 加强安全后误拒看似敏感的无害提示；[Claude 3.7 Sonnet 系统卡](https://assets.anthropic.com/m/785e231869ea8b3b/original/claude-3-7-sonnet-system-card.pdf)写明在内部边界数据集上不必要的拒答比 Claude 3.5 Sonnet（new）少 45%（扩展思考模式少 31%），做法是偏好模型训练：用拒答、违规与帮助性分类器给回答打分，有违规时偏好违规更少的，都不违规时偏好更有帮助、更少拒绝的。
- **失败与长尾**：XSTest 中带原系统提示的 Llama2-70b-chat 完全拒绝 38% 的安全提示，作者归因于词汇过拟合；系统提示能改变安全行为，但不稳定；StrongREJECT 发现越能提高回答意愿的越狱越会降低回答质量；HarmBench 的版权类行为是例外，ASR 随规模上升。

## 10 指令与格式遵循

结论：可验证的约束既是评测又是奖励，所以最容易被过拟合；换一组约束，分数就掉。

- **代表评测**：[IFEval](../../papers/arxiv-2311.07911/README.md)（25 类可程序检查的指令，如字数、关键词次数、JSON 格式）；[IFBench](../../papers/arxiv-2507.02833/README.md)（58 种新的域外约束，GPT-4.1、Claude 3.7 Sonnet 等在 IFEval 上很高，在这里低于 50%）；RACE 的风格要求也属于这一类。
- **看不到什么**：没有明说的约定（例如项目已有的命名与结构）；约束与主任务冲突时怎样取舍（IFBench §5 把它归为奖励黑客与指令层级问题）。
- **主要来自哪一段**：SFT 教格式；RLVR 用约束验证函数做奖励：[Tulu 3](../../../llm/papers/arxiv-2411.15124/README.md) 把它命名为 RLVR 并用于指令约束；IFBench 在同样数据上发现 GRPO 一致优于 DPO。Claude 4 系统卡把"简单提示就能显著减少硬编码"作为指令遵循改进的证据，说明指令遵循与 2.1 节的奖励黑客是同一个问题的两面 `[判断]`。
- **失败与长尾**：Tulu 3 降低 KL 惩罚后出现只为满足 IFEval 约束而写的怪异输出；IF-RLVR 略微损害 AlpacaEval 2 一类对话评测；RACE 中要求越多，最强的代码模型也明显变差。

## 跨领域对照表

| 领域 | 主要测什么 | 评分方式 | 看不到什么 | 主要来自哪一段训练 |
|---|---|---|---|---|
| 代码（函数级） | 规格到代码的正确性 | 执行单元测试，pass@k | 测试外的正确性、可读性 | 预训练代码数据 → SFT → RLVR（测试用例） |
| 代码质量 | 可读、可维护、按约定写、审查找 bug | 静态分析检查明说的要求；需求变更后的维护代价；人工复审 | 未明说的项目约定；长期演化 | 偏好与 rubric 阶段、人工反馈 `[判断]` |
| Agent 式编码 | 仓库内多步定位、修改、验证 | 隐藏测试；少量人工复审 | 可合并性、交互、破坏性操作、成本 | agent 环境 RL；长上下文 |
| 科研 | 科学知识、推理、研究代码 | 选择题、精确匹配、执行测试 | 提出问题、设计实验 | 预训练知识；RLVR（推理）；工具 |
| 医疗 | 知识；对话中的安全行为 | 选择题；医生 rubric + 模型裁判 | 工作流与健康结局 | 预训练知识；领域对齐与后训练（回答方式） |
| 法律 | 规则回忆与推理 | 精确匹配、平衡准确率；人工判分 | 起草、长文书、跨法域 | 预训练知识 |
| 金融 | 财报检索与数字推理 | 人工复核答案 | 多文件、实时数据 | 检索系统与长上下文；推理训练 |
| 角色扮演 | 人设一致、拟人、吸引力 | 人工评分；专用奖励模型；LLM 裁判（不可靠） | 长期一致性、对用户的长期影响 | 预训练语料覆盖；SFT 与偏好阶段 `[判断]` |
| 安全对齐 | 拒绝有害、抵抗越狱、不过度拒答 | 分类器 ASR；rubric 评分器；人工标注 | 多轮与智能体场景的危害 | 偏好与安全 RL；对抗训练 |
| 指令与格式 | 满足可验证约束 | 约束验证函数 | 未明说的约定；约束与任务冲突 | SFT；RLVR（约束） |

## 从表里读出的三点

1. `[判断]` 越接近"程序可判定"的领域，越早进入 RL，越要防奖励黑客；越接近"专家判断"的领域，越依赖 rubric 与裁判，越要防长度偏置与裁判偏差。代码、指令遵循属于前者，医疗、角色扮演属于后者，安全两头都占。
2. `[判断]` 知识型领域的考试题接近饱和后，评测正在迁移到 rubric 化的开放对话（MedQA → HealthBench）；rubric 恰好也是生成式奖励模型的输入格式，所以评测迁移与后训练迁移同步发生。
3. `[判断]` 同样是"不好用"，各领域卡在不同的段：金融卡在检索与长上下文，法律的规则回忆卡在预训练知识，医疗的安全回答卡在后训练对齐，代码质量卡在奖励设计。诊断一个模型在某领域的短板时，先看该领域的评分方式与这一段的对应关系。

## 批注

**易误读**

- Claude 4 系统卡的奖励黑客数字来自 Anthropic 自建的评测（易钻空子题取自训练分布中 3.7 曾出问题的题目），不同公司之间不可直接比较；ImpossibleBench 是公开评测，可以跨公司比较，但作者之一来自 Anthropic。
- METR 2025-08 只有 18 个 issue、一个模型（Claude 3.7 Sonnet）、每题一次运行，"修改时间"由 METR 对照参考 PR 估计，不是原作者给出（原文自述高方差、主观）。
- METR 2025-06 的"70%–95%"是在单个任务（Optimize LLM Foundry）上、每种提示 20 次运行得到的。
- HealthBench 的 0.60 等分数是按 rubric 加权后的得分，不是"答对率"；Hard 子集 32% 也是同一口径。
- FinanceBench 的百分比来自 150 例人工复核样本，不是全部 10,231 题。
- CharacterEval 摘要（v2）写 23,020 个样例，引言写 11,376 个；本页不引用样例数。
- XSTest 正文结果一节写"200 safe prompts"，与摘要的 250 条安全提示不一致；本页按摘要与数据说明写 250 条安全、200 条不安全。

**`[判断]` 的依据**

- 评分方式与训练信号的对应：R1 用答案匹配与测试用例做奖励；Tulu 3、IFBench 用约束验证函数；Kimi K2、DeepSeek-V3.2 用 rubric 生成式奖励（见后训练总览）；CharacterRM 同时是评测器与奖励模型。反例：人工复审至今没有规模化进入奖励。
- 测试看不到的三层与推论：Claude 3.7 / 4 系统卡、Baker 等、METR 两篇、ImpossibleBench、MaintainBench、RACE；METR 2025-08 自己也提出"RLVR 让模型在可自动评分的任务上更强"的假设。边界：Claude 4 系统卡显示有针对性的训练干预能大幅压低第 1 层问题，所以"RLVR 必然导致黑客"不成立。
- Agent 式编码主要来自环境 RL：R1 自述软件工程 RL 不足而提升小；Claude 4 系统卡、Kimi K3 都把训练环境的改造列为关键工作。没有一家公开不同训练段对 SWE-bench 分数的分解。
- 科研能力的空白：GPQA、HLE、SciCode 都是给定问题求解；HLE 作者自述不代表自主研究能力。
- 科研与法律的知识来自预训练：SciCode 给背景提分；LegalBench 规则回忆最弱；GPT-4 技术报告关于考试能力与 RLHF 的结论。边界：R1 显示 RL 也能提升 GPQA 一类知识型题目中的推理部分。
- 医疗回答方式由后训练塑造：Med-PaLM 的 instruction prompt tuning 前后对比；HealthBench 中 o3 的完整性提升与小模型的进步。OpenAI 没有在 HealthBench 论文中说明是否用类似 rubric 训练过这些模型。
- 角色扮演与预训练语料：CharacterEval 中 GPT 系列在中文扮演上不占优，但这些模型的 SFT 与偏好数据也不同，无法单独归因于预训练。
- 金融的推理部分：FinanceBench 作者写明检索对之后仍有推理错误，但没有测推理训练的效果。
- 指令遵循与奖励黑客同源：Claude 4 系统卡用"提示能否压低硬编码"衡量指令遵循；IFBench §5 把约束与任务冲突归为奖励黑客。
- 三点结论：第 1 点依据全页各节；第 2 点依据 MedQA 被 HealthBench 作者称为已饱和、后训练总览中 rubric 奖励的出现；第 3 点依据 FinanceBench、LegalBench、Med-PaLM 与第 2 节。反例：安全同时依赖分类器式的自动判定和人工标注，不能简单归入任一端。

**与其他论文的关联**

- "为过测试而写代码"与语言模型 RL 中的奖励黑客是同一现象，算法侧的讨论见[语言模型强化学习](../../../llm/fields/posttraining/rl/README.md)；机器人 RL 中换掉一项奖励就学会撞墙再弹回，是同一个坑（[后训练总览](../../../llm/fields/posttraining/README.md)"与机器人强化学习的共性"）。
- 角色扮演与开放式对话里的 LLM 裁判偏差，见 [Judging LLM-as-a-Judge](../../papers/llm-judge/README.md)；弱模型监督强模型的问题，见 [On scalable oversight with weak LLMs judging strong LLMs](../../papers/arxiv-2407.04622/README.md)，CriticGPT 是代码上的实例。
- [SFT 学新知识会增加幻觉](../../../llm/papers/arxiv-2405.05904/README.md)解释了为什么医疗、法律的知识缺口难以靠后训练补上。
- [Constitutional AI](../../../llm/papers/arxiv-2212.08073/README.md) 记录了安全 RL 训练过头的 Goodhart 现象（回答过于严厉、塞入套话），与 XSTest 测的过度拒答方向一致。

- Claude 3.7 Sonnet 系统卡引用的是 Anthropic 官方 PDF；Claude 4 之后各代系统卡的奖励黑客数字没有核对。
