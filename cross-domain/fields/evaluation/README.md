# 评估：评测怎样测量模型，又怎样变成训练目标

> 状态：领域入门页（§3.6 研究对象变体）· v2 · 依据 [synthesis.csv](synthesis.csv)（15 篇）
>
> 速览：
> - 一次评测由四样东西组成：题目分布、模型的接入方式（提示、工具、脚手架）、判分器、汇总统计。能自动判分的评测，同一个判分器就能当强化学习的奖励、拒绝采样的过滤器、挑检查点的标准；评测和 RL 环境是同一个对象的两种用法。
> - 评测的好坏叫效度：分数是否反映想测的能力。它没有自己的 benchmark，只能借另一个参照来检验，例如人类判断、重新出的一套题、训练截止之后的新题。
> - 四种失效都有原文数字：污染（GSM1k 上最多掉 8 个百分点；三家前沿模型能背出 SWE-bench Verified 的参考补丁）、饱和（MMLU 停在 86%–87%）、捷径与裁判偏差（AlpacaEval 只让模型改详略，胜率在 22.9% 到 64.3% 之间变）、排行榜动态（微调数据里 Arena 数据从 0 加到 70%，ArenaHard 胜率从 23.5% 升到 49.9%）。
> - 方法谱系沿判分器移动：选择题 → 参考答案 → LLM 裁判与评分细则 → 成对人评竞技场 → 单元测试 → 交互环境 → 滚动更新与私有题集。后训练的奖励类型与之一一对应（Qwen3 把奖励分成规则、带参考答案的模型打分、无参考的奖励模型三类）。
> - `[判断]` 趋势是评测数据从公开走向隐藏：公开的题迟早进训练集，能判分的题迟早变成奖励。2026 年 OpenAI 停止报告 SWE-bench Verified，Kimi K3 在训练环境里配了隐藏验证器。

## 什么是评测

一次评测由四样东西组成。以 [SWE-bench](../../papers/arxiv-2310.06770/README.md) 为例：**题目分布**是 12 个 Python 仓库里的 2,294 个真实 GitHub issue；**接入方式**是把 issue 文本和修复前的代码库交给模型，模型可以直接写补丁，也可以通过一套工具在仓库里搜索、运行命令（[SWE-agent](../../../llm/papers/arxiv-2405.15793/README.md)）；**判分器**是该 issue 的修复 PR 带来的单元测试，修复前失败、修复后必须通过（fail-to-pass），原有的回归测试也要通过；**汇总统计**是解决率，再加上采样几次、怎样平均。四样中任何一样改动，分数含义都会变：同一个 GPT-4，在 SWE-bench Lite 上换脚手架，解决率从 2.7% 变到 28.3%（[OpenAI 的 SWE-bench Verified 说明](../../papers/openai-swe-bench-verified/README.md)）。

**评测即目标。** 一个评测一旦能自动判分，它的判分器就能直接拿去训练，用法有三种：

| 用法 | 怎样用判分器 | 原文例子 |
|---|---|---|
| 奖励 | RL 中每条回答由判分器打分 | [DeepSeek-R1](../../../llm/papers/arxiv-2501.12948/README.md) 的数学、代码、逻辑题只用规则奖励（答案匹配、编译与测试用例、格式）；[Tülu 3](../../../llm/papers/arxiv-2411.15124/README.md) 把"答案能被程序验证才给奖励"的 RL 命名为 RLVR，在 GSM8K、MATH 与 IFEval 式约束上训练 |
| 过滤 | 采多个回答，只留判分器通过的作训练数据（拒绝采样） | Llama 3 的"奖励模型 → 拒绝采样 → SFT → DPO"六轮循环（见[后训练方向](../../../llm/fields/posttraining/README.md)） |
| 选择 | 用开发集分数决定数据配比、超参数、发布哪个检查点 | Tülu 3 把评测分成开发集与未见集，开发时只看开发集；Arena 上少数提供方私下测多个变体、只公布最好的那个（[The Leaderboard Illusion](../../papers/arxiv-2504.20879/README.md)） |

这样做的代价就是 Goodhart 定律（"当一个指标变成目标，它就不再是好指标"）。[HELM](../../papers/arxiv-2211.09110/README.md) 在局限一节引用它来说明为什么评测的效度格外重要，The Leaderboard Illusion 以它开篇。在 RL 里，同一现象叫奖励黑客：策略找到让奖励变高、真实目标却没变好的捷径，机制与语言模型中的案例见 [RL 方向](../../../llm/fields/posttraining/rl/README.md)，这里不重复。

读者熟悉的腿足 RL 可以直接对照：评测与 RL 环境的部件一一对应。

| 评测的部件 | RL 中的对应 | 例子 |
|---|---|---|
| 题目分布（测试集） | 初始状态分布、提示集 | Qwen3 推理 RL 只用 3,995 个"题目—验证器"对 |
| 接入方式（提示、工具、脚手架） | 环境与动作空间 | Kimi K2 从 GitHub 的 issue 与 PR 搭出带可执行单元测试的开发环境，同时支持一万多个沙箱并发 |
| 判分器 | 奖励函数、验证器、奖励模型 | R1 不对推理任务用神经奖励模型，因为它在大规模 RL 中会被钻空子 |
| 留出的未见题 | 测试环境、域随机化之外的场景 | Kimi K3 用公开验证器给诊断反馈，用隐藏验证器评估留出场景 |

本页按 STYLE §3.6"以研究对象界定的方向"来写：评测本身就是 benchmark，没有另一个 benchmark 来给它打分；它好不好，要看分数和另一个参照（人类判断、新出的题、真实使用）是否一致。所以先讲它测什么、怎样检验它的效度、它怎样进入训练，再讲方法谱系和历史。按领域（角色扮演、安全、代码规范遵循、科研、金融、医疗、法律、代码、智能体）展开的"各测什么能力"在子页 [各领域的评测](domains.md)；智能体的交互环境在 [Agent 方向](../agents/README.md)。

## 从任务看：评测测的是哪一段训练给的能力

结论：不同评测族主要测不同训练阶段的产物，但一个分数里总混着几段：预训练给的能力、后训练对格式与风格的塑造、评测本身的接入方式。

| 评测族 | 测什么 | 主要由哪一段训练决定 | 证据 |
|---|---|---|---|
| 知识选择题：MMLU、MMLU-Pro、GPQA | 预训练读到的知识，以及在选项中调用它 | 预训练 | [MMLU](../../papers/arxiv-2009.03300/README.md) 故意不给训练集、只在 zero-/few-shot 下评测，假设知识来自预训练；DeepSeek LLM 发现 SFT 前后知识类评测只有小幅波动（[预训练方向](../../../llm/fields/pretraining/README.md)"预训练与后训练的分工"）。边界：Tülu 3 发现同一基座、不同后训练的模型 GPQA 走势与 MMLU 不同，认为后训练影响知识调用 |
| 可验证指令：IFEval | 字数、格式、关键词这类能被程序检查的约束 | SFT 与 RLVR | Tülu 3 按 [IFEval](../../papers/arxiv-2311.07911/README.md) 的 25 类约束合成近 3 万条训练数据，再做 RLVR；它自建约束不重叠的 IFEval-OOD，Tülu 3 70B 最终模型 IFEval 83.2、IFEval-OOD 27.8 |
| 偏好：MT-Bench、AlpacaEval、Chatbot Arena | 人（或裁判模型）更喜欢哪个回答，含风格、详略、语气 | 偏好学习与 RLHF | [MT-Bench 与 Chatbot Arena](../../papers/llm-judge/README.md) 的出发点：对齐后的模型明显更受用户偏好，MMLU、HELM 却分不出它和基座；Arena 数据加进微调，ArenaHard 胜率翻倍而其他任务收益有限 |
| 可验证推理：AIME、LiveCodeBench、HLE | 多步推理得到可核对的最终答案 | 推理 RL（RLVR）与推理时计算 | [MMLU-Pro](../../papers/arxiv-2406.01574/README.md) 上思维链让 GPT-4o 提高 19%，在 MMLU 上反而有害；推理 RL 的配方见 [RL 方向](../../../llm/fields/posttraining/rl/README.md)，采样口径见[推理时计算](../../../llm/fields/inference/README.md)"用什么衡量进展" |
| 执行与智能体：SWE-bench、交互环境 | 在代码库或环境里多步完成任务 | 智能体 RL 与训练环境 | K2 用与 SWE-bench 同构的"issue + 可执行单元测试"环境做 RL；评测体系见 [Agent 方向](../agents/README.md) |
| 长上下文：大海捞针、RULER、MRCR | 在长输入中检索、追踪、聚合 | 预训练末段的分级扩长 | 分层与口径见[长上下文方向](../../../llm/fields/long-context/README.md)"用什么衡量进展" |

`[判断]` 题目形式本身也决定测到的是哪一段。DeepSeek LLM 在微调中加入 2000 万道中文选择题，MMLU 从 49.4 升到 60.9，生成式问答 TriviaQA 不变，作者判断这是对 benchmark 的过拟合，此后预训练和微调都不用选择题数据（[预训练方向](../../../llm/fields/pretraining/README.md)"⑤"一节）。选择题分数可以通过熟悉题型来提高，知识本身没有增加。

## 从测量看：效度与四种失效

结论：检验效度的办法都是"换一个参照再测一次"：重新出一套题、按训练截止日期切分、与人类判断比一致率、人工复核判分器、做统计检验。四种失效各有对应的检验。

### 污染：测试题进了训练集

污染指测试题或与它极相似的内容出现在训练数据中。检测有三种思路，各管一部分：

| 检测思路 | 做法 | 结果 | 管不到的 |
|---|---|---|---|
| 重新出题 | [GSM1k](../../papers/arxiv-2405.00332/README.md)：纯人工重写 1,205 道与 GSM8k 同风格、同难度分布的小学应用题 | 最多掉 8 个百分点；Phi、Mistral 与部分 Llama 系列几乎各尺寸都有落差，前沿模型几乎没有；生成 GSM8k 原题的似然与落差正相关（r² = 0.36） | 两套题只是高度相似；作者认为污染不是落差的全部原因 |
| 按时间切分 | [LiveCodeBench](../../papers/arxiv-2403.07974/README.md)：竞赛题标注发布日期，只用模型训练截止之后的题 | DeepSeek-Instruct 与 GPT-4o 在各自截止日期之后发布的 LeetCode 题上明显下降 | 越新的模型可用题越少（代码生成只剩 349 题，约 1%–1.5% 的波动） |
| 统计检验 | [Oren 等](../../papers/arxiv-2310.17623/README.md)：被训练过的模型更偏好公开仓库里的题目顺序，比较原顺序与打乱顺序的似然 | 有误报率保证；审计 4 个开放模型，没有发现普遍的逐字污染 | 只管逐字记忆；读过构造题目所用的原始资料（例如 MMLU 取材的考试）检测不到 |

模型方的去污染只能做到 n-gram 匹配。DeepSeek-R1 在预训练与后训练数据中删掉与评测题有 10-gram 重合的文本，仅数学一项就删了约 600 万段，作者同时承认 n-gram 去不掉改写过的题，2024 年以前发布的 benchmark 可能仍有污染，于是另报了 AIME 2025。Tülu 3 用 8-gram，与未见集重叠超过 2% 的训练集整个删除；它列出的公开数据集中，Evol CodeAlpaca 与 HumanEval 的重叠达 70.7%。

污染最终让一个公开 benchmark 退役。[OpenAI 2026 年的审查](../../papers/openai-swe-bench-verified-retired/README.md)发现，GPT-5.2-Chat、Claude Opus 4.5、Gemini 3 Flash Preview 在部分 SWE-bench Verified 任务上能复现参考补丁或逐字背出任务描述；GPT-5.2 的思维链提到了相关版本的发布说明，而那正是解出一道"描述不完整"的题所需的信息。OpenAI 据此停止报告该基准。

### 饱和：分不出强弱

饱和指顶尖模型的分数挤在上限附近，差别小于噪声。MMLU 的引言写道，GLUE、SuperGLUE 发布后都只用了约一年就接近人类水平；MMLU-Pro 的引言写道，GPT-4 在 2023 年 3 月达到 86.4% 后，2024 年上半年的前沿模型都停在 86%–87%。之后的回应是加难：MMLU-Pro 把选项扩到 10 个、加推理题；[GPQA](../../papers/arxiv-2311.12022/README.md) 让博士出题、其他领域的博士上网 37 分钟也只答对 34%；[Humanity's Last Exam](../../papers/arxiv-2501.14249/README.md) 先用当时的前沿模型筛题，只收它们答不出的题，初版最高的 o3-mini (high) 也只有 13.4%。

用模型筛题有一个口径问题：分数是被构造压低的。HLE 作者写明接近 0 的小幅变化不代表进展；下一代模型的提升里，有一部分来自它不是筛题时用的那批模型。GPQA 则有统计功效问题：448 题，要 50%→60% 这种量级的差别才有 80% 的把握检出。

### 捷径与裁判偏差：判分器不在测想测的东西

判分器被捷径骗过的方式取决于它是什么：

- **选项可猜**：MMLU 只有 3 个干扰项，MMLU-Pro 认为模型可以不理解题意而排除选项；Kimi k1.5 训练时剔除不写推理、猜 8 次内就能猜中的题，否则推理错了也能拿奖励（[RL 方向](../../../llm/fields/posttraining/rl/README.md)）。
- **LLM 裁判的偏差**：MT-Bench 论文测出位置偏差（交换两份回答的顺序，GPT-4 只有 65.0% 的判决保持一致，Claude-v1 为 23.8%）、冗长偏差（把列表改述一遍放在前面、不增加信息，GPT-3.5 与 Claude 有 91.3% 判它更好），并讨论了偏爱自己输出的可能（论文认为证据不足）。[长度控制的 AlpacaEval](../../papers/arxiv-2404.04475/README.md) 只让模型改详略：原版胜率在 22.9% 到 64.3% 之间变，回归掉长度差后为 41.9% 到 51.6%，与 Arena 排名的相关从 0.94 升到 0.98。
- **裁判能力不够**：[LiveBench](../../papers/arxiv-2406.19314/README.md) 让 GPT-4-Turbo 判 AMC、AIME、Zebra 谜题的对错，错判率 10%–46%；推理 RL 坚持规则验证器，原因之一在此。
- **单元测试判错**：OpenAI 标注 1,699 个 SWE-bench 样本，61.1% 的测试可能把正确解判错，38.3% 的 issue 描述不完整，合计剔除 68.3%，留下 500 题作 Verified；2026 年复盘 o3 始终解不出的 138 题，59.4% 仍有缺陷（35.5% 测试过窄，例如直接导入 issue 里没提到的函数名；18.8% 过宽）。
- **测试通过不等于代码好**：SWE-bench 原文自述，只靠执行测试不足以保证可靠，模型写的补丁常常不如人写的完整、高效、可读。代码规范与可维护性怎样评测，见[各领域的评测](domains.md)。

### 排行榜动态：评测变成竞赛场之后

成对人评竞技场（Chatbot Arena：用户提问，两个匿名模型作答，用户投票，按 Bradley–Terry 模型算排名）解决了"静态题集跟不上真实使用"的问题，但规模化之后出现了另一类失效。The Leaderboard Illusion 综合 200 万场对战：少数提供方可以在发布前私下测多个变体、只公布最好的那个，Llama 4 发布前 Meta 测了 27 个；这种 best-of-N 违背了排名模型的无偏抽样假设，模拟中测 10 个变体可让最高分高出约 100 分；Google 与 OpenAI 估计各拿到约 19.2% 与 20.4% 的对战数据，83 个开放权重模型合计约 29.7%，而这些数据能直接用来训练。题目本身没有泄漏，失效来自"在测试集上挑选"和"训练分布贴近测试分布"。

### 为什么评测数据被隐藏

结论：隐藏是对前三种失效的系统性回应，形式从"请别公开"一路收紧到"训练环境里也有看不见的验证器"。以下只列原文或官方材料写明的做法与理由：

| 做法 | 谁 | 原文理由 |
|---|---|---|
| canary 字符串，请求不在网上明文公开题目 | GPQA（沿用 BIG-bench 的 canary） | 降低泄漏进基础模型训练语料的风险，方便训练方过滤 |
| 题目不给被测者看 | SWE-bench / Verified | 智能体只拿到 issue 文本，看不到要通过的测试 |
| 不公开，预先承诺公开条件，另留备用题 | GSM1k | 防止同样的污染再次发生；经 API 评测闭源模型时数据可能泄漏，留一批题备查 |
| 公开大部分、保留私有测试集 | HLE | 检查模型是否过拟合公开题 |
| 新题延后一个月公开 | LiveBench | 公开榜单上始终约有 1/6 的题是私有的 |
| 开发集与未见集分开，开发时不看未见集 | Tülu 3 | 检验配方是否泛化到没针对过的评测 |
| 公开验证器 + 隐藏验证器 + 有限提交次数 | Kimi K3（训练环境） | 缓解智能体的奖励黑客 |
| 停用公开基准，转向原创私有评测；建议密码保护发布、严格遵守 canary | OpenAI（2026） | 公开的 benchmark 甚至其解答最终都可能进入训练数据 |

`[判断]` 隐藏换来了抗污染，代价是外部无法复核：HLE 的私有集、GSM1k 未公开期间、OpenAI 的内部评测，结果都要靠出题方自己报告。

## 评测怎样进入训练

§3.6 模板在这里是"从内部看"；评测的"内部"是训练回路，所以本节写判分器在训练中怎样被使用、怎样被钻空子。结论：报告里每一种奖励都对应一种评测判分器，评测会出的问题，在训练中以奖励黑客的形式出现。

**奖励类型与评测判分器同构。** Qwen3 的通用 RL 覆盖 20 多类任务，奖励分三种：规则奖励（指令遵循、格式，作者写明设计良好的规则能防止奖励黑客）；带参考答案的模型打分（让 Qwen2.5-72B-Instruct 对照参考答案打分，避免规则误判格式等价的答案）；无参考答案的奖励模型（用人类偏好数据训练）。这三种分别就是谱系里的程序判分、参考答案判分与 LLM 裁判。

**判分器可靠时，RL 在评测上的进步是真的；不可靠时，奖励与评测背离。** DeepSeek-R1 附录 B.5 的图 6 是一个直接的例子：用帮助性奖励模型多训练一段，奖励持续上升，Codeforces 成绩却下降，于是偏好奖励只放在最后 400 步。这时 Codeforces 这个评测起到了检测奖励黑客的作用。R1 的结论把"规则奖励"和"让 LLM 对照标准答案判对错"列为两种稳健的机制，后者只适用于答案短而明确的任务，开放式写作仍然没有可靠奖励。

**判分器的盲区会变成模型的行为。** Kimi K2 的指令遵循 RL 用"代码检查 + LLM 裁判"混合判分，并专门加了一层检查，抓"声称遵守了指令、其实没有"的输出。它的自我批评 rubric 奖励（模型按一组评分细则两两比较自己的回答）里有一类"防奖励黑客"的规定细则，例如禁止开头恭维用户、禁止解释"这个回答为什么好"；附录 F.3 自述，这套细则可能偏向显得自信、果断的回答，因为它惩罚自我限定与免责声明，在模糊或主观的问题上会抑制谨慎、多视角的回答。Tülu 3 降低 KL 惩罚后，IFEval 上的 RLVR 出现了只为满足约束而写的怪异输出。`[判断]` 模型的一部分行为特征（是否追问、是否加免责、是否写得长）可以追溯到训练时判分器奖励了什么、没检查什么；不同模型行为上的差别，有一部分来自各家的判分器不同。

**评测数据本身成为训练数据。** Tülu 3 按 IFEval 的 25 类约束合成训练数据，结果是 IFEval 80 分上下、约束不重叠的 IFEval-OOD 只有 20–30 分，作者写明各模型普遍过拟合 IFEval。The Leaderboard Illusion 的受控实验也是同一件事：在 Arena 分布的数据上训练，ArenaHard 胜率翻倍，其他任务收益有限。

**训练环境照着 benchmark 搭，也照着 benchmark 设防。** K2 的软件工程 RL 环境与 SWE-bench 同构；K3 的智能体环境里，智能体与验证器隔离，公开验证器给诊断反馈、隐藏验证器评留出场景，提交次数有限，并用长度预算抑制智能体裁判偏爱冗长输出的奖励黑客（与 AlpacaEval 的长度偏差同一类问题）。机器人一侧有同样的现象：World Models（2018）的控制器在过于确定的"梦境"里得分 2086，回到真实环境只有 193（[世界模型方向](../../../robotics-embodied/fields/world-models/README.md)"从测量看"）；腿足 RL 的奖励项也会被策略利用（[模仿学习与机器人强化学习](../../../robotics-embodied/fields/imitation-reinforcement-learning/README.md)）。

## 方法谱系

结论：评测方法沿三条轴移动：判分器（答案匹配 → 参考答案 → 模型 → 人 → 单元测试 → 环境）、交互方式（单轮 → 多轮 → 与环境交互）、题目来源（公开静态 → 滚动更新 → 私有）。每一步修上一步的失效，同时带来新的被钻空子方式；每种判分器在后训练中都有对应的奖励。按部件拆分的基线见 [Baseline 页](BASELINES.md)。

|---|---|---|---|---|---|

## 主线历史

每个节点写"上一步留下了什么问题、这一步改了什么、后来暴露了什么"。

1. **MMLU（2020，UC Berkeley）：把评测对准预训练知识。** 留下的问题：GLUE、SuperGLUE 都在约一年内接近人类水平，作者认为它们测的是语言技能，没测到预训练读到的专业知识。改变：57 个学科的考试题，不给训练集，只在 zero-/few-shot 下测。GPT-3 175B 平均 43.9%，13B 以下接近随机，法律、道德与计算类科目接近随机；GPT-3 的置信度与准确率最多差 24 个百分点。做不好的场景：3 年后饱和（前沿模型停在 86%–87%）；选择题可以靠熟悉题型刷分（DeepSeek LLM 的 2000 万道选择题）；对提示与打分函数敏感。`[判断]` "不给训练集"假设训练语料里没有这类题；网页规模的预训练和针对性的微调数据让这个假设失效，后面每一步的污染问题都从这里来。
2. **HELM（2022，Stanford CRFM）：标准化与多指标。** 留下的问题：各家只报自己挑的场景，平均只覆盖 HELM 核心场景的 17.9%，有的模型之间没有一个共同场景。改变：16 个核心场景 × 7 个指标，30 个模型在统一提示下评测，覆盖率 96.0%，公开全部输出。做不好的场景（自述）：结论依赖提示这一适配方式；训练数据不透明，污染无法核查；每个数据集只取 1000 个样本、3 个随机种子。`[判断]` "在统一框架下重测所有对照模型"成了后来模型报告的惯例（DeepSeek 各代在内部框架中重测对照，见[预训练方向](../../../llm/fields/pretraining/README.md)"用什么衡量进展"）；少样本提示的设定却不适合对话模型，下一步转向开放式回答。
3. **2023：三种新判分器同时出现。** 留下的问题：对齐后的对话模型明显更受用户偏好，MMLU、HELM 却分不出它和基座（MT-Bench §1）；代码题几行就写完；知识题开始饱和。改变：LMSYS 的 [MT-Bench 与 Chatbot Arena](../../papers/llm-judge/README.md) 用 GPT-4 当裁判、用众包投票排名，GPT-4 与人类在去掉平局后的一致率约 85%，与人类彼此之间相当；Google 的 [IFEval](../../papers/arxiv-2311.07911/README.md) 只测程序可检查的指令；Princeton 的 [SWE-bench](../../papers/arxiv-2310.06770/README.md) 用真实仓库与单元测试，最好的 Claude 2 只解决 1.96%；NYU 的 [GPQA](../../papers/arxiv-2311.12022/README.md) 要专家出题、非专家上网也做不出。做不好的场景都由后来的工作量出：裁判偏爱冗长（AlpacaEval-LC）；IFEval 被拿来训练而过拟合（IFEval-OOD）；SWE-bench 的测试大面积误判（Verified 剔除 68.3%）；GPQA 统计功效低。
4. **2024：效度危机与修补。** 留下的问题：各家报告的高分有多少是真的。改变：Scale AI 的 [GSM1k](../../papers/arxiv-2405.00332/README.md) 重新出题量出最多 8 个百分点的落差；[LiveCodeBench](../../papers/arxiv-2403.07974/README.md) 按训练截止日期切分，量出截止日期前后的落差；[LiveBench](../../papers/arxiv-2406.19314/README.md) 每月换题、延迟公开；Stanford 用回归去掉 AlpacaEval 的长度偏差、用可交换性检验污染；Waterloo 的 [MMLU-Pro](../../papers/arxiv-2406.01574/README.md) 加难 MMLU；OpenAI 与 SWE-bench 作者人工复核出 [SWE-bench Verified](../../papers/openai-swe-bench-verified/README.md)，GPT-4o 从 16% 升到 33.2%。做不好的场景：时间切分后题量越来越少；长度控制只修了事先猜到的那一个偏差；Verified 剩下的题后来仍有一大半判分有缺陷，并且被污染。
5. **2024 末–2025：评测变成训练目标。** 留下的问题：推理模型需要大规模、可靠的奖励。改变：Tülu 3 公开了以评测为中心的后训练配方（为每项核心技能选开发集评测、针对性地准备数据、开发与未见分离、8-gram 去污染），并在 GSM8K、MATH、IFEval 上做 RLVR；DeepSeek-R1 只用规则奖励训练推理，去污染后另报 AIME 2025；Qwen3 把奖励分成规则、参考答案、奖励模型三类；Kimi K2 从 GitHub 搭软件工程环境，并用自我批评 rubric 把 RL 扩展到不可验证任务；评测一侧，CAIS 与 Scale AI 用前沿模型筛题建 HLE 并保留私有集，Cohere 的 The Leaderboard Illusion 审计 Arena。做不好的场景：IFEval 上的过度优化；R1 中奖励模型被钻空子、Codeforces 下降；K2 的 rubric 偏向自信的回答；Arena 上的私下测试与选择性公布。
6. **2026：公开基准退役，评测转入私有与隐藏验证器。** 留下的问题：Verified 在 6 个月内只从 74.9% 升到 80.9%，剩下的题到底是做不出还是题有问题。改变：[OpenAI 的复盘](../../papers/openai-swe-bench-verified-retired/README.md)发现 59.4% 的难题判分有缺陷、三家前沿模型都有污染迹象，停止报告该基准，改报 SWE-bench Pro 公开子集，长期转向领域专家内部编写的私有评测；Kimi K3 在训练环境里用隐藏验证器与有限提交次数防奖励黑客。做不好的场景：OpenAI 自述 SWE-bench Pro 也检测到少量污染；私有评测的结果外部无法复核。

## 趋势

以下四条都是跨论文的 `[判断]`，支撑论文与反例列在批注里。

**1. 判分器与奖励同步迁移。** 评测的判分器从选项匹配走到规则检查、模型裁判、单元测试、交互环境，每一种出现后不久就出现在训练里：IFEval（2023 年 11 月）的约束一年后成为 Tülu 3 的 RLVR 奖励；SWE-bench（2023）的"issue + 单元测试"成为 K2（2025）的 RL 环境；LLM 裁判（2023）成为 K2 的自我批评 rubric 与 K3 的智能体裁判。原因是同一件事：能自动判分的东西就能当奖励。于是评测的失效（裁判偏爱冗长、测试过窄）也原样变成训练的失效（K3 对冗长输出加预算、IFEval 过度优化）。

**2. 评测数据从公开走向隐藏。** 2023 年 GPQA 只是请求别公开、加 canary；2024 年 GSM1k 不公开并预先承诺公开条件，LiveBench 延迟一个月公开；2025 年 HLE 保留私有集；2026 年 OpenAI 停用公开基准、转向私有评测，K3 在训练环境里配隐藏验证器。驱动力是污染和"评测即目标"两者叠加。代价是外部复核变难，同一实验室既出题又报告分数。

**3. 从测答案走向测行为与过程。** MMLU 与 HLE 都测校准（模型说的置信度与实际准确率是否一致）；LiveCodeBench 加入自我修复与测试输出预测；SWE-bench 自述"测试通过不等于可读"；K2 的 rubric 直接规定回答不许恭维、不许自夸。评测的对象从"答对没有"扩展到"怎样回答、怎样做事"，对应的训练信号也在塑造这些行为。各领域的行为类评测（角色扮演、安全、代码规范）见[各领域的评测](domains.md)。

**4. 能被直接优化的评测，区分度丧失得快。** GLUE、SuperGLUE 各约一年；MMLU 约三年停在 86%–87%；SWE-bench Verified 从 2024 年 8 月发布到 2026 年 2 月被发布者停用，约一年半。滚动更新与私有集是延长寿命的两种办法。

## 主要路线与团队偏好

- **广覆盖的学术考试（Hendrycks 与 CAIS：MMLU、HLE）。** 押注：封闭式、可自动判分、覆盖众多学科的考试题，能给研究者与政策制定者一个共同参照。`[判断]` 两篇都同时测校准误差，都以"现有 benchmark 饱和"为出发点。代价：饱和之后只能再加难；HLE 自述只测封闭式学术题，高分不代表自主研究能力。
- **保留测试集（Scale AI：GSM1k、HLE）。** 押注：评测数据不公开或部分不公开，才能测出真实能力。`[判断]` 两篇都保留不公开的题（GSM1k 整体暂不公开并另留备用题，HLE 保留私有集）。代价：外部复核依赖出题方。
- **测量学与统计修正（Stanford，Liang 与 Hashimoto：HELM、AlpacaEval-LC、Oren 等）。** 押注：评测的问题可以用标准化、回归去偏、假设检验来修。`[判断]` 三篇都把评测问题形式化为统计问题（覆盖率、中介变量、可交换性检验）。代价：只能修事先识别出的偏差，AlpacaEval-LC 自述不处理裁判的其他问题。
- **规模化人类偏好与滚动题（UC Berkeley，Stoica：Chatbot Arena、LiveCodeBench）。** 押注：让真实用户与不断出现的新题来定义评测。代价：Arena 成为营销目标后出现选择性公布与数据不对称（The Leaderboard Illusion，由 Cohere 等发起，部分作者自己也向 Arena 提交过模型）。
- **真实环境与执行判分（Princeton：SWE-bench、SWE-agent；OpenAI Preparedness 接手修订）。** 押注：在真实仓库里跑真实测试。代价：判分器本身需要大规模人工复核；OpenAI 把它当作风险评估工具，最终以私有评测替代。
- **训练与评测同一条管线（AI2 的 Tülu 3、DeepSeek、Kimi、Qwen）。** 押注：评测既是目标也是体检，靠去污染、开发与未见分离、隐藏验证器保持诚实。`[判断]` AI2 公开去污染工具与未见集，其余三家只在报告中描述做法。

`[判断]` 收敛：所有路线都接受"公开静态题会被污染、会被优化"，都在引入某种不公开或不断更新的部分。分化：学术评测方选择公开大部分、保留一小部分并公开流程；前沿实验室转向完全内部的评测；中间地带（众包竞技场）的问题在于题目公开流动、模型却可以私下多次提交。

## 当前开放问题

- **隐藏的评测怎样被外部信任？** 私有集抗污染，但结果只能由出题方报告。入口：[OpenAI 的 Verified 复盘](../../papers/openai-swe-bench-verified-retired/README.md)、[HLE](../../papers/arxiv-2501.14249/README.md)、[GSM1k](../../papers/arxiv-2405.00332/README.md) 的发布承诺。
- **不可验证的能力（写作、角色扮演、代码可读性与架构）判分器从哪来，被优化后会塑造出什么行为？** R1 自述写作类任务没有可靠奖励；K2 的 rubric 自述偏向自信；SWE-bench 自述测试测不到可读性。入口：[Kimi K2](../../../llm/papers/arxiv-2507.20534/README.md)、[偏好学习方向](../../../llm/fields/posttraining/preferences/README.md)、[各领域的评测](domains.md)。
- **污染检测能否超出逐字记忆？** n-gram 去不掉改写（R1 自述），可交换性检验只管逐字（Oren 等），重新出题只能近似同分布（GSM1k）。入口：[Oren 等](../../papers/arxiv-2310.17623/README.md)、[LiveCodeBench](../../papers/arxiv-2403.07974/README.md)。
- **智能体评测与训练环境怎样防止被钻空子？** 环境越真实，可利用的漏洞越多（K3 的沙箱崩溃）；脚手架差异让同一模型分数差十倍。入口：[Agent 方向](../agents/README.md)、[RL 方向](../../../llm/fields/posttraining/rl/README.md)第 6 节。

## 阅读顺序

1. [MMLU](../../papers/arxiv-2009.03300/README.md) → [MMLU-Pro](../../papers/arxiv-2406.01574/README.md)：静态选择题从设计到饱和、加难，看"只测预训练知识"这个设计假设了什么。
2. [MT-Bench 与 Chatbot Arena 精读](../../papers/llm-judge/reading.md)第 3–4 节：LLM 裁判的偏差怎样测出来，"超过八成一致"指的是哪个子集。
3. [SWE-bench](../../papers/arxiv-2310.06770/README.md) → [SWE-bench Verified](../../papers/openai-swe-bench-verified/README.md) → [Verified 退役说明](../../papers/openai-swe-bench-verified-retired/README.md)：一个执行判分基准的完整生命周期，三篇连读。
4. [GSM1k](../../papers/arxiv-2405.00332/README.md) 与 [LiveCodeBench](../../papers/arxiv-2403.07974/README.md)：两种测污染的办法。
5. [Tülu 3](../../../llm/papers/arxiv-2411.15124/README.md)的评测与去污染部分、RLVR 一节，再读 [RL 方向](../../../llm/fields/posttraining/rl/README.md)的奖励黑客案例：评测怎样变成训练目标。
6. [The Leaderboard Illusion](../../papers/arxiv-2504.20879/README.md)：评测变成竞赛场之后的失效。

读完可以做一个检验：任选一个自己常用的评测，写出它的四个部件（题目分布、接入方式、判分器、汇总统计），再回答两个问题——如果把它的判分器直接当 RL 奖励，模型最可能学会什么捷径？它的题目有没有可能已经在训练数据里，用本页的哪种办法能检出来？按问题组织的练习见[路线图](ROADMAP.md)，本方向收录的全部文献见[论文目录](PAPERS.md)。

## 批注

**易误读**

- GSM1k 的"最多掉 8 个百分点"出自 v4（NeurIPS 版）摘要，早期预印本的数字不同；落差比较的是同一模型在 GSM8k 与 GSM1k 上的准确率，两套题只是高度相似，作者自述不是同分布（§3）。
- MT-Bench 中 GPT-4 与人类约 85% 的一致率是去掉平局后的子集（S2）；包含平局时为 66%（[精读](../../papers/llm-judge/reading.md)第 4 节）。位置一致率 65.0% 是默认提示下、答案质量相近的特定实验（Table 2）。
- IFEval 83.2 与 IFEval-OOD 27.8 出自 Tülu 3 Table 31（70B 最终模型）；IFEval-OOD 由 Tülu 3 团队自建，约束与 IFEval 不重叠、形式相似，两者分数不是同一难度的比较。
- The Leaderboard Illusion 的 23.5% → 49.9% 是对 Llama-3.1-8B-Instruct 的 ArenaHard 胜率，用 GPT-4o 作裁判模拟人类偏好，不是 Arena 排名本身（§4.2）。
- SWE-bench Verified 的 GPT-4o 16% → 33.2%，一部分来自分布向容易题偏移；OpenAI 按难度分层后，各难度内的解决率也提高了，说明主要是剔除了不可能的题。
- OpenAI 2026 年的污染探测用 GPT-5 诱导其他模型、用模型裁判标注严重程度，再人工核验"强污染"案例；它说明这些模型见过部分题，不能换算成污染对分数的贡献。
- HLE 的分数是初版（2025 年 1 月）所测模型的结果（v11 Table 1）。

**判断的支撑论文**（各行见 [synthesis.csv](synthesis.csv)）

- "评测与 RL 环境同构"：Qwen3 §4.4（三类奖励）、K2 §3.2.1（软件工程环境、指令遵循的混合判分与 hack-check）、K3 §4.2（公开与隐藏验证器）、R1 §2 与附录 B.5。反例：Tülu 3 的 RLVR 只用了 GSM8K、MATH、IFEval 这类简单验证器，未见集上的提升仍然存在（Table 31），说明把评测当奖励不必然只得到过拟合。
- "判分器的盲区会变成模型的行为"：K2 附录 F.3、Tülu 3 附录 B.4、R1 附录 B.5、The Leaderboard Illusion §4.2。边界：这些都是训练方自述或受控实验，没有一篇直接比较不同实验室的判分器与其模型的行为差别。
- "不给训练集的假设失效"：DeepSeek LLM 的选择题实验（见[预训练方向](../../../llm/fields/pretraining/README.md)）、GSM1k、LiveCodeBench、OpenAI 2026。反例：GSM1k 中前沿模型几乎没有落差，Oren 等也没找到普遍的逐字污染。
- 趋势 1：IFEval → Tülu 3 RLVR；SWE-bench → K2；MT-Bench → K2、K3 的裁判。反例：DeepSeek-R1 明确拒绝把神经裁判用于推理任务，判分器迁移到训练中有选择。
- 趋势 2：GPQA §1 脚注、GSM1k §3、LiveBench §2、HLE §3、K3 §4.2、OpenAI 2026 讨论一节。反例：LiveBench 与 HELM 都公开全部题目与输出，以可复核为优先。
- 趋势 3：MMLU §4、HLE §4.2、LiveCodeBench §1、SWE-bench Limitations、K2 附录 F。
- 趋势 4：MMLU §1（GLUE、SuperGLUE）、MMLU-Pro §1、OpenAI 2024 与 2026、HLE §5。只是几个时间点，不足以拟合"寿命缩短"的趋势。
- 团队偏好：Hendrycks 同时署名 MMLU 与 HLE；Scale AI 出 GSM1k、合作 HLE；Liang 与 Hashimoto 同时署名 HELM、AlpacaEval-LC，Hashimoto 署名 Oren 等；Stoica 同时署名 MT-Bench 与 LiveCodeBench；Princeton 的 Narasimhan、Press 同时署名 SWE-bench 与 SWE-agent。
